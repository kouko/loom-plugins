# Adaptable confirmation template

Write in the user's conversation language.

Use this outline as content connections, with optional grouping, headings and
length. Merge, reorder or expand as needed:

- Connect the live problem and supplied impact to the wanted outcome and supplied preservation boundary.
- Include only applicable user decisions/consequences and the necessary question.

Show each fact once, instead of copying Problem/Outcome/Acceptance/Scope fields.

Ground every factual clause in this request/current evidence.
Require actual-request support or evidence for every date, role, impact and constraint.
Preserve abstraction and present-versus-desired quantifiers.
Treat a rule role separately from any unverified representation: list, file, cache, algorithm or UI.
Keep present affected population distinct from desired coverage.
Include only supplied boundaries; inconsistent results establish no identical-result guarantee.
Repair assistant shorthand using the already supplied role.
Its conversational meaning establishes no named application object.
Preserve a supplied interface boundary while leaving private helpers to implementation choices.
Borrow only information connections, keeping example details as case-specific facts.

Missing required facts stay in the existing interview: ask only what is needed and why.

## Final-message check

Check each sentence for scope, outcome or a required decision or consent.
Remove private progress, status, paths, defaults, check logs, commits and handoff
inventories unless requested; end at the necessary question and wait.
Retain required disclosures: verbatim WARN notices, cost/egress, one-way-door
consequences, principles and carried details when applicable.

Disclose in the same yes automatic publication, opt-out and the separate merge decision.
Explain that only after review AND publication checks pass does yes authorize
BOTH uploading the change branch (non-forced push) AND opening a pull request ready for review,
with opt-out available anytime before publication and a separate merge decision.
