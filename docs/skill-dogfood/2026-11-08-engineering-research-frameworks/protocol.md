# Framework-selection dogfood protocol

Test the uninstalled revision-5 framework-selection prototype. Target snapshot
will be copied under input/new/engineering-research; comparator input/old is the
frozen revision-4 package. Same description; no automatic triggering improvement
claim from a body change.

A: 20 positive and >=5 adjacent negatives, two fresh native Codex executions
each. Native description-only discovery with 3–6 adjacent descriptions and real
body reads; preserve catalogs. Host-adapted Codex telemetry is not Claude Skill()
or installed Loom parity. Keep labels/rationales out of actor prompts. Use
varied question types and predeclare ambiguous-boundary sensitivity.

B: a fresh informed coordinator derives six realistic tasks from the raw skill,
using minimal genuine current repo source and real prior generated observations
where relevant, never fabricated benchmark outcomes. Include direct facts,
feasibility/choice, a mixed risk question, invalid causal/comparative evidence,
and a bounded migration question if supported by genuine inputs. Freeze task
prompts and domain/contract criteria before outputs. Run old/new on the SAME
cases, randomized masked run IDs, in one batch (baseline before/with new), with
identical resources/permissions. Actors do not receive framework answer labels.
No active change/config; source and skills immutable; notes only plus explicitly
permitted bounded scratch probes. Preserve all artifacts and tool trajectories.
Auditors should accept an equivalent appropriate method, not require keywords.

Two fresh independent pinned-model auditors review all produced artifacts,
actual operations and predeclared criteria. They see masked IDs, source and raw
contract, not variant mapping, author predictions or other reviewers. Use coarse
buckets; distinguish confirmed domain errors, actor lapse, prose ambiguity and
harness limits. No auto-fixes or global dogfood-pass.

C: fresh first-time reader gets only raw new package and fixed questions about
self-containment, two uncertain triggers, executable procedures and undefined
terms. No author explanation, previous findings or development history.

Requested native model/provider/effort: gpt-6.1-sol / first-party OpenAI / medium.
Explicit user consent persists and current request authorizes this dogfood;
exact payload/destination recorded in authorization.json. No private sessions,
vault data or credential contents as prompt. Local auth symlinks only; cleanup
finally. Exclude proxy/API env aliases. Filter hidden reasoning before retaining
logs. Fixed requested model name does not prove immutable server weights.

Highest-risk untested axis/prediction, recorded before execution: the new router
may prescribe a named method where direct evidence suffices, enforce one method
on a mixed question, or allow a polished comparison to hide absent/confounded
observations. These are predictions, not findings. Case designers may know the
contract; isolated actors and auditors do not receive these predictions.

Preserve earlier test costs, failures, source records and frozen prototype. New
outputs go here. Record local HEAD and origin/main ref without claiming remote
freshness. Testing is not installation or shipping; keep author familiarity and
small task diversity as limitations.
