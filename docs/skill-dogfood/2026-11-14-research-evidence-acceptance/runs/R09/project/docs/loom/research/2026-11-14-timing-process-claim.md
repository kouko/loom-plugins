# 兩份執行收據是否足以支持全面簡化研究流程

## Question and scope

待決定事項：是否能由 B02 較快，推論將複雜研究全面改成簡短查檔會提高品質並降低成本。範圍限於現有兩份收據及實際工作摘要；不重新跑模型、不執行 suite、不連網、不修改來源。

充分證據條件先定為：時間需比較相同問題與完成標準；品質需有可檢查成果及共同標準的獨立評估；成本需有適用計費與完整用量；全面適用需涵蓋目標工作種類及變異，而非單次不同工作的差異。

## Method and rationale

直接核對歷史執行紀錄與工作範圍，檢查比較是否成立。這是改流程的效果主張，應檢查是否完成相同工作、品質與成本是否有觀測，再判斷因果；單純比較耗時不足。現有資料已足以判斷原主張缺乏支持，無須新實驗。只使用本 project 的來源，未引用外部資料。

## Findings

- **已支持的觀測**：B01 耗時 103.188 秒，B02 為 42.637 秒；B02 少 60.551 秒，約少 58.68%。兩者 exit_code 都是 0、timed_out 都為 false。這只證明收據記錄的兩次工作完成狀態與耗時，不能證明內容正確。
- **比較條件未滿足**：摘要記錄 B01 查 nested repository/worktree 排除與失敗順序，附關係圖；B02 查 TEST_ROOTS 與 tests/local 排除，短筆記且無圖。兩者都是 source-only，但問題範圍與產出不同。較少工作量、不同難度或輸出長度都是替代解釋；資料無法分離「方法變簡短」的效果。
- **品質改善無支持**：task-summary 明說未提供品質評估；也沒有兩份成果正文或獨立正確性、完整性評分。不能以 exit code、速度、篇幅或是否有圖代理品質，也不能反推複雜研究品質較好。
- **實際金額仍未知**：B02 input tokens 為 116861，B01 為 177820；output tokens 為 1359 與 4249。cached_input_tokens 分別為 92544 與 148352；若快取為 input 的子集，未快取輸入分別為 24317 與 29468。這些是用量差異，無價格表、帳單或完整計費定義，不能宣稱實際省款幅度。reasoning_output_tokens 不應未確認是否已含於 output 就重複加計。
- **普遍性與因果未解**：每類只有一次，沒有相同任務配對、分配方式或變異資料。兩份收據的 requested_model/provider/effort 均為 gpt-6.1-sol/openai/medium，但 requested 欄位不等於已確認實際執行版本；環境、順序、快取條件亦不足以確認一致。

## Decision impact

不支持全面改流程，也不支持「品質更好」或已證實「更省成本」。保留現行按問題選方法，是目前可逆且不必新增設施的選擇；對單純事實查核採短查檔則是可研究的局部候選，尚非本資料證實的優勝方案。全面簡化可能漏掉跨路徑互動與失敗順序；這是由工作範圍差異導出的風險，未被這兩次執行直接測量。保留複雜方法亦可能付出不必要用量，但其幅度尚未知。

若要決定是否改流程，最少需要以下觀測（本次未執行）：

1. **同題比較與實際產出**：對同一問題、同一來源修訂、相同完成要求，取得原流程與短查檔的完整輸出；覆蓋簡單查核與真正需跨路徑推理的複雜題。不得把縮小要求當成方法改善。
2. **共同品質判準與獨立檢查**：事先列明必要正確性、完整性、來源可追溯性與漏失風險，由不知道流程標籤的評估者逐項查核。若主張品質「更好」，需要觀測改善；若只求省成本，至少先確認品質不低於預定可接受範圍。
3. **可比資源及計費紀錄**：保留實際模型版本、設定、輸入、快取與執行順序，以及耗時、用量、適用單價或實際帳單；納入修正錯誤、補查與重試成本，以每個達到品質要求的完成任務為分母。
4. **重複與適用邊界**：在目標工作種類內配對重複觀測，控制或平衡順序與快取，報告變異及失敗案例。沒有固定兩次就足夠的門檻；數量需能辨識預先認定有意義的品質及成本差異。局部勝出只允許局部決策，全面改動需相應範圍證據。

上述不要求立刻建置評測平台；先取得最小、同題且可獨立核對的一組比較，才能判斷是否值得擴大。若短查檔在複雜題漏失必要條件，就應保留該類的深入研究。

## Limitations and open questions

研究已完成資料核對，但支持改流程的條件仍未滿足。未讀到兩份產出正文、歷史命令、品質評估、費率及環境；無法判定任一方法品質高低、真正成本或普遍因果效果。沒有重跑模型或製造測量，亦未執行 suite。來源未附修訂識別，結論限於本次提供的靜態收據與摘要。
