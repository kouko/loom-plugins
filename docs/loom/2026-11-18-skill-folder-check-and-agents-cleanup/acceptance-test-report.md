## 我替你決定的事

以下前四項是檢查的界線，請逐項決定接受或退回。

- **未 commit 且被 git 忽略的路徑不算違規** — 實作選擇放行 `node_modules`、`__pycache__`、`.venv`、`.pytest_cache` 這類名稱、被忽略的 `.pyc` 檔，以及放在被忽略名稱底下的 repository，因為這些內容不會進 repo，而且本機快取不該讓測試失敗。一旦強制加入 git，檢查就會失敗。要改成也擋的話，本機快取可能讓測試失敗。
- **指向資料夾的 symlink 不算違規** — 實作選擇放行，因為 git 只存連結本身，不存裡面的檔案。我試過連結後面確實有檔案、也能透過連結讀到，未 commit 和已 commit 都通過。要改成也擋，只需調整檢查，但會連帶擋下所有指向資料夾的連結。
- **以 gitlink commit 的 repository，檢查只看得到磁碟上有的內容** — gitlink 是外層 repo 只記下內層 commit 的指標，不存檔案；檢查是到磁碟上找檔案，所以新 clone 沒抓內容、資料夾是空的時，放在 skill 子資料夾或 skill 資料夾的 repository 會通過，只有更深一層的因為資料夾本身就違規而仍會失敗。這項限制沒有寫進檢查的說明，也沒有人明確決定過，我把它列在最後一節請你決定。同樣地，已 commit 的內容只要從磁碟移走，即使刪除還沒 commit，檢查也會通過。
- **巢狀 repository 裡的檔案一律算數，包括被忽略的** — 外層 git 看不進巢狀 repository，所以實作直接掃磁碟，不套用忽略規則。結果是本來扁平的巢狀 repository 只要多了 `__pycache__` 這類快取，檢查就會失敗；清掉快取後恢復通過。這比前面第一項嚴格，代價是偶爾誤報，好處是不會漏掉真正的巢狀內容。
- **審查細節改為指向現有來源** — `AGENTS.md` 不再自己列出審查鏡頭和人數，改指向鏡頭說明文件與計算人數的自動檢查工具，避免兩邊內容不一致。代價是讀者要多開一個地方才看得到細節。
- **這次不 bump plugin 版號** — 變更沒有動到任何 plugin 內容，已安裝的副本不受影響。若日後認為文件變更也要發版，需要另開變更。
- **把抓到問題的對抗測試留進常設測試** — 這樣之後每次變更都會跑到，代價是多了四個測試檔。
