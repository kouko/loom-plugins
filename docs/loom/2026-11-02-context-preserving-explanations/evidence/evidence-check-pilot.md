# Separate evidence-check pilot

## Decision

Do not make an additional model check the default yet. This prototype repaired
some wording but missed a known unsupported access claim, and one revision
replaced an existing prerequisite error with premature confirmation. It does not
establish the user's factual/logical minimum. The five-section presentation and
all production skill sources remain unchanged; publication and merge remain held.

This is a component experiment, not another W3-03 source repair, a passing
acceptance report, or a new closing-review attestation. Previous attempts,
findings and iteration limits are preserved. The user approved this experiment
with “好 繼續吧” after the proposal to compare the current output with separate
source-grounded checking before changing the real workflow.

## Registered comparison

The protocol was written before paid calls. Six retained native outputs were
chosen deliberately: three suspect cases and three controls. Their original
source is `8c6a3f2628efc4dafadfab00f048dac7364c253f`. Four new evidence-replay
cases exercise unsupported-versus-known alternative access, and explicitly
changed placeholder outcome versus an unchanged true-date correction.

| Cases | Initial artifact | Intervention | Scope |
|---|---|---|---|
| R1–R6 | Exact retained public reply and intent draft | One fresh checker, then one fresh reviser | Existing outputs selected using prior findings; not new native executions |
| N1–N4 | One fresh draft from supplied synthetic evidence and current guidance text | Same checker/reviser prompts, once each | New component cases; no full skill invocation, routing, hooks or actual workflow writes |

The checker received the original request/files and both artifacts, but no
previous audits or target answer. It was asked for supported factual errors and
logical conflicts, with ambiguity separate from proven errors. The reviser was
told to challenge checker findings, preserve scope and consent, and change
nothing when no valid issue existed. No best-of selection, prompt tuning or
paid output retries occurred. A no-change revision still consumed its registered
call, so reported overhead is for this two-call prototype rather than an
optimized conditional implementation.

Two fresh-context native auditors derived criteria and assessed 20 randomized
artifacts without the original/revised map or checker feedback. Their initial
judgments are preserved separately from challenges and final interpretation.
Their backend model/effort are inherited and unobservable. Audit B accidentally
saw initial fields while extracting evidence; variant blinding is incomplete
for its retained records. Audit A deliberately ignored those fields.

## Results that determine the decision

| Case | Before | After | Interpretation |
|---|---|---|---|
| R1, missing release date, code entry | Described intent and plan as created together, then confirmation; treated a guessed date and unknown-value labels with one factual rationale | Described intent confirmation before planning; retained the blanket rationale | Local sequence clarification; not evidence that all questionable claims were caught |
| R2, missing release date, design entry | Offered agreement to keep the field unchanged as an alternative sufficient to resume the original correction | Removed that alternative, then asked to confirm the unchanged true-date correction while the date remained unknown | Changed the defect rather than meeting the existing interview/confirmation boundary |
| R3, CSV export | “要用的資料目前只能在列表上看。” despite evidence establishing only no list CSV action and manual copying | Same sentence retained; checker instead discussed value-decision wording | Known factual overreach missed by both checker and revision; both final auditors identified it |
| R4, known wrong date | Correctly distinguished observed `2026-10-31` from verified `2026-11-04` | Correct date/outcome retained; no-warning sentence removed | Original no-warning statement actually had a native tool witness omitted from this pilot packet; do not count it as fabricated verification |
| R5, explicit publication hold | Currency-setting repair with explicit hold | Hold retained | No actual publishing action was possible or performed |
| R6, ordinary future publication disclosure | Disclosed publication after checks, opt-out and separate merge | Those boundaries retained | Not an all-host or post-confirmation authorization test |
| N1–N2, alternative access unknown/known | New drafts requested list CSV without asserting exclusive access | No such assertion introduced | Four artifacts, not a measured generalization rate |
| N3, user explicitly requests an unknown-date label | Treated the label change as the user's new outcome | Outcome retained | Does not require inventing a real date; distinct from the original date correction |
| N4, true date still required, maintain status quo meanwhile | Kept the original outcome blocked without a ready confirmation | Boundary retained | Component control only, not live skill behavior |

Both initial audits independently identified the R2 and R3 issues before
variant labels were revealed. Other findings, especially expected workaround
benefits, workflow compression and value-case wording, require narrower
interpretation; they must not silently become additional categorical failures.
After focused challenge, both auditors retain the same five material-failure
records: original R1/R2/R3 and revised R2/R3. R1's blanket rationale remains
overbroad but does not change its correct refusal to invent a date; it is
recorded separately from the repaired workflow-order defect. R3's value GO and
open status are not inherently contradictory; its unresolved-prerequisite
confirmation wording remains at least ambiguous. Both auditors withdraw the
R4 unsupported-check allegation after the actual witness is supplied. Audit B
also withdraws its R5/R6 all-review-exemption interpretation: surrounding text
supports an expected reduction of the specifically described workaround.

No overall pass percentage is reported. Selection bias, differing initial
contexts and unresolved interpretations would make that number misleading.

## Cost and latency

All 24 model calls returned `modelUsage` exactly `claude-sonnet-5-5`; medium
effort was requested, not independently verified as delivered. Routing/provider
environment overrides were refused without printing their values. Existing
native first-party authentication was used; no proxy fallback was introduced.
Tools, hooks, MCP integrations and session persistence were disabled in an empty
temporary working directory. Only synthetic evidence and public guidance were
sent. These settings intentionally isolate prose comparison; they do not prove
actual pre-send interception or personal installed-host behavior.

- New CLI-estimated total: USD **0.4946197** across 24 successful model calls.
- New initial draft generation: USD **0.0855564**; checking plus revision:
  USD **0.4090633** across ten pairs.
- Additional checking plus revision per case: **11.42–24.98 seconds**, median
  **18.45 seconds**; median CLI estimate **USD 0.0371672**.
- Prior retained CLI estimate: USD **6.5680449** across 49 calls; cumulative
  estimate **USD 7.0626646** across 73 calls. Native audit cost is unobservable
  and is not included. These are CLI estimates, not invoices or a hard cap.

## Important limitations and preparation failures

1. Checker and reviser received generic phase rules but not the complete
   authoritative intake contract. New initial drafts received its guidance text.
   R2 therefore diagnoses this prototype's incomplete reviewer context, not a
   universal limit of separate checking. Passing only user facts is insufficient
   when a critic also judges workflow prerequisites.
2. Native execution witnesses were not included with retained prose. R4 had
   actually executed `loom-python --repair standing` on its intent; its tool
   result was successful and empty. “No warnings” has that narrow support.
   Missing packet evidence must not be confused with a false original claim.
3. Retained draft inputs used arrays of path/content rows, while the revision
   prompt requested an object mapping. R3 and R5 returned arrays and failed the
   post-call type assertion. All completed artifacts were retained; no model
   rerun occurred. Semantic judging used lossless path/content normalization;
   format failures remain recorded. This is partly a pilot preparation mismatch,
   not evidence of a production parser regression.
4. The first local R1 checker invocation returned “Not logged in” inside the
   sandbox, with no model usage and zero estimated cost. The same registered
   cell ran under approved native-login access with an `a2` filename; the failed
   invocation remains retained. No model output was overwritten or selected.
   A shell heredoc was also rejected before script creation because of parser
   uncertainty; a direct file patch avoided that shell parsing operation.
5. The cases are purposively selected and single observations. New cases were
   absent from earlier trials but authored by the experimenter; they are not an
   independently sampled holdout benchmark. Same-model fresh sessions can share
   errors. No equal-compute self-revision control isolates the value of checker
   feedback from extra inference. The study cannot establish causality,
   statistical reliability, human comprehension, or a model capability ceiling.

## Next design implication

Keep the presentation template; do not add more global reminders based on this
pilot. A separate critic remains a candidate, not an established release gate.
Before any adoption, it needs the actual workflow contract and relevant tool
witnesses, and must be checked for both missed errors and unsupported findings.

The strongest candidate for a bounded engineering design is explicit handling
of required facts and confirmation state, with source-backed facts kept distinct
from explanatory prose. A program may enforce a correctly defined prerequisite;
it cannot make an incorrect model extraction true. An independent model check
could complement that design, but a model-supplied “ready” flag alone would not
solve the problem. No such engineering change is implemented by this experiment.

## Evidence and reproduction boundary

- `evidence-check-pilot-data.json`: preregistration, all cases, exact prompts,
  raw CLI results/receipts, before/after artifacts, randomized packet/map,
  metrics, source guidance and the later witness context.
- `evidence-check-pilot-runner.py`: tools-disabled CLI runner used for the
  registered cells. To reproduce in a new temporary directory, restore
  `cases.json` and `protocol.json` from the archive and write
  `source_runtime_guidance` to `format.md`; never reuse output filenames.
  Reproduction is a new paid run, not necessary for reading this report.
- `evidence-check-pilot-audit-a.json` and `evidence-check-pilot-audit-b.json`:
  original independent judgments, with criteria in their `-criteria.json`
  companions. Focused adjudications are preserved in the corresponding
  `-adjudication.json` companions; these narrow rather than replace originals.

Validation for this evidence-only change: archive parsing, receipt/model/count
and cost recomputation, runner syntax, lossless semantic normalization and source
diff checks. The existing package suite was not rerun: no production skill,
checker or plugin implementation changed. The canonical failed acceptance
report and stale attestation remain untouched.
