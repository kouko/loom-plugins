## Method and safeguards

Six identical synthetic requests ran once per variant in fresh native Claude
Code sessions. All baseline calls started before candidate calls, using a
frozen snapshot; there was no best-of selection or prompt tuning against this
round's results. One new sparse README case exercises a known preview-command
correction without a supplied wider roadmap. Other cases reuse existing CSV,
missing-date and invoice controls.

Both variants retained original hooks with recorded sandbox wrappers, seven
hook preflight checks, and private-read/network-bind/source-write denial probes.
All twelve sessions returned exactly `claude-sonnet-5-5` in `modelUsage`;
medium effort was requested, not independently verified as delivered. Inherited
provider/model environment overrides were refused without printing credentials.
Native first-party authentication was retained. No actor permission denial,
fixture commit, input change or runtime snapshot change was observed.

Two fresh-context auditors froze source-only case criteria first. They then
read twelve randomized replies, saved intents and actual tool-use/result
trajectories without the variant map or each other's judgments. Snapshot/fixture
paths and source SHAs were normalized in the judging packet only. Loaded
guidance text can reveal stylistic differences, so this is not perfect blinding.
Native audit backend model/effort are inherited and unobservable. Initial
findings and focused challenges are both retained; doubtful readings are not
automatically treated as factual defects.
