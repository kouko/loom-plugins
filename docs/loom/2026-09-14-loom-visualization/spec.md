# Add a loom-visualization skill for coding-harness conversations — spec
intent: 2026-09-14-loom-visualization@c1b76092
pre-build-review: required — removes the public `loom-workflow:cot-explain` skill name and adds a SessionStart hook that interacts with another plugin's hook

## Requirements
REQ-1 — Skill replaces cot-explain
  The loom-workflow plugin shall ship a `loom-visualization` skill and no `cot-explain` skill, install on Claude Code and Codex, and leave no repository reference that routes to `cot-explain` except historical change records → Acceptance #1
REQ-2 — Eleven shape templates
  The loom-visualization skill shall provide one template for each of the 11 information shapes named in the intent, each carrying a markdown-table form, an ASCII form or a stated table substitute, and a Mermaid form → Acceptance #2
REQ-3 — Client-aware form choice
  WHEN the skill's client check runs in a Claude Code terminal session, a Codex CLI session, or an unrecognised environment, the skill shall return the form documented for that client and shall not permit Mermaid for any client not confirmed to render it → Acceptance #3
REQ-4 — CJK-safe ASCII without third-party packages
  WHEN an ASCII diagram with Chinese or Japanese labels is produced through the skill on an interpreter with only the Python standard library, the skill's alignment check shall pass → Acceptance #4
REQ-5 — Mermaid templates parse
  The loom-workflow package shall carry a validation program under which every Mermaid form in the skill's templates and references parses without error using Mermaid's own parser → Acceptance #5
REQ-6 — Reasoning page mode
  WHEN documented reasoning is given to the skill's page mode, the skill shall produce a standalone reasoning page equivalent to what `cot-explain` produced → Acceptance #6
REQ-7 — Obsidian boundary
  IF the requested output is a note inside an Obsidian vault THEN the skill shall decline and name the Obsidian visualizer, and no template shall contain Obsidian-only syntax → Acceptance #7
REQ-8 — Unprompted use
  WHEN a user in a fresh session with only the loom plugins installed asks to compare several options or explain a multi-step flow, the agent shall present a table or diagram following the skill without the skill being named → Acceptance #8
REQ-9 — One trigger instruction alongside ascii-graph-toolkit
  WHILE `ascii-graph-toolkit` is also installed, the session-start context shall contain one diagram trigger instruction rather than two conflicting ones → Acceptance #9
REQ-10 — Package suite green
  The repository package test suite shall pass with the change applied → Acceptance #10

## Design decision
- **Location and identity** — the skill lives at `loom-workflow/skills/loom-visualization/`; `cot-explain` is deleted. Every live reference is renamed to `loom-visualization`: `loom-code/contract/manifest.yaml:27`; `docs/loom/evidence/mechanisms.yaml:91-93` (skill id, eval) and `:202` (tool id); `loom-workflow/scripts/test_skill_count.py:25`; `loom-workflow/skills/using-loom-workflow/SKILL.md:16,31`; `README.md:163`; `loom-workflow/README.md`, `README.ja.md`, `README.zh-TW.md` (`:36`, `:109`); the keyword lists in `loom-workflow/.claude-plugin/plugin.json:21` and `loom-workflow/.codex-plugin/plugin.json:21` plus the Codex `longDescription` (regenerated by `scripts/sync_codex_manifests.py`); `scripts/run_package_tests.py:37`; `scripts/test_run_package_tests.py:54`; `.github/workflows/loom-workflow-ci.yml:11,57,67-68,87`. `loom-workflow/tests/test_cot_explain_scripts.py` becomes `test_loom_visualization_page_scripts.py` pointing at the new skill path, and `loom-workflow/scripts/test_cot_explain_compaction.py` is replaced by `test_loom_visualization_compaction.py` (required SKILL.md sections plus the token cap), which becomes the skill mechanism's eval. The frozen description baseline in `docs/skill-dogfood/2026-09-13-compress-loom-skill-descriptions/cases.md` is a historical record and is not re-frozen; `scripts/test_loom_skill_description_catalog.py` gains an explicit rename map (`loom-workflow/skills/cot-explain/SKILL.md` → `loom-workflow/skills/loom-visualization/SKILL.md`) applied to the on-disk leaf paths before comparing with the baseline, so the hash, character and word assertions stay unchanged. Historical records under `docs/loom/` and `loom-workflow/CHANGELOG.md` history keep the old name. The CI pin on `markdown-it-py` for this suite (`loom-workflow-ci.yml:85`) is dropped so the stdlib renderer is what CI tests. `agent-decided` — a rename keeps the skill and contract populations net-zero; a rename map keeps a hash-pinned historical baseline intact.
- **No alias for `cot-explain`** — removal is recorded as a breaking change in the loom-workflow CHANGELOG. `user-decided` (intent Constraints, 2026-09-14). The version moves to 5.0.0 in both plugin manifests. `agent-decided` — semantic versioning for a removed public skill name.
- **Folder shape** — flat subfolders only: `SKILL.md` (procedure: classify the information shape → read `templates/<nn>-<shape>.md` → run the client check → choose form → generate and verify, or page mode), `templates/` (11 shape files), `scripts/` (client check, ported ASCII generators and checks, page renderer and verifier, Mermaid validator), `references/` (client capability matrix, CoT Mermaid spec, fidelity check), `assets/` (page template, trigger card), `NOTICE.md` (third-party attribution). `agent-decided` — one file per shape lets the agent read only the shape it needs; SKILL.md stays under the ~6,000-token cap by moving cot-explain's long procedure into `references/`.
- **Template file form** — each template starts with `target: coding-harness`, then sections `When to use`, `Table`, `ASCII`, `Mermaid`, `Common mistakes`. Shapes without a faithful ASCII form (data model) state the table substitute in the `ASCII` section. Mermaid forms use only long-stable diagram types (flowchart, sequenceDiagram, stateDiagram-v2, erDiagram, mindmap, timeline, gantt, quadrantChart, xychart-beta, pie); templates are authored here from Mermaid's MIT docs and Diagon's MIT conventions, not copied from the Obsidian visualizer. `agent-decided` — the intent forbids mixing with Obsidian templates, and authoring avoids carrying the Obsidian skill's third-party notice.
- **Client check** — `scripts/detect_client.py` (stdlib) reads environment variables and prints JSON `{client, mermaid, remote_viewer, reason}`. Rules: `CLAUDECODE=1` → `claude-code-<CLAUDE_CODE_ENTRYPOINT>`; `CLAUDE_CODE_BRIDGE_SESSION_ID` set or entrypoint `remote_*` → `remote_viewer: true`; `CODEX_THREAD_ID`, `CODEX_SANDBOX` or `CODEX_CI` → `codex`; `GEMINI_CLI=1` → `gemini-cli`; anything else → `unknown`. `mermaid` is `false` for every environment-detected client in this change, because each is documented or reported to show Mermaid source raw, or is unverified. SKILL.md allows Mermaid only when the agent has no shell and its own host identity is claude.ai or the Claude Desktop chat, where Mermaid rendering is reported. Default form everywhere else: markdown table plus ASCII in a code block. `agent-decided` — a wrong Mermaid choice shows the user raw source, a wrong ASCII choice still reads; the matrix in `references/client-matrix.md` carries sources and a verified date.
- **ASCII engine** — port `width`, `glyphs`, `align`, `checks_seam`, `checks_table`, `checks_kink`, `generate` and the six generators (`table`, `flow`, `tree`, `bar`, `arch`, `seq`) from ascii-graph-toolkit v0.6.0, recording the source commit in each file header. `width.char_width` is reimplemented on `unicodedata`: control characters (`Cc`), combining marks and format characters (`Mn`, `Me`, `Cf`) → 0, East Asian Width `W`/`F` → 2, else 1. The ported width tests replace ascii-graph's `wcwidth`-derived expectations with ones derived from the interpreter's Unicode database, and pin CJK ideographs, kana, CJK punctuation, full-width forms and every box-drawing glyph the generators emit. The four shapes with no generator (branching decision, reasoning chain, state, timeline) ship as hand-authored ASCII in their templates and are verified by the ported checks in tests. `agent-decided` — stdlib width agrees with `wcwidth` on CJK ideographs, kana, CJK punctuation and box-drawing glyphs, which is the failure the intent names; it diverges on some symbols, Hangul Jamo medials and Indic spacing marks, so the template guidance keeps emoji and pictographic symbols out of box labels.
- **Mermaid validation** — a test-only Node project at `loom-workflow/tests/mermaid/` (`package.json`, committed `package-lock.json` pinning `mermaid` and `jsdom`, `validate_mermaid.mjs`; `node_modules/` git-ignored and outside the skill folder) extracts every ```` ```mermaid ```` block from the skill's `templates/*.md` and `references/*.md`, runs `mermaid.parse` under a jsdom window, and exits non-zero on any parse error or when it finds zero blocks. A new CI job in `loom-workflow-ci.yml` runs `actions/setup-node`, `npm ci` and the validator with no skip path. The pytest wrapper runs the validator when `node_modules` is installed; otherwise it skips with the reason printed, and it fails instead of skipping when `CI` is set. The blind run installs and executes the validator directly. `validate_mermaid.mjs` also carries a self-test that a known-bad block (`A -> B`) is rejected, so the check cannot pass vacuously. `agent-decided` — a scratch probe on 2026-09-14 showed `mermaid.parse` fails headless without a DOM (`DOMPurify.addHook is not a function`) and passes with jsdom, while rejecting `A -> B`; mermaid-cli would need a Chromium download.
- **Page mode** — cot-explain's `render_cot_html.py`, `verify_cot_html.py`, `cot-report-template.md`, `mermaid-cot-spec.md` and `fidelity-check.md` move into the new skill unchanged in behaviour; `render_cot_html.py`'s `markdown_it` use (CommonMark subset plus tables, `render_cot_html.py:166-167`) is replaced by a stdlib renderer covering headings, paragraphs, emphasis, inline code, links, lists, tables and fenced blocks, so the existing script tests — renamed to `loom-workflow/tests/test_loom_visualization_page_scripts.py` and run against the stdlib renderer — are the equivalence oracle for REQ-6, together with the `leftover_markdown` check. `why-these-rules.md` is dropped as design history. `agent-decided` — the intent forbids third-party Python at run time.
- **Obsidian boundary** — SKILL.md's first step checks whether the output target path has an ancestor directory containing `.obsidian/`; `detect_client.py --target <path>` reports `obsidian_vault: true` for it. The skill then declines and names `obsidian:obsidian-mermaid-visualizer`. A test asserts no template contains Obsidian wikilinks (`[[`) or callouts (`> [!`), and — as a template style rule to avoid collision with Obsidian comments — no `%%` Mermaid comment lines. `agent-decided` — a `.obsidian/` folder is the vault marker Obsidian itself creates.
- **Trigger card** — loom-workflow gains a Claude SessionStart hook (`startup|clear|compact`, script `loom-workflow/hooks/session-start`) that prints one of two cards from `assets/` as `additionalContext` in the same three-key JSON shape loom-code uses, stdlib Python only. Both cards are imperative and at most 150 words, measured by a test with Python `str.split`.
  - **Full card** (`trigger-card.md`): before explaining an option comparison of 2+ options, a flow of 3+ steps, a branching decision, a state or lifecycle, an actor sequence, an architecture, or a reasoning chain, and before typing any box-drawing diagram, invoke `loom-visualization`.
  - **Coexistence card** (`trigger-card-coexist.md`), printed only when `ascii-graph-toolkit` is active: it contains no trigger for flows, state machines, architecture, sequences or box-drawing diagrams — those shapes are left entirely to the toolkit's own card — and triggers `loom-visualization` only for option comparisons, branching decisions, reasoning chains, timelines, quantities, data models and reasoning pages. A test asserts that no trigger phrase in the coexistence card names a shape named in the toolkit card's trigger lines, using a fixture copy of that card.
  - **Active means** all of: the config directory is `$CLAUDE_CONFIG_DIR` or else `~/.claude`; `plugins/installed_plugins.json` has a key starting `ascii-graph-toolkit@`; that key is `true` in `enabledPlugins` after merging the user `settings.json`, then the working directory's `.claude/settings.json` and `.claude/settings.local.json`; and, for an entry whose `scope` is `project` or `local`, its `projectPath` equals the working directory. Any unreadable or malformed file counts as not active, so the full card prints. Tests cover installed-and-enabled, disabled, other-project, config-dir override and malformed JSON.
  - No Codex hook is added.
  - `agent-decided` — prose-only guidance was measured not to change behaviour while an imperative card did; when activity cannot be proven, one loom card is safer than none; loom-code registers no Codex SessionStart hook, so Codex support is unverified.
- **Hook mechanism registration** — `loom-code/scripts/check_mechanisms.py` hook recompute and the `counting:` paragraph in `docs/loom/evidence/mechanisms.yaml` widen to include `loom-workflow/hooks/hooks.json`. Two hook ids are registered: the new `SessionStart:startup|clear|compact:session-start` and the already-shipping `PostToolUse:Write|Edit:validate-skill-folder-structure.sh`, each with its eval (the card test file and the existing folder-structure test). The loom-workflow 5.0.0 CHANGELOG section carries `budget-exception:` lines for both, the first as a new mechanism earning its eval, the second as a counting correction for a hook that already existed. The loom-code session-start word cap (`loom-code/scripts/test_session_start_words.py:31`) stays scoped to loom-code; the loom-workflow card has its own 150-word cap. `agent-decided` — PRINCIPLES.md non-negotiable 4 requires every mechanism to be counted and to carry an eval; host-hygiene is reserved for infrastructure outside the loom flow.
- **Unprompted-use protocol** — the blind run for REQ-8 uses a Claude Code session whose enabled plugins are only `loom-code`, `loom-design` and `loom-workflow` (a scratch project whose `.claude/settings.local.json` disables every other enabled plugin; no credentials are copied). It sends seven fixed prompts, each in a fresh session: three ask to compare several options, three ask to explain a multi-step flow, and one control asks a one-line factual question. Pass means all six trigger prompts answer with a markdown table or a diagram in the form the skill prescribes for that client, and the control answers without one. `agent-decided` — a fixed prompt set with a negative control makes the line decidable by someone who never saw the change.
- **Out of scope held** — no edit to monkey-skills, the Obsidian skill, git-memory/ship/write-spec diagram rules, or page offline rendering.

## Alternatives considered
- Keep `cot-explain` as a separate skill beside the new one — rejected: two overlapping entries for reasoning diagrams, and the user chose to merge.
- Depend on `ascii-graph-toolkit` when installed — rejected: the intent requires loom-workflow to work alone.
- Vendor the `wcwidth` package — rejected: adds a third-party table to maintain; stdlib East Asian Width covers the CJK failure the intent names.
- Validate Mermaid with `@mermaid-js/mermaid-cli` — rejected: needs a headless Chromium download; `mermaid.parse` under jsdom was proven sufficient.
- Write generators for decision, chain, state and timeline — rejected: large new code for shapes whose static ASCII templates can be verified by the existing checks.
- Detect the client from available tool names — rejected as a primary signal: unverified beyond one host; kept only for the no-shell chat case.
- Allow Mermaid for the Codex IDE extension — rejected: one user report, and it cannot be told apart from Codex CLI by environment.
- Add a Codex SessionStart hook — rejected: no verified Codex SessionStart registration precedent in this repo.
- Re-freeze the description baseline in `cases.md` — rejected: it is a hash-pinned historical record; a rename map in the test keeps it intact.
- Detect ascii-graph-toolkit from `installed_plugins.json` alone — rejected: installed is not enabled, and project-scoped installs apply elsewhere.
- Classify the loom-workflow hook as host-hygiene — rejected: the card is part of a loom-workflow tool, not infrastructure outside the flow.
- Copy the Obsidian visualizer's Mermaid templates — rejected: they target Obsidian's bundled Mermaid and the intent forbids mixing.
