## 對你既有的資料做了什麼 (what this did to data you already had)

這個提醒只看寫入或指令裡提到哪個檔案，從不讀筆記內容，也不會自己寫任何東西；你本機既有的內建記憶不會被改動或搬移。之後 agent 存一筆它判斷為「任何人都適用」的教訓時，會在當下 repo 的 `docs/loom/memory/` 新增一個記憶檔並重建索引；repo 還沒有這個資料夾時會先建立它。這是新增，不會改既有的教訓。被移除的舊提醒腳本本來就沒有任何設定接上，移除不影響任何人。另外，只是用 shell 讀一筆記憶筆記也會出現提醒，這只是多一次提醒，不會寫任何東西。

## I decided for you

- **「移除後不再引用」的範圍** — 只算執行時用到的檔案和測試；更新紀錄、搬遷紀錄這類歷史文件保留舊名字。這是實作時 agent 的決定（寫在計畫的風險段）。若你要連歷史紀錄都清乾淨，要改的是幾份舊紀錄檔，但會改寫歷史。
- **提醒改用 Python 重寫，不沿用舊的 shell 腳本** — 舊腳本需要另外安裝的工具，沒有那個工具時會安靜失效；這是 agent 的決定。之後要改回去成本很低。
- **shell 指令只看字面上的路徑** — 經過變數或另一個腳本檔寫的筆記不提醒，由 description 補位；只讀筆記的指令也會提醒。這是修正時 agent 的決定（寫在 spec）。這次實測，agent 用 shell 寫的筆記剛好全都經過變數，所以這一塊目前實際上是靠 description 撐著。
- **第一輪我在小 repo 先放了空的記憶庫，重試時拿掉** — 重試專門驗「沒有記憶庫」的情況。

## Things I am not sure you want

- agent 用 shell 寫記憶筆記時，幾乎都是先把資料夾放進變數（像 `D=資料夾; cat > "$D/筆記.md"`），現在的提醒看不到這種寫法：重試 6 次全沒提醒。description 在其中 5 次仍讓技能被呼叫，剩下那次是本機才成立的事，本來就不該寫進 repo，所以這次結果都對。要不要讓提醒也認得「同一個指令裡先設定、再使用的變數」，還是接受目前只靠 description？
- 已知限制（照你的指示只回報、不修）：記錄時機的評估裡，兩位讀者都把第 4 個候選（任何人都可能遇到的指令陷阱）判成不記，可能是新加的「只跟某個工具有關就不記」這句把它往外推了；樣本只有各一次，舊版也判成不記，所以還不能下結論。
- 舊版在「請你記住」這種明講的情況下，本來就會把 repo 教訓寫進 repo（3/3）。看得出的差別是：新版會同時存一份在內建記憶、記憶庫位置固定了、本機才成立的事也會先經過分類。agent 自己主動存記憶時的效果，兩輪都沒有量到。
