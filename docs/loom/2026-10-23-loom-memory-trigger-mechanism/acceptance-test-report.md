## 對你既有的資料做了什麼 (what this did to data you already had)

這個提醒只看檔案名稱和修改時間，從不讀筆記內容，也不會自己寫任何東西；你本機既有的內建記憶不會被改動或搬移。每次 agent 跑完一個 shell 指令，它會看一下你本機所有專案的記憶資料夾有沒有剛被改過的筆記（實測約 0.01 到 0.02 秒），所以你在另一個 session 剛存了記憶時，這邊也可能多出一次提醒，這只是多一句話，不會寫任何東西。之後 agent 存一筆它判斷為「任何人都適用」的教訓時，會在當下 repo 的 `docs/loom/memory/` 新增一個記憶檔並重建索引，repo 還沒有這個資料夾時會先建立它；這是新增，不會改既有的教訓。被移除的舊提醒腳本本來就沒有任何設定接上。另外，第三輪試驗在你的 Claude Code 專案清單裡留下 7 個用完即丟的專案資料夾（只有試驗內容），我的刪除被安全機制擋下，清單在 evidence 檔，需要你核准或自己刪。

## I decided for you

- **「移除後不再引用」的範圍** — 只算執行時用到的檔案和測試；更新紀錄、搬遷紀錄這類歷史文件保留舊名字。這是實作時 agent 的決定（寫在計畫的風險段）。若你要連歷史紀錄都清乾淨，要改的是幾份舊紀錄檔，但會改寫歷史。
- **提醒改用 Python 重寫，不沿用舊的 shell 腳本** — 舊腳本需要另外安裝的工具，沒有那個工具時會安靜失效；這是 agent 的決定。之後要改回去成本很低。
- **shell 寫入改用「最近 10 秒有沒有筆記被改過」來判斷** — 不再看指令內容，所以經過變數寫的也抓得到。這是修正時 agent 的決定（寫在 spec），代價是：記憶資料夾被搬到別處時看不到、指令跑超過 10 秒才結束時看不到、別的 session 剛存記憶時可能多一次提醒、同一筆筆記在 10 秒內接著跑的指令會重複提醒。
- **前兩輪我把內建記憶導到暫存資料夾，第三輪改用真實位置** — 新的判斷方式只看真實位置，所以第三輪必須這樣試；只用新建的專案名稱。

## Things I am not sure you want

- 同一筆筆記寫完後 10 秒內，agent 再跑任何 shell 指令（包括跟記憶無關的 `ls`）都會再提醒一次：第三輪有一次同一筆筆記出現 3 次提醒。結果沒有出錯，只是多佔一點對話。你要的「一次」是「至少一次」就沒問題；如果是「剛好一次」，要不要讓同一筆筆記只提醒一次？
- 第三輪留下的 7 個試驗用專案資料夾要刪掉，刪除被安全機制擋下，需要你核准或自己刪（清單在 evidence 檔）。
- 已知限制（照你的指示只回報、不修）：記錄時機的評估裡，兩位讀者都把第 4 個候選（任何人都可能遇到的指令陷阱）判成不記，可能是新加的「只跟某個工具有關就不記」這句把它往外推了；樣本只有各一次，舊版也判成不記，所以還不能下結論。
- 舊版在「請你記住」這種明講的情況下，本來就會把 repo 教訓寫進 repo（3/3）。看得出的差別是：新版會同時存一份在內建記憶、記憶庫位置固定了、本機才成立的事也會先經過分類、shell 寫入也會提醒。agent 自己主動存記憶時的效果，三輪都沒有量到。
