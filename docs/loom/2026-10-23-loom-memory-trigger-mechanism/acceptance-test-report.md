## 對你既有的資料做了什麼 (what this did to data you already had)

這個提醒只看寫入的是哪個檔案，從不讀筆記內容，也不會自己寫任何東西；你本機既有的內建記憶不會被改動或搬移。之後 agent 存一筆它判斷為「任何人都適用」的教訓時，會在當下的 repo 新增一個記憶檔並重建索引，這是新增，不會改既有的教訓。被移除的舊提醒腳本本來就沒有任何設定接上，移除不影響任何人。要注意：在還沒有記憶庫的 repo，第一次記錄會新建一個記憶資料夾，而位置目前不固定（試跑那次開在 `docs/memory/`）。

## I decided for you

- **「移除後不再引用」的範圍** — 只算執行時用到的檔案和測試；更新紀錄、搬遷紀錄這類歷史文件保留舊名字。這是實作時 agent 的決定（寫在計畫的風險段）。若你要連歷史紀錄都清乾淨，要改的是幾份舊紀錄檔，但會改寫歷史。
- **提醒改用 Python 重寫，不沿用舊的 shell 腳本** — 舊腳本需要另外安裝的工具，沒有那個工具時會安靜失效；這是 agent 的決定。之後要改回去成本很低。
- **試的時候我先在小 repo 建好空的記憶庫** — 因為第 1 條假設記憶庫已經存在；沒有記憶庫的情況只試了一次，結果寫在下面的問題裡。

## Things I am not sure you want

- repo 還沒有記憶庫時，agent 會自己挑位置（試跑那次是 `docs/memory/`，不是 `docs/loom/memory/`），因為技能文字從沒寫明位置，舊版也一樣。這個提醒現在會在每個裝了 loom-workflow 的 repo 觸發，要不要把預設位置寫死成 `docs/loom/memory/`？
- agent 用 shell 指令而不是編輯工具寫記憶筆記時，提醒不會出現（這次 19 個 session 裡有 2 個是這樣寫筆記）。description 本身在那次仍然讓技能被呼叫。要不要也攔 shell 寫入，還是接受這個缺口？
- 已知限制（照你的指示只回報、不修）：記錄時機的評估裡，兩位讀者都把第 4 個候選（任何人都可能遇到的指令陷阱）判成不記，可能是新加的「只跟某個工具有關就不記」這句把它往外推了；樣本只有各一次，舊版也判成不記，所以還不能下結論。
- 舊版在「請你記住」這種明講的情況下，本來就會把 repo 教訓寫進 repo（3/3）。這次看得出的差別是：新版會同時存一份在內建記憶、會出現提醒，而本機才成立的事也會先經過分類。agent 自己主動存記憶時的效果，這次沒有量到。
