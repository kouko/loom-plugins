## 我替你做的決定

- **共用建議格式** — 選擇只靠 Python 內建功能的共用模組，避免 help 提前依賴額外套件；改成各命令自行維護會增加重複規則。
- **文字位置** — 一般建議放 stderr，保留原診斷與 stdout；GitHub 規則報告留在原 stdout；改位置會影響既有讀取者。
- **錯誤分類** — 只對已註冊命令提供命令建議，未知或內部錯誤保持中性，不猜修法；細分需要額外可靠事實。
- **JSON 相容性** — 四個既有檢查維持原版本，新增可選欄位，成功為 null；改成必要欄位會增加相容成本。
- **交付狀態相容性** — 第五種 JSON 保留既有下一步欄位，以相同內容增加新欄位，不強制統一結構；移除舊欄位會破壞既有讀取者。
- **可選內容** — 只在核心結果驗證後顯示非空文字，忽略不適用建議，保留原診斷；擴大驗證器用途需要另訂契約。
- **依據實際結果建議** — 由知道結果的命令決定內容，不解析畫面文字，也不假造確認、重試或權限；未來新增原因要補相應情境。
- **零退出碼的限制** — 無法同步、規則未確認、非阻擋警告及缺少驗證記錄仍保持原語意；若改成阻擋將是政策變更。
- **成功後續與清理清單** — 只有確有下一步才提示；清理清單仍須先檢視與取得同意；改成自動處理會擴大資料操作範圍。
- **建議寫出失敗** — 只容忍建議自身的輸出錯誤，保留原結果與一次執行；主輸出失敗及程序中止不作成功保證。
- **hook 例外** — 保留宿主訊息格式與原生 Git hook 的精確內容，避免舊安裝被誤認為外來檔案；修改需處理所有權相容性。
- **其他協定例外** — 保留可執行 setup、CI 註記、進度、清理後切換目錄及確認清單的格式；新增一般文字會破壞原用途。
- **help 與啟動界線** — help 只供查詢，原有啟動與修復責任不變；啟動器及獨立工具不算新增 checker 命令。
- **覆蓋範圍的記錄** — 分開記錄十六個命令、五種 JSON 與兩種受驗證讀取方式；日後新增介面需補相應實測。
- **遠端實測界線** — 使用既有受控外部回應與臨時 Git 倉庫，未宣稱真實宿主或 GitHub 強制規則通過；補驗需要相應環境與授權。
- **版本與翻譯** — 採次版更新並同步衍生資訊，日文與繁中說明只同步版本；完整翻譯不是本次交付。
- **測試方式** — 使用獨立離線環境跑完整的相關測試模組，合併後以四個隔離工作程序重驗；不重跑全套，其完整執行由接受前的檢查負責。
- **合併後的版本** — 保留本次 CLI 版本與主線新增的流程工具版本，避免解衝突時覆蓋任一更新；若日後回退，需重新同步版本資訊並驗證。
- **重要問題的處置** — 沒有收到被主代理駁回的重要或致命問題，也沒有自行略過此等失敗。
