```markdown
title: Local ZIP writer for a one-file export
type: loom-research

created: 2026-11-12
updated: 2026-11-12
tags: [loom/research]
---

## Question and scope
Synthetic F1: select installed local ZIP writer; one UTF-8 text member,
round-trip content required, fewer subprocess boundaries preferred.
No product implementation authorized. Python 3.15.2 and Apple Zip 3.0 on macOS.

## Method and rationale
Bounded trade study plus matched one-member round-trip, stopping after both
candidates meet mandatory conditions. Common criteria: installed availability,
content/member correctness, process boundary. No performance comparison needed.

## Findings
Both Python zipfile and /usr/bin/zip are installed and round-tripped receipt.txt
containing `receipt α\n`. CLI exit 0, no stderr. Python uses an in-process
library API; CLI requires a subprocess from a Python caller. Neither is proved
superior under supplied constraints. The initial tentative Python preference
assumed a Python-hosted caller, which the fixture did not establish; that
recommendation is explicitly withdrawn. Installed CLI availability alone also
cannot establish that switching is better.

## Evidence
[Synthetic source](../2026-11-12-design-code-research-routing/evidence/fixture-sources.md)
defines constraints, not actual user behavior. Actual command: Python one-liner
used ZipFile.write and subprocess.run(["/usr/bin/zip","-q",...]) with identical
receipt.txt, then ZipFile.read on both. Output: zip_exit 0; both member lists
['receipt.txt']; both decoded contents 'receipt α\n'. Temporary data:
/private/tmp/loom-f1-1j6z7ein. Installed zipfile source inspected: write calls
_writecheck, then self.open(..., mode='w') and shutil.copyfileobj. This supports
the local call path; not every ZIP feature. CLI help identifies Zip 3.0 and stdin
support. `command -v` returned /usr/bin/zip and /opt/homebrew/bin/python3.

## Decision impact
Same-condition follow-up, 2026-11-12: the user challenged Python simplicity.
No new capability evidence was supplied. Reassessment exposed the unsupported
caller-language assumption; withdraw the initial preference. Keep both viable
and resolve caller context before recommending either. For an existing Python
caller prefer zipfile to avoid subprocesses; for shell prefer installed zip to
avoid introducing Python. These are conditional inferences, not measured ease.
Do not infer nested tool superiority from total feature count. If host is shell,
Python unavailable, or metadata/compression requirements change, revalidate.

## Limitations and open questions
Only one text payload was tested. No speed, metadata, permissions, password,
cross-platform, corruption or deployment claim. No product files changed.
```
