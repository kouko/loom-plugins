# 讓每一個對抗測試程式都值得留下 — 我試了什麼、發生了什麼

試跑日期 2026-09-23，在專案的一份乾淨副本上，版本 `3b44e42b`（比對基準 `dbce4780`）。
我沒有參與這次修改的實作。

先講結論：**十三條驗收條件裡，十一條成立，兩條不成立**。不成立的兩條是同一個原因 ——
用來「防止有人把已經刪掉的最低數量規定寫回去」的那道檢查，在英文句子裡只要數字和名詞
之間夾了一個形容詞就看不見了，而這次變更自己刪掉的那句英文，正好就是這個形狀。我把它
原封不動貼回說明文件，整套測試仍然全綠。

## 你要的每一件事，一條一條看

### 1. 被判定為「小改動」的變更，也會一併跳過對抗這一步，而且不另外發明第二套「多小算小」的標準

- **我怎麼試的**：我另外開了一個丟棄用的小倉庫，在裡面做一個只改一份說明文件的改動，
  然後問工具「這次要跑哪些步驟」。
- **發生了什麼**：工具回答要跳過的步驟是「規格、計畫、對抗、盲跑」四項——對抗確實被
  加進了原本就會自動跳過的那一組。同一個問題在舊版本上問，跳過的只有三項。
  判斷「多小算小」的地方仍然只有一處，審查人數和跳步兩件事讀的是同一段判斷。
- **證據**：`selection show` 的輸出，`skip` 欄位為 `["spec","plan","adversarial","blind-run"]`。
- **判定**：**成立**。

附帶一句值得你知道的調整：現在「小改動」的門檻比「只需要一位審查者」更嚴格一點——
只要這次改動裡出現任何一個「會被執行的檔案」（程式、腳本、測試），或者刪掉了任何一個
測試，就不算小改動。理由是：跳過對抗的正當性，來自「這次改動沒有任何會被執行的行為可以
被打壞」。

### 2. 這條界線有拿歷史紀錄重新檢查過，而且說明了結論

- **我怎麼試的**：讀這次變更留下的那份界線檢討文件，再自己照它寫的重算方式，
  把它點名的四個歷史改動重跑一次。
- **發生了什麼**：文件的結論是「界線維持不變」，理由是：在五個倉庫、134 個歷史改動中，
  能重算的 128 個裡只有 2 個會被這條界線放行，兩個都是純文件改動，兩個都沒有產生任何
  對抗程式，也沒有任何對抗程式抓到過缺陷。文件還誠實地寫下一個「其實可以再放寬」的
  觀察，並說明為什麼這次不做（因為同一段判斷也決定審查人數，而那不在這次範圍內）。
  我重跑了它點名的四個改動，四個答案都與文件一致。
- **證據**：界線檢討文件；我自己重跑的結果——兩個被放行的改動判定為「小」，兩個被排除的
  改動判定為「不小」。
- **判定**：**成立**。
  但要說清楚：文件裡的百分比與總表是從五份調查用的試算表算出來的，**那些試算表不在
  倉庫裡**，所以那部分數字我無法自己重算，只能確認它給了可重跑的方法，而方法在這個倉庫
  能重跑的部分都對得上。

### 3. 真的要跑對抗時，留下的程式最多五個，而且沒有「寫個理由就能破例」的後門

- **我怎麼試的**：在丟棄用的倉庫裡做一個「不小」的改動，先放六個對抗程式，再減到五個。
- **發生了什麼**：六個時被擋下，訊息是「這次改動有 6 個對抗測試程式；最多只允許 5 個」；
  減到五個就通過。我也翻過相關說明與程式碼，沒有任何「填一個理由就放行」的欄位或分支；
  說明文件明講「想多寫、或想整步跳過，用白話講一句就好」。
- **證據**：兩次執行的輸出（一次被擋、一次通過並寫出驗證紀錄）。
- **判定**：**成立**。

### 4. 每個留下的程式都要寫一行「我防的是哪一類缺陷」，沒寫的會被機器擋掉

- **我怎麼試的**：把其中一個程式開頭那行說明刪掉再試一次。
- **發生了什麼**：立刻被擋，訊息點名是哪一個檔案、說它「前 20 行裡沒有那一行說明」。
  內容本身不限格式，只要不是空的就算。我也看了這次變更自己留下的四個程式，四個都寫了。
- **證據**：被擋下的輸出；四個程式的開頭數行。
- **判定**：**成立**。

### 5. 第 3、4 條由同一條新規則重算，規則清單剛好多一條，沒有舊規則被刪或改名

- **我怎麼試的**：分別列出新舊兩個版本的規則清單，逐行比對。
- **發生了什麼**：舊版 25 條、新版 26 條，差異只有一行——新增 `adversarial.proportionate`，
  沒有任何一條消失或換名字。倉庫裡也有一個測試在盯著「總數是 26」。
- **證據**：兩份清單的比對結果（唯一差異：`> adversarial.proportionate`）。
- **判定**：**成立**。

### 6. 抓到缺陷的程式要併進「以後每次都會跑」的測試裡，沒抓到的要說明並移除；這是審查站的規矩，不新增機器規則

- **我怎麼試的**：讀審查站的那段文字，確認它兩半都講清楚了；再確認確實沒有為它新增
  機器規則（第 5 條已經證明只多一條）；最後檢查這次變更自己的四個程式現在在哪裡。
- **發生了什麼**：文字兩半都在，而且說明了「從建置階段交接的紀錄讀每個程式的結果，
  沒給結果的一律當成沒抓到」。倉庫裡有一個測試在盯著這段文字。
- **證據**：審查站的那段文字與盯著它的測試。
- **判定**：**成立**（規矩本身已經就位）。
  **但這次變更自己還沒照做**：它留下的四個程式仍然只躺在這次變更的資料夾裡，
  不在「以後每次都會跑」的那套測試裡——我確認過那套測試不會收集那個資料夾。
  依這四個程式自己寫的說明，它們描述的問題後來都有對應的修正，也就是說它們是「有抓到」
  的那一類，照規矩應該要被併進去。這件事必須在這次審查結束前完成，否則這條規矩在它
  自己身上第一次就沒有生效。

### 7. 「更新程式要附突變證據」這個義務只針對已經併入常跑測試的程式，而且只寫在一個地方

- **我怎麼試的**：在所有會被 agent 讀到的說明文字裡，搜尋「突變證據」。
- **發生了什麼**：只出現一次，就在對抗流程的那份說明裡，而且那句話已經明確限定在
  「被帶進以後每次都會跑的那套測試的程式」。
- **證據**：全文搜尋結果（一筆）。
- **判定**：**成立**。

### 8. 沒有任何會被讀到的文字再規定「最少要幾個」；數量只寫在一個地方；有檢查在防止它被寫回來

- **我怎麼試的**：先跑那組專門檢查這件事的測試（全綠）。接著做真正的試探：把
  「至少三個」重新寫回其中一份說明文件，再跑一次。
- **發生了什麼**：前兩半是成立的——今天確實沒有任何地方寫最低數量，數量也確實只寫在
  一份文件裡，其他地方都改成指向它。**第三半不成立**：我把這次變更自己從英文說明裡
  刪掉的那句話原封不動貼回去（「至少三個可執行的濫用與邊界案例」的英文原句），
  整套測試 112 項**全部通過**，沒有任何一項發現。
  原因很具體：那道檢查在英文裡只看數字後面**緊接著**的那個字是不是「案例／程式」之類的
  名詞；只要中間夾一個形容詞（像「三個 *可執行的* 案例」），它就當作這句話跟數量無關。
  中文和日文的同一句話會被抓到，英文的不會。
- **證據**：貼回英文原句後測試 112 項全綠；直接餵句子給那段掃描程式，
  「write at least three cases」會被抓到，「write at least three executable abuse or
  boundary cases」不會。
- **判定**：**不成立**（前兩半成立，防止寫回來的那道檢查對英文有漏洞）。

### 9. 三份翻譯說明和倉庫慣例檔可以用自己的話重述，但有檢查會在它們跟唯一出處矛盾時擋下來

- **我怎麼試的**：讀那道檢查，確認它涵蓋哪些檔案；然後用第 8 條同一個試探。
- **發生了什麼**：檢查確實涵蓋三份翻譯說明、倉庫慣例檔，以及對抗 agent 的觸發文字，
  而且中文、日文的矛盾寫法都抓得到。但它跟第 8 條用的是**同一段掃描程式**，所以同一個
  英文漏洞照樣存在：英文說明可以被改回矛盾的內容而不被發現。
- **證據**：同第 8 條。
- **判定**：**不成立**（涵蓋範圍正確，但英文的矛盾攔不住）。

### 10. 「至少要記錄一次對抗執行」由同一段共用判斷計算，不再是兩份說法不同的複本

- **我怎麼試的**：搜尋程式碼裡所有講這件事的地方；再在丟棄用的倉庫裡實際觸發一次。
- **發生了什麼**：現在只有一段共用判斷寫出這句話，兩個呼叫它的地方都不再自己寫訊息。
  實際觸發時，訊息是「at least one adversarial execution is required」。
- **證據**：搜尋結果只有一處；實際被擋下的輸出。
- **判定**：**成立**。

### 11. 被判定為小改動時，被跳掉的步驟要當場用一句話告訴使用者，也要列在 PR 裡

- **我怎麼試的**：我把自己當成照著站台文字走的人。文字說：「跑一次 `selection show`，
  如果它回報沒有綁定使用者選擇、而且跳過清單不是空的，就用這一句把那些步驟唸給使用者聽，
  內容從那個欄位讀，不要憑記憶。」我照做了，沒有任何需要猜的地方——我能直接寫出
  「Skipped as a narrow change: spec, plan, adversarial, blind-run」。四個站台的文字一致，
  Ship 站另有一句規定要把同樣的內容寫進 PR 的驗證段落。倉庫裡有兩個測試在盯這兩處文字。
- **證據**：我照著文字實際跑出來的輸出與可直接寫出的那一行；盯著文字的兩個測試。
- **判定**：**成立**（文字可照著執行，沒有需要猜的地方）。
  PR 本身還沒開，所以「PR 裡真的有那一行」這件事我這次看不到，只能確認規定與盯著它的測試。

### 12. 只有「打得動」的攻擊才留下程式；打不動的只寫進報告；報告要交代三個數字

- **我怎麼試的**：讀對抗流程說明與對抗 agent 的契約，當成指令照著想一遍。
- **發生了什麼**：說明寫得很明確——程式只有在「對著現狀就是紅的」時候才留下，因為
  一寫出來就是綠的那種程式只是在複述既有行為，不是在證明缺陷；打不動的攻擊寫成一次
  嘗試紀錄，不補程式。報告要交代的三個數字（找到幾個攻擊點、幾個值得留下程式、實際留下
  幾個）在兩處都寫了，而且 agent 回報的格式裡就有這三個欄位，不只是散文。
- **證據**：對抗流程說明的那兩段；agent 契約的回報格式；盯著這些句子的測試。
- **判定**：**成立**。

### 13. 對抗分兩段跑：先讀、先攻、先報告，第一段不寫任何程式；只有打成功的才進第二段

- **我怎麼試的**：同上，把 agent 契約當成要照做的指令讀一遍。
- **發生了什麼**：契約裡有一節叫「你執行的順序」，兩段編號分明：第一段攻擊並回報，
  什麼都擋住就到此為止；第二段只對打成功的寫程式，跑到紅了才留下，一寫出來就是綠的
  就丟掉。沒有含糊或需要自行判斷的地方。
- **證據**：agent 契約的那一節；對抗流程說明的對應段落；盯著它們的測試。
- **判定**：**成立**。

## 我替你決定的事

- **不成立的兩條我沒有去修**。盲跑的規矩是照交付的樣子量，修了就量不到了。
- **界線檢討文件裡的統計我只查了能查的部分**。原始試算表不在倉庫裡，我選擇說「無法重算」
  而不是照抄它的數字。如果你要那些百分比有人獨立驗過，得另外把試算表放進來。
- **第 6 條我判成立，但把「這次變更自己還沒照做」獨立寫出來**。另一種寫法是直接判不成立。
  我選擇分開講，因為「規矩有沒有寫好」和「這次有沒有照做」是兩件事，前者已經完成，
  後者是這次審查結束前還要做的動作。
- **沒有審查者的發現被駁回**。我沒有收到任何需要在這裡揭露的「被判定為重要卻被駁回」的
  項目。

## 我不確定你要不要的事

  由你決定要不要在這次一起做。
- 第 6 條要求把有用的對抗程式併進常跑測試。這次的四個要全部併進去，還是只併其中幾個？
  依它們自己寫的說明，四個描述的問題後來都有對應修正，看起來四個都該併。
- 這次變更的資料夾裡找不到計畫文件。如果計畫是你當初用白話說可以跳過的，那沒問題；
  如果不是，那是一份應該存在卻不見的紀錄。
