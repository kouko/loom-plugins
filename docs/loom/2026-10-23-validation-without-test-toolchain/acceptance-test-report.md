## 我替你決定的事

- **用發布時印狀態的那段檢查代替真的發布** — 我沒有執行發布本身，因為它會推送到遠端；改為直接呼叫發布、合併與 CI 共用的同一段狀態判斷。之後若要再確認，就是在有遠端的專案真正發布一次。
- **用手改過的證明測「不接受」的情況** — 最終驗證本來就拒絕產生這些錯誤證明，所以我讓證明的內容指紋對上 commit、只改掉指令或測試，模擬有人手改或沿用舊證明。這是驗證必須擋下的情況，但不是使用者平常會走到的路。
- **（實作時的取捨，計畫裡標為 agent 決定）驗證不再問 Go 哪些檔案會被編譯** — 改成「找漏洞測試若被排除編譯，最終驗證實際跑一次時會看到它沒通過而拒絕」。我試過被排除編譯的測試檔，最終驗證確實拒絕。若之後想在驗證時也擋，代價是驗證又得依賴 Go 工具。
