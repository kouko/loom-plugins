# 讓 Loom 站點向你報告時更常使用「圖表化呈現」技能 — 我試了什麼、結果如何

2026-09-14 在專案的乾淨副本上試跑（版本 b8fbcc1f）；修正後在新的乾淨副本上重跑第 1、4、5 條（版本 792d90a4）。第 2、3 條沿用先前結果：兩組共 36 份原始對話紀錄在 792d90a4 完全沒變，重數結果仍一樣。

## 你要的東西，逐條

### 1. The `loom-visualization` description names Loom stations reporting to the user as a use case, and the repository's description budget checks pass.
- **我怎麼試**：在乾淨副本裡打開這個技能的說明文字（Claude 用來判斷「現在該不該叫出這個技能」的那一句），並跑了專案自帶的「所有技能說明總長度不能超標」檢查。
- **結果**：在 792d90a4 的乾淨副本上，說明文字多了一段，意思是「包括 Loom 站點向使用者報告的時候（覆述需求、讓你做選擇、盲跑結果）」。長度檢查（這版多了一項）7 項全部通過。
- **證據**：說明文字原文已在乾淨副本中讀到；技能說明目錄檢查輸出「7 passed」（先前 b8fbcc1f 為「6 passed」）。
- **判定**：可用 — 說明文字確實點名了這個時機，長度也沒超標。

### 2. A before/after comparison runs the same fixed set of Loom station reporting prompts in fresh sessions with only the Loom plugins enabled, once with the current description and once with the new one, and reports how many sessions invoked `loom-visualization` in each.
- **我怎麼試**：
  1. 讀了對照測試的事前規則：9 個固定題目（覆述需求 3 題、讓你做難以反悔的選擇 3 題、盲跑結果報告 3 題），每題在舊說明、新說明各跑 2 次，以及「新版叫出技能的次數要嚴格多於舊版才上線」這條判定規則。
  2. 自己寫了一支獨立的計數程式，逐一打開 36 份對話紀錄，數每場對話有沒有真的叫出這個技能，不看作者的計數程式。
  3. 另外花一點額度抽查：挑 2 題（一題「讓你選資料庫」，一題「盲跑結果報告」），用同樣的方式各在舊、新說明下重跑 1 次。每場都是全新對話、空白資料夾，其他已安裝的外掛全部關閉，只載入該組自己的 Loom 副本。
- **結果**：
  - 我的獨立計數與作者公布的一致：舊說明 18 場中叫出 12 場，新說明 18 場全部叫出。每場也都確認有完整回答、沒有錯誤中斷。
  - 差距全部來自「盲跑結果報告」這 3 題：舊說明 6 場一次都沒叫出，新說明 6 場全部叫出；另外兩類題目在舊說明下本來就每場都叫出。
  - 抽查與原結果一致：「選資料庫」那題新舊都叫出了；「盲跑結果報告」那題舊說明沒叫出、新說明叫出。每場都確認只載入了該組自己的副本。
  - 一個保留：規則文件寫著「在任何一場對話跑之前就定好」，但它和結果、對話紀錄是同一次存檔進去的，所以光看存檔紀錄，無法證明它真的是先定的。重跑的抽查結果與規則吻合，但這點本身沒辦法驗證。
- **證據**：獨立重數與抽查結果的文字紀錄；4 份抽查對話的原始紀錄；原有 36 份對話紀錄。
- **判定**：可用 — 數字經獨立重數吻合，抽查也重現了同樣的差別；只有「規則是事先定好的」這點無法從紀錄上證明。

### 3. The new description ships only if its sessions invoke `loom-visualization` more often than the current description's; otherwise the description stays unchanged and the report says so.
- **我怎麼試**：把判定規則套到我自己數出來的次數上，再比對技能檔在這次改動前後有沒有真的換掉。
- **結果**：18 嚴格大於 12，規則的結論是「上線」；技能檔的說明文字確實從舊句換成了新句，而且只改了這一行。
- **證據**：獨立重數紀錄中的兩組總數；改動前後技能檔的比對。
- **判定**：可用。

### 4. The shipped description is word-for-word the one that ran in the comparison.
- **我怎麼試**：在 792d90a4 的乾淨副本裡，用專案自己的說明文字讀取方式，把上線的那句說明讀出來，算出它的指紋（一種內容稍有不同就會完全改變的編碼），和對照測試記下的指紋比對；再跑專案裡「上線文字必須等於測試文字」的防護測試。這版的防護測試把測試時的指紋直接寫死在測試裡，不再去讀對照紀錄文件。
- **結果**：指紋完全相同（e98a3ed1…fd45），與防護測試寫死的值、以及對照結果頁記下的值都一致；防護測試 3 項全部通過。
- **證據**：乾淨副本中重算出的指紋；防護測試輸出「3 passed」。
- **判定**：可用。

## 對你既有的資料做了什麼

沒有影響——這次只改了一個技能的一句說明文字、版本號與更新紀錄，外加這次改動自己新增的測試與對照紀錄；不會讀寫你已有的任何資料。唯一你會感覺到的差別是：之後 Loom 站點向你報告時，Claude 會更常叫出圖表化技能。

## 我替你決定的事

- **版本號升到 5.1.0** — 我把 loom-workflow 當成「新增能力、不破壞舊用法」的次版本升級。之後若覺得只是小修正，要改回修補版本號得在發布前改掉，發布後就只能往上加。
- **對照測試的規模與做法** — 我選了 3 類題目 × 每類 3 題 × 每組 2 次，並關掉你已安裝的 Loom 外掛，讓每組只載入自己的副本（否則新版的對話會混進舊說明）。樣本不大（每組 18 場），若之後想要更有把握，得再花額度擴大重跑。
- **撞到用量上限的那一場重跑了** — 新說明組有一場因為帳號用量上限直接回錯、沒有作答；我先修正計數程式，讓「錯誤結束」算作未完成，等上限解除後重跑那一場，原紀錄被覆蓋。若你認為應該把那場算成「沒叫出」，新說明會是 17/18，仍多於舊說明的 12/18，結論不變。
- **loom-memory 那筆經驗沒有放進這個分支** — 你沒回答要不要一起放，我採保守預設不放。若要放，得另開一次改動。

## 你可能不想要的地方

- 換成新說明後，「讓你比較選項」的回答有 12 場中 9 場沒有用一般表格，而是在程式碼區塊裡用線條畫出一張表（舊說明只有 12 場中 1 場這樣）。可是這個技能自己寫著「選項比較要用一般表格」。而且技能被叫出的次數之所以變多，完全來自「盲跑結果報告」那類訊息；覆述需求和讓你選擇的訊息，舊說明本來就每次都會叫出。換句話說，新說明沒有讓選擇類訊息更常用技能，卻讓它們更常偏離技能自己的表格規則。你能接受這個代價嗎，還是要先修正再上線？（我自己重數了一次，同樣是 9 比 1。）
- 對照規則是否真的在跑之前就定好，存檔紀錄證明不了（它和結果一起存檔）。你接受目前的證據，還是希望之後類似的測試先單獨存一次規則再開跑？
