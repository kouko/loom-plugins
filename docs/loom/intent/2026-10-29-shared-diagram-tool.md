# 跨站共用的圖表討論工具（draw.io 為首個後端）
originator: kouko
kind: engineering
needs-design: yes — .drawio 圖檔是使用者直接閱讀與編輯的檔案介面，且協作循環（agent 產圖、使用者手改、agent 讀回）是多狀態行為，現有規格未涵蓋
status: confirmed 2026-10-31

## Problem
與 agent 討論技術架構、流程與介面時只能用文字往返：對話視窗顯示不了圖形（Mermaid 在終端機顯示成原始碼），討論成果無法累積成一份雙方共用的圖檔，使用者無法直接在圖上表達意見。各站（理解問題、寫規格、談架構、談計畫）都有這個需求，但目前沒有任何共用通道。即使圖檔已建立，使用者存檔後仍須回到對話發訊息提醒 agent 讀回，協作會中斷。

## Proposed outcome
有一個各站共用的圖表工具：任何討論中 agent 可以產生與更新圖檔，使用者在自己的編輯器（VS Code 或本機 draw.io 桌面版）不用重新開檔就看到更新，也能手動編輯同一張圖讓 agent 讀回；在討論仍進行時，使用者存檔後不必再發訊息提醒 agent；圖檔隨變更存放在 git 存放庫內、可被機械檢查驗證。圖檔後端以可註冊的介面描述：使用者可以在已註冊的後端之間選擇當次要用的（draw.io 為首個實作），未來加入其他圖面工具不影響各站的引用方式。

## Acceptance
1. 在任一站的討論中，agent 產生圖檔後，使用者以 VS Code 的 Draw.io 擴充開啟該檔，agent 後續更新同一檔案時，開著的圖不重新開檔即顯示新內容（測試前先存檔或開啟自動存檔）。
2. 使用者在圖上手動做一項修改並存檔後，agent 讀同一檔案能正確複述該項修改。
3. 規格引用的每張圖附有文字投影（節點與連線清單）；投影與圖不一致時，機械檢查失敗並指出差異。
4. 內容損壞或不符合約定格式的圖檔會被機械檢查拒絕，訊息指出問題檔案。
5. 依存放庫文件，在乾淨環境裝妥前置工具後，第 1、2 條的協作循環可以重現。
6. 使用者以本機 draw.io 桌面版開啟同一圖檔時，agent 更新後：開啟自動存檔的設定下圖自動同步；未開啟時出現「檔案已修改」提示，點擊後圖顯示新內容。
7. 使用者可以在已註冊的圖檔後端之間選擇當次要用的後端；介面允許註冊多個後端，且至少以一個最小的示範後端（非 draw.io）證明註冊與選擇機制可運作。
8. 圖檔產生與驗證的說明位於單一共享位置，多於一個站引用它時不需複製其內容（抽查兩個站別文件確認引用而非重述）。
9. 在 agent 等待使用者修改圖的討論回合內，使用者以 VS Code 或 draw.io 桌面版修改並存檔後，不必再發訊息提醒；agent 能讀回並正確複述這項修改。
10. 等待期間沒有新的圖檔內容時，agent 不會把無關檔案變更或未改內容的存檔誤認為使用者的圖面修改。

## Constraints
- 圖檔必須存放在 git 存放庫內、隨變更一起審查；不得只存在雲端服務。
- 顯示與編輯面同時支援 VS Code 的 Draw.io 擴充與本機 draw.io 桌面版：前者無聲即時合併；後者在開啟自動存檔時無聲同步，否則以一鍵同步提示運作。
- 不依賴特定對話主機的渲染能力：圖由編輯器顯示，對話視窗只攜帶路徑與文字投影。
- 檔案後端以可註冊的介面描述（格式、投影、驗證方式各為後端自帶）；站別文件只引用介面、不內嵌特定格式的細節；本次至少註冊 draw.io 一個完整後端與一個最小示範後端以證明機制。

## Out of scope
- 游標級多人即時協作（共享游標、同時拖曳）與任何雲端儲存服務。
- VS Code 與桌面版以外的顯示面（瀏覽器版、自架版本）。
- WebSocket 即時橋接與 MCP server 整合。
- Penpot 或其他真實第二後端的完整實作（本次只寫註冊與選擇機制，加上一個最小的示範後端作為證明）。
- 架構文件嵌圖（ARCHITECTURE.md）等後續用途。
- 對話回合結束後由主機重新啟動 agent。
