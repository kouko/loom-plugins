# 修正五筆已確認的技能指令矛盾
originator: kouko
kind: engineering
needs-design: yes — 第五項需設計 session 證據、技能來源版本與多階段分析之間的讀取及引用契約，現有規格未涵蓋此來源核對與版本辨識流程。
status: confirmed 2026-10-23

## Problem
獨立複核確認五筆技能指令在特定情況下無法同時遵守。執行這些技能的 agent 可能重排已確認的需求、宣稱未發生的使用者確認、產生錯誤語言的標題、無法首次建立記憶庫，或被要求取得禁止讀取的資訊。目前只有文字契約與部分初始化行為的證據，沒有五項產品流程皆已重現故障的證據。

## Proposed outcome
這五處既有操作具有一致且可執行的指令，使用者能依原本的需求、語言與確認結果取得正確產物。

## Acceptance
1. 規格需求保留已確認驗收條件的順序與對應，同時遵守不可妥協原則。
2. 交接資訊如實區分已發生的產品行為確認與不適用該確認的工程變更。
3. dbt 模型的標題與其他描述欄位遵循使用者的工作語言。
4. 首次記錄可完成有效記憶庫的建立與記錄，既有有效內容不因初始化而被覆寫，損壞或舊格式的儲存區不被當成全新儲存區處理。
5. 技能分析能對照所選 session 的可觀察紀錄、目標技能原始檔與直接相關資源提出有來源依據的修改建議；能區分當時可證明的版本與目前版本，來源不可取得時明示限制。

## Constraints
- 使用者於 2026-10-23 回覆「開始吧」，確認上述五項並授權規格、計畫、實作與驗證；不包含發布或合併。
- 以獨立複核確認的五筆為範圍：F09、F10、F14、F27、F37。
- 遵守既有三類使用者決策、既有資料保護與 repository 測試／發布規則。

## Out of scope
- 前次複核撤回的三十筆與仍需釐清的五筆。
- 與上述修正無關的新功能、資料格式遷移與跨技能通用規則引擎。
- 直接套用回顧建議，或修改被分析的 session、技能及專案原始內容。
