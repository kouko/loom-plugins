## Problem
前一輪只有相容性與審查人數兩個流程完成統一建議，其餘命令仍混用不同位置與寫法。agent 必須自行辨認後續建議與操作要求；部分命令即使退出碼為零，也可能尚未同步或無法確認結果，單靠退出碼不足以判斷接下來能做什麼。

## Proposed outcome
這輪完成全部十六個 CLI 子命令的下一步建議一致性，讓 agent 能在各命令適用的輸出介面找到清楚、與實際結果相符的建議，保留原判定與協定，並以一次完整交付與整體驗收確認完成。

## Acceptance
1. 全部十六個子命令及其必要模式均有可核對的建議行為與驗證證據；清楚列明機器協定特例，不以僅完成盤點或任意標為不適用冒稱完成遷移。
2. 一般 CLI 的拒絕、錯誤及需要後續處理的結果能以統一標籤提供與原因相符的建議；尚未完成或無法確認的結果不因退出碼為零而被當成成功，未知修復保持未知，無必要後續操作時不編造建議。
3. 既有五個 JSON 命令可用一致的可選欄位取得建議；同時具有文字與 JSON 輸出的命令不維護互相矛盾的建議，原有必要欄位及既有下一步欄位保持相容。
4. 建議的有無或內容不改變原判定、退出碼、審查政策或必要授權，不觸發自動執行、重試、文字備援或繞過宿主信任與結果查證。
5. help、進度、hook、CI、setup 輸出及清理後的工作目錄交接保持原用途與協定相容；統一建議不新增對使用者既有資料的寫入或刪除副作用。
6. help 與流程說明符合實作，獨立 dogfood 涵蓋每個命令適用的正常、拒絕／錯誤及特殊模式；完整測試與獨立審查通過，清楚揭露模擬、未實測宿主與遠端操作的界線。

## Constraints
- 使用者要求：「可以一口氣做完全部嗎？」本輪以全部十六個命令完成後一次交付與驗收，取代繼續每兩個命令一批交付的提案。
- 沿用使用者已確認的 `Suggested next step:` 文字標籤與 `suggested_next` JSON 欄位名稱，不重問命名。
- 建議不構成執行、發布、合併或宿主信任授權。
- 保留現有 worktree、既有證據與使用者工作。
- 不以欄位或文案統一本身宣稱 agent 成功率、速度、成本或 token 改善。

## Out of scope
- 替原先沒有 JSON 模式的命令新增 JSON 模式，或強制所有輸出改用同一 JSON 結構。
- 可直接執行的操作清單、通用執行器、自動修復、重試或全面故障恢復框架。
- 改變業務判定、發布／合併授權、宿主信任政策或清理的授權界線。
- 真實使用者資料遷移、已安裝 plugin 更新及付費外部模型呼叫。
