## Problem
上一輪實測已證明指定的命令搭配預先準備的有效審查輸入可以完成驗證，但操作目標與輸入由主代理提供，尚未證明首次使用的代理能自行找到命令、準備輸入並修正錯誤。命令概要與詳細資料要求目前分散在工具說明及操作指引中，代理是否能在不依賴作者補充的情況下完成任務，仍缺乏實際證據。

## Proposed outcome
讓首次使用的代理能依隨附的操作資訊，完成既有驗證與發布相關 CLI 任務，並在輸入不合格或工作受阻時辨識原因與可行的下一步。

## Acceptance
1. 未參與開發的代理能在沒有作者提供命令答案或預製完整輸入的情況下，依隨附說明找到適用命令，並以提供的真實必要資料準備可接受的輸入，完成本次涵蓋的既有任務。
2. 對可由呼叫端修正的輸入錯誤，代理能依工具回覆與隨附說明辨識問題並完成修正，不必閱讀工具實作或向作者詢問。
3. 代理能從實際結果正確區分任務完成、仍在等待、被阻擋與結果無法確認，不將進度、格式有效或部分成功當成整體完成。
4. 既有合法呼叫、結果讀取、退出狀態及授權與獨立驗證條件保持相容；操作便利性不以省略證據或放寬判定取得。
5. 保留首次操作與修正過程的實際紀錄，明確區分已驗證與未驗證的命令及環境，不以受控測試推論跨宿主或整體時間、token 效益。

## Constraints
- 沿用目前保留的 worktree 進行下一輪，不刪除或重建該目錄。
- 延續逐步整理 CLI 的方向，保留既有授權、驗證、驗收與失敗阻擋條件。
- 不把代理自行準備輸入解釋為可自行編造審查結論或補造授權。

## Out of scope
- 全面重寫 Python 工具或遷移整體工具協定。
- 新增正式資料轉換工具。
- 模型分派政策、使用者決策點與宿主安裝機制的變更。
- 長任務排程、自動重試及跨宿主完整相容性認證。
