# 避免 Loom 在可以續行時過早停止

## Problem
Loom 在已取得繼續工作所需的結果、且沒有必須等待使用者的決定或其他明定阻礙時，仍可能只回報接下來要做什麼就結束回合。使用者必須額外說「請繼續」才能讓工作往前。2026-10-22 的 Claude Code 紀錄已確認收尾審查中有這種情況；其他站的交接文字也有同類風險，但尚未逐一證實。另一種停頓是把可由既有決定、專案證據、實測或適用的外部資料回答的技術選擇交給使用者，要求不必要的確認。

## Proposed outcome
Loom 在達到可續行條件後，agent 自行執行已明定的必要動作；進度回報不會取代執行。遇到重大選擇時，agent 讓使用者看見後果，但先查可用證據並自行處理可查證的技術判斷；只有尚未確定的使用者結果偏好或授權才要求使用者選擇。

## Acceptance
1. 在本站已取得必要結果、下一個動作已明定且沒有合法停止條件時，agent 不需使用者再說「請繼續」就會執行該動作；只回報進度不算完成。
2. 在本站已完成、下一站已有明定入口且沒有合法停止條件時，agent 不需使用者再說「請繼續」就會啟動下一站。
3. 對於可由既有決定、專案證據、實測或適用的外部資料判斷的選擇，agent 先查證並記錄理由；「以後難替換」、「影響品質上限」或「有三項以上取捨」本身不會使 agent 停下來要求使用者選方案。
4. 當不同做法會實質改變使用者要的結果，且查證後仍無法從既有決定推得偏好，或行動需要尚未取得的明確授權時，agent 才請使用者決定；在等待時繼續不依賴答案的工作。
5. 對於重大選擇，使用者能看見與自身相關的後果，即使 agent 不需請使用者選方案；需要使用者確認成果、取得授權或遇到其他正當停止條件時，agent 仍依現有規則處理。

## Constraints
- 以既有站點和選擇指引的小幅修改為基礎，用實際執行驗證；不增加審查者、checker 規則或新的使用者決策點。
- 保留現有審查、驗證、使用者驗收、合法停止條件與外部審查重試授權要求。
- 不把外部研究視為使用者偏好或行動授權；既有的使用者決定優先於通用做法。

## Out of scope
- Claude Code 的 API、用量、登入或 host 執行環境故障。
- 9 月 19 日已處理的缺件時站間循環問題。
- 取消 Loom 的三個既有確認點，或取消對費用、資料與不可逆行動的授權要求。
