# 發布與合併時的審查證明驗證不依賴測試語言的工具與當下的工作目錄

status: confirmed 2026-10-23

## Problem
在 Go 專案使用 Loom 的開發者，找漏洞測試若用「整個套件加上只跑一個測試」的寫法，最終驗證會接受並產生審查證明；但發布時若所在環境無法執行 Go（例如沙盒讓 Go 的快取資料夾不能寫入，或找不到 `go`），同一份證明會被判成「證明過期」，PR 上寫出錯誤的狀態（reading-list-summarize-scraper #19、#20，2026-10-23）。同一段驗證讀測試檔時讀的是目前所在的版本，而不是正在被驗證的版本；Rust 的驗證讀的是磁碟上目前的 `Cargo.toml`，也不是被驗證版本裡的那份。後兩者目前沒有造成誤判，但在其他目錄或版本驗證時可能讀錯。

## Proposed outcome
驗證一份已產生的審查證明時，結果只取決於被驗證那個版本裡已 commit 的內容和證明本身，不取決於驗證所在的機器有沒有該語言的工具、也不取決於工作目錄當下的檔案。

## Acceptance
1. 在找不到 `go`、或 Go 快取資料夾不能寫入的環境，驗證一份以 Go 套件寫法產生的有效審查證明，結果是有效，不是過期。
2. 驗證時，Go 測試檔與同資料夾其他測試檔、以及 Rust 的 `Cargo.toml`，讀的都是被驗證那個版本裡的內容；工作目錄當下的內容和該版本不同時，結果不受影響。
3. Go 套件寫法下，指定測試不在指定檔案裡、或同資料夾另有測試檔宣告同名測試時，驗證仍不接受。
4. 現有可被接受的 Go 單檔寫法與 Rust 寫法仍產生有效的審查證明；repo 的完整 package suite 通過。

## Constraints
- 驗證仍不執行紀錄裡的測試程式；最終驗證仍須實際執行並成功。
- 審查證明的格式不變，既有證明照樣可驗證。

## Out of scope
- 最終驗證時確認找漏洞測試已併入完整測試套件的那段檢查（它在無法執行 Go 時本來就放行）。
- 其他語言測試指令的接受規則。
