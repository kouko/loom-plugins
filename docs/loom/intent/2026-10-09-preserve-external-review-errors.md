# 保留外部審查失敗原因
originator: kouko
kind: engineering
needs-design: no — 現有外部審查規格已定義失敗結果，此變更不新增介面或跨物件流程
status: confirmed 2026-10-09

## Problem
外部 coding agent 在正式審查時若失敗，使用者有時只會看到空白的退出碼，無法辨認是額度限制還是其他問題，也無法據此決定何時重試。目前只能再執行一次，才可能取得具體錯誤，增加時間與用量。

## Proposed outcome
外部審查失敗時，Loom 能在已有可信錯誤資訊的情況下回報可判讀的原因，同時明確保留該次審查未完成的狀態。

## Acceptance
1. 外部審查程序失敗且回傳可判讀的錯誤時，使用者能看到具體原因，而不是只有空白的退出碼。
2. 外部審查程序失敗且沒有可判讀的錯誤時，使用者能看出原因仍未知；失敗的執行不會被計為完成的獨立審查。
3. 現有成功審查仍能回傳原有結果，且不揭露與失敗原因無關的審查材料或敏感資訊。

## Constraints
- 保留外部審查現有的授權、資料傳送、模型及 effort 選擇規則。
- 修正目前支援的外部 CLI 執行路徑，不引入新的付費服務。

## Out of scope
- 更改 Claude 帳戶額度或保證外部服務可用。
- 自動切換模型、供應商或無限次重試。
