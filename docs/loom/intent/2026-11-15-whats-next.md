## Problem
kouko 在不同專案的開發對話中反覆詢問建議的下一步。目前以一般提示詞取得建議，歷史案例出現建議偏離專案目標、依據未核實的現況，以及同意建議後仍停留在重複確認的情況。既有研究支持需要一致的判斷原則，但尚未證明新增 skill 能改善效果。

## Proposed outcome
提供獨立的 whats-next skill，依目前目標、進度、證據與限制推薦值得採取的下一步，以首選及必要替代方案協助決定方向，並在需要重新判斷時支援 agent 主動使用。

## Acceptance
1. 明確呼叫或自然語言詢問下一步時，能取得符合目前目標及限制的具體首選，包含推薦依據與預期得到的結果；不把未知現況當成事實。
2. 重要取捨或未定偏好影響選擇時，提供必要替代方案及其適用條件；沒有重要替代方案時不湊選項，目標完成且無合理後續時可以建議停止。
3. agent 在工作受阻或新證據使方向需要重新判斷時可以主動使用；已有明確計畫且正常推進時，不因這個 skill 反覆中斷工作或要求選擇。
4. 建議不擴張既有授權；已獲授權的未完成工作不因額外的通用確認而停住，需要另行授權的行動仍交回原有流程處理。
5. 針對自然問法、主動使用與不應使用的情境，以及建議品質與授權邊界，提供可重現的行為驗證與普通回答的比較結果；未測得的觸發可靠度或平台效果不宣稱已成立。

## Constraints
- user-decided — 使用獨立 skill，名稱為 whats-next；採用「首選＋必要替代方案」。
- 保留本次使用中的 worktree，不因交付或合併刪除。
- 保留既有專案目標、使用者修正、限制與授權；研究中的原始對話不因開發或發佈而公開。
- 觸發與輸出品質分開驗證；局部或模擬結果不等同於已安裝平台的整體效果。

## Out of scope
- 每回合背景呼叫、終端建議按鈕、跨專案排程與持久任務佇列。
- 修改 recap-state 的既有用途，或讓建議自動取得新任務、費用、資料外傳或合併的授權。
- 安裝或更新本機各 host 的 plugin 副本。
