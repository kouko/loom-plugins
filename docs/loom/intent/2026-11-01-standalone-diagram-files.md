# 獨立使用互動圖表與指定外部圖檔

## Problem
需要討論與編輯圖表的人，有時尚未進入 Loom 變更流程，或已有放在其他位置的圖檔。目前只能先建立變更紀錄，才能產生或更新圖表；這讓獨立討論與既有圖檔的使用不方便。

## Proposed outcome
互動圖表工具可獨立使用；每次準備編輯既有外部圖檔時，都先詢問使用者要不要在專案內建立副本。使用者可選擇編輯副本或直接編輯原檔。Loom 新建圖檔與副本仍遵守固定存放規則。

## Acceptance
1. 沒有 Loom 變更紀錄時，使用者仍可建立 draw.io 圖表並指定保存位置。
2. 每次準備編輯既有外部圖檔時，工具會先詢問使用者要不要在專案內建立副本；回答前不開始編輯或複製。
3. 使用者選擇直接編輯原檔時，可在編輯後更新文字投影與檢查結果；選擇先建立副本時，原檔保持不變。
4. 在 Loom 流程中，經同意建立的副本與文字投影保存在該次變更的圖表資料夾。
5. 在 Loom 變更流程內新建的圖表仍保存在該次變更的圖表資料夾；未經明確選擇，不會改寫外部原檔。
6. 工具指引能清楚區分獨立使用與 Loom 變更內使用。

## Constraints
- user-decided — Loom 新建的變更圖檔、副本與相關檔案留在 `docs/loom/<change-id>/` 內；使用者針對外部原檔明確選擇直接編輯時，可依其意願在原位置編輯。
- user-decided — 獨立使用與軟體開發中的 Loom 討論都必須適用。
- user-decided — 每次準備編輯既有外部圖檔時，先詢問使用者要不要複製到專案內；答覆前不編輯也不複製。
- user-decided — 對話中使用「先在專案內建立副本」等自然說法，並告知實際保存位置。
- existing principle — 使用者既有資料不得在未經確認時被改寫、刪除或傳送。

## Value case
使用者是需要以圖表與 agent 討論的人；目前的替代方式是先建立 Loom 變更或自行管理圖檔。使用者希望在 PR #125 釋出後立即處理，且本次不取代或延後其他原定工作。GO — 已確認的兩種使用情境都受到目前的位置限制影響。

## Out of scope
- 自動同步編輯器與圖檔，不需存檔就更新投影。
- 搬移既有圖檔的原始位置。
- 改變其他 Loom 文件的存放位置。
