# 與 agent 協作編輯 draw.io 圖表以溝通規格與介面設計
originator: kouko
kind: engineering
needs-design: yes — .drawio 圖檔是使用者直接閱讀與編輯的檔案介面，且協作循環（agent 產圖、使用者手改、agent 讀回）是多狀態行為，現有規格未涵蓋
status: open

## Problem
規格與介面設計的討論只能用文字往返：使用者無法直接畫出或修改圖面，對話視窗也顯示不了圖形（Mermaid 在終端機顯示成原始碼），agent 對畫面布局與流程的理解常需要多輪文字修正，而且討論成果無法累積成一份可編輯的圖檔。受影響的是以 loom 進行開發的使用者本人；後果是溝通慢、誤解要反覆澄清。

## Proposed outcome
使用者與 agent 共用同一份 draw.io 圖檔溝通規格與介面設計：agent 產生與更新圖，使用者的編輯器不用重新開檔就看到更新，使用者也能手動編輯同一張圖讓 agent 讀回；圖檔隨變更存放在 git 存放庫內，並可被機械檢查驗證。

## Acceptance
1. 使用者以 VS Code 的 Draw.io 擴充開啟 agent 產生的圖檔後，agent 更新同一檔案，開著的圖不重新開檔即顯示新內容（測試前先存檔或開啟自動存檔）。
2. 使用者在圖上手動做一項修改並存檔後，agent 讀同一檔案能正確複述該項修改。
3. 規格引用的介面流程圖附有文字投影（節點與連線清單）；兩者不一致時，機械檢查失敗並指出差異。
4. 內容損壞或不符合約定格式的圖檔會被機械檢查拒絕，訊息指出問題檔案。
5. 依存放庫文件，在乾淨環境裝妥前置工具後，第 1、2 條的協作循環可以重現。
6. 使用者以本機 draw.io 桌面版開啟同一圖檔時，agent 更新後：開啟自動存檔的設定下圖自動同步；未開啟時出現「檔案已修改」提示，點擊後圖顯示新內容。

## Constraints
- 圖檔必須存放在 git 存放庫內、隨變更一起審查；不得只存在雲端服務。
- 顯示與編輯面同時支援 VS Code 的 Draw.io 擴充與本機 draw.io 桌面版：前者無聲即時合併；後者在開啟自動存檔時無聲同步，否則以一鍵同步提示運作。
- 不依賴特定對話主機的渲染能力：圖由編輯器顯示，對話視窗只攜帶路徑與文字投影。

## Out of scope
- 游標級多人即時協作（共享游標、同時拖曳）與任何雲端儲存服務。
- VS Code 與桌面版以外的顯示面（瀏覽器版、自架版本）。
- WebSocket 即時橋接與 MCP server 整合（待本循環證明價值後再議）。
- 架構文件嵌圖（ARCHITECTURE.md）等後續用途。
