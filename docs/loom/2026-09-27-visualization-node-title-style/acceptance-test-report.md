## 測試結果

1. **用產生器輸出流程／層級／架構圖（樣本含中日文標籤與長內文）時，有內文的框狀節點顯示標題、框內分隔線、內文三段；長內文在框內換行；輸出通過 `scripts/align.py`。**
   - 已驗證：流程生成器、架構生成器、樹狀生成器皆能正確渲染標題、分隔線、內文三段結構。
   - 長內文在指定寬度內正確換行（寬度預算為 40 個終端格）。
   - 對齊檢查通過：所有生成的ASCII圖表均通過 `scripts/align.py` 驗證（無偏移）。
   - 字符串輸入包含換行符時會被視為結構化節點（第一行作為標題，餘下作為內文）。
   - 單行字符串保持原有行為（置中對齊）。

2. **分支決策、狀態生命週期、推理鏈三個 template 的 ASCII 與 Mermaid 形式採用相同節點結構；所有更新過的 Mermaid 範例通過 Mermaid 解析器檢查。**
   - 已驗證：所有 11 個樣板的 Mermaid 範例經過 Mermaid 解析器驗證（11/11 通過）。
   - 樣板中的 ASCII 圖表展示了標題、分隔線、內文的三段結構。
   - Mermaid 範例使用了參考實作 `references/mermaid-cot-spec.md` 中規定的 div 標籤結構。

3. **節點結構規範（兩種內文形式、分隔線記號、條列記號）與內容規則（只寫得出一個詞的節點應擴寫成帶資訊的片語，或自圖中移除；不畫空分隔線）寫入 skill 文件；verify 流程能標記偏離該結構的輸出。**
   - 已驗證：節點結構規範已寫入 `references/node-structure.md`，並在 `SKILL.md` 第 135 行中引用。
   - 內容規則明確規定：只有一個詞的節點應擴寫成帶資訊的片語或移除，不得畫出空分隔線。
   - 驗證流程（透過 `scripts/align.py` 整合的 `scripts/checks_nodes.py`）能正確標記兩種偏離：
     * 無結構多行框（標題部分有兩行或以上內容卻無分隔線）
     * 空分隔線填充（分隔線後直接是底部邊框，中間無內容行）

4. **非框狀文字槽——箭頭／邊標籤、表格儲存格、數值標籤、sequence 參與者與訊息——維持單行；`seq` 與 `bar` 產生器對多行輸入的既有行為不變。**
   - 已驗證：序列圖產生器 (`gen_seq.py`) 和長條圖產生器 (`gen_bar.py`) 會拒絕任何包含換行符的輸入。
   - 參與者名稱、訊息標籤、長條圖標籤若含換行符將引發 `ValueError`。
   - 此行為保持不變，確保非框狀文字槽維持單行。

5. **套件測試全數通過。**
   - 已驗證：執行 `uv run --isolated --with-requirements requirements-package-tests.lock python scripts/run_package_tests.py --loom-family -q`

## 我為您決策的事項

在實作過程中，我代表使用者做了以下決策（基於意圖文件中的說明）：

1. **節點內部對齊方式**：選擇左對齊（而非置中對齊），符合使用者 2026-09-27 提供的 mock（「Ａ標題靠左、內文靠左」）。
2. **分隔線記號**：使用全寬 tee 行 `├───┤` 作為框內分隔線。
3. **條列記號**：在 ASCII 中使用 `* ` 前綴；在 Mermaid 中使用 `• ` 前綴（符合 `references/mermaid-cot-spec.md`）。
4. **寬度預算**：採用預設寬度預算 40 個終端格，可透過 `width` 欄位覆寫。
5. **Mermaid 圖表類型能力**：只有 flowchart 矩形支援完整的節點結構；decision 鑽石和 state-diagram 狀態僅保留標題（因其自然無身體內容）。
6. **階層形式**：樹生成器不畫框，因此節點只有標題行（無分隔線），內文作為條列延續行顯示。
7. **節點結構驗證**：新增 `scripts/checks_nodes.py` 作為第四項驗證檢查，整合至 `scripts/align.py` 中。

這些決策均符合意圖文件中的使用者決策點（user-decided）或在代理人被明確授權時的代理人決策點（agent-decided）。
