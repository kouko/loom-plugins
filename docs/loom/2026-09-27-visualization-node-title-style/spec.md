# Unified node text structure for loom-visualization — spec
intent: 2026-09-27-visualization-node-title-style@ef9582e
pre-build-review: not-required — no security, privacy, irreversible-data, public-contract or cross-system surface; the behaviour is fully pinned by the intent and the carried details, and the branch-end reviewer recomputes risk from the diff

## Requirements
REQ-1 — Structured nodes in generated diagrams
  WHEN a flow or architecture generator receives a node that carries a title and a body — given explicitly as an object, or as a multi-line label whose first line is the title — the generator shall render that node as a title line, an in-box horizontal separator row, and left-aligned body lines that wrap inside the box interior, and the whole output shall pass the skill's alignment check; the hierarchy form, which draws no boxes, shall carry a node's body as bulleted continuation lines under its label → Acceptance #1
REQ-2 — Templates adopt the node structure
  The branching-decision, state-lifecycle and reasoning-chain templates shall show the node structure in their ASCII forms and adopt it in their Mermaid forms where the diagram type renders node bodies, and every updated Mermaid example shall pass the repository's Mermaid parser check → Acceptance #2
REQ-3 — Node-structure rule written and mechanically flagged
  The skill shall document the node structure (two body forms, separator and bullet marks, left alignment) together with the content rule that a node with only one word to say is expanded into an informative phrase or removed from the diagram rather than drawn with an empty separator, and the skill's alignment verification shall flag a box whose interior carries multiple content lines without a separator row, or a separator row with no body after it → Acceptance #3
REQ-4 — Non-box text slots unchanged
  Arrow and edge labels, table cells, bar labels, sequence participants and sequence messages shall remain single-line, and the sequence and bar generators shall keep rejecting multi-line input → Acceptance #4
REQ-5 — Package suite green
  The repository package test suite shall pass with the change applied → Acceptance #5

## Design decision
- **Node input schema** — a step/node may stay a plain string (rendered as today: single-line, centered), or become `{"title": str, "body": [str, ...]}` (structured). A plain string containing `\n` is given the structured rendering: first line is the title, remaining lines the body, separator inserted — one multi-line semantics, no second format. `seq`/`bar` keep rejecting `\n`. `agent-decided` — the explicit object form is self-documenting in the JSON payload; the `\n` mapping keeps existing multi-line usage meaningful instead of adding a parallel syntax.
- **Separator and bullet marks (ASCII)** — the separator row is a full-width tee row `├───┤` spanning the box interior; body items are prefixed `* ` in the input and rendered as given. Verified clean against the ported seam/kink checks before this spec. `user-decided` — the user's 2026-09-27 mock (`│ TITLE │` / `├──────┤` / `│* Context A │`); the generator keeps its existing 1-cell interior padding, so body lines render `│ * item │` — the mock's unpadded left edge is normalised to match the title row (agent-decided, cosmetic).
- **Alignment** — title and body are left-aligned inside structured nodes (user-decided 2026-09-27, 「Ａ標題靠左、內文靠左」). Plain single-line labels keep the generator's existing centered rendering. `agent-decided` — the user pinned the structured form; the degenerate single-word box (which the content rule expects to be rare) keeps the existing convention, so no existing diagram changes silently.
- **Body wrapping** — the generator wraps long body lines width-aware (stdlib) at the diagram's width budget (new optional payload field, default fixed in the build), continuation lines flush with the body's left edge. `agent-decided` — the skill's own rule forbids hand-measuring CJK widths, so the generator must own wrapping; the intent requires wrapping inside the box rather than unbounded width.
- **Bullet marks (Mermaid)** — Mermaid structured nodes use `• ` bullets, matching the house convention `references/mermaid-cot-spec.md` already prescribes for its `<div style='text-align:left'>TITLE<br/>━━━━━━<br/>• …</div>` label shape, which the flowchart-based templates adopt as their Mermaid expression of the node structure. `agent-decided` — one Mermaid convention then serves chat templates and page mode; `•` is width-unsafe in terminal boxes (East-Asian Ambiguous), which is why ASCII uses `* ` — the two marks each follow their medium's constraint, and the CoT spec file itself is not edited (intent Out of scope).
- **Per-type Mermaid capability** — flowchart rectangles carry the div structure; decision diamonds and state-diagram states stay title-only (the container rule makes a title-only node conforming: no body, no separator). Any body syntax attempted in other diagram types must pass the parser check or is not shipped. `agent-decided` — a diamond holds a question and a state holds a name; neither has a natural body, and the container rule is what makes that a decision rather than an omission.
- **Hierarchy form** — the tree generator draws no boxes, so its nodes gain no separator: title is the label line, body is `* `-prefixed continuation lines in the input (the generator already renders continuation lines). This is the spec's reading of Acceptance #1's hierarchy mention, bounded by scope A (user-decided 2026-09-27: only boxed nodes carry the full three-segment structure). `agent-decided` — template 07's own guidance rejects boxed hierarchies; continuation lines carry body inside the tree idiom.
- **Node-structure check joins the alignment oracle** — a fourth check (`scripts/checks_nodes.py`) wired into `scripts/align.py` flags: a box interior with two or more content lines and no separator row (a multi-line box that skipped the structure), and a separator row with no body line after it (the empty-separator padding failure). Tests live in `loom-workflow/tests/loom-visualization/`; the mechanism ledger (`docs/loom/evidence/mechanisms.yaml`) is updated per PRINCIPLES.md non-negotiable 4. `agent-decided` — intent Acceptance #3 requires the verify flow to flag deviations mechanically; a test-only validator would leave hand-drawn runtime output unverified, since the skill points agents at `align.py`.
- **Docs home** — the node structure and the content rule live in one new reference (`references/node-structure.md`); `SKILL.md` and the touched templates point at it; the SKILL.md failure-mode list gains the empty-separator and unstructured-multi-line traps. `agent-decided` — a single home for the rule; SKILL.md stays under its token cap.
- **Compatibility scope** — only the loom-visualization copy of the scripts changes; upstream `ascii-graph-toolkit` is untouched (intent Out of scope). Both plugin manifests and `CHANGELOG.md` take a minor bump in the same change (skill guidance and generator behaviour change), README version strings sync. `agent-decided` — repo versioning rule.

## Alternatives considered
- Mandatory three-segment box for every node, body empty if needed — rejected: the measured padding distortion recorded in `mermaid-cot-spec.md` (writers inflate content to fill a printed quota); the user chose container + content rule instead.
- Centered title/body in structured nodes — rejected: user chose left alignment (mock); centered bullets lose their left-edge alignment.
- Agent pre-wraps body lines in the JSON input — rejected: forces hand CJK width measurement, which the skill forbids.
- One bullet mark everywhere — rejected in both directions: `•` is East-Asian Ambiguous and width-unsafe in terminal boxes; `*` in Mermaid would break the CoT house convention for no gain.
- Boxed nodes for the tree form when a node carries body — rejected: contradicts template 07's guidance that the tree form is the shorter hierarchy idiom; continuation lines carry body without boxes.
- Put the node-structure rule only in SKILL.md — rejected: token cap; only in templates — rejected: no single home; a dedicated reference with pointers wins.
- Keep the structure check as a test-only validator — rejected: the runtime verify step (`align.py`) is what hand-drawn output passes through, so the deviation must be flaggable there.
