## 我替你決定的

- **把這條檢查寫成「前後不一致」的補充說明，不另開一個新的審查項目**（主流程的決定）— 這樣 reviewer 的審查項目清單和既有測試都不用動。代價是：想單獨統計「方向寫反」被抓到幾次時，要從「前後不一致」的發現裡再挑出來。
- **不加關卡標記，也不加新的自動測試**（主流程的決定）— 這條檢查完全由 LLM reviewer 審查時執行，沒有固定測試守著它的措辭。代價是：日後有人改寫這段規範本身時，只有 closing review 的 LLM reviewer 會讀到，不會有測試變紅。
- **loom-design 和 loom-workflow 沒有內容變更也一起升版號**（主流程的決定）— 三個一起升，讓更新時整組一起拿到。
- **試驗怎麼設計是我決定的** — 每份 diff 只請兩位 reviewer；寫反的那句剛好和別處沒改的文字矛盾（這種情況原本的審查規則也可能抓到）；沒有另外拿「沒加這段規範」的舊版做對照，所以這次試驗不能說明新規範多抓了多少，只能說明 reviewer 有照新規範逐句比對，而且兩種情況都判對。「寫反了但別處沒有任何矛盾」的更難情況沒有試。
