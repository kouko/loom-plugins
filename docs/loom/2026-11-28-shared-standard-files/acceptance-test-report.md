## 我替你決定的事

- **哪些規則搬進標準檔、哪些留在審查文件** — 實作時決定：規則本身搬進標準檔，審查者「怎麼跑測試、怎麼打分、問題多嚴重」的做法留在審查文件。這次修正又把五條原本留在審查文件、其實是寫測試時該遵守的規則（例如「修一個問題最多加一個測試」）搬進測試標準。之後若想再調整分界，要再改一次兩邊的指標和對應測試。
- **兩句「測試要能失敗」併成一句** — 修正時決定：寫的人原本讀「邏輯改了也不會失敗的測試不算測試」，審的人讀「不能因它宣稱測的行為而失敗的測試算問題」，現在只留後者。我判定這不算放寬或收緊：兩句都在禁止同一種測試，後者只是把「哪種改變」講得更具體。若你認為前者範圍更廣，要把它加回測試標準那一節。
- **「測試的測試」的例外** — 修正時決定：絕對禁止之外，明寫一個例外，就是釘住一句文字的測試必須附的自我驗證小測試。我判定這不算放寬：搬移前這種小測試本來就是規則要求的，以前兩條規則並存但沒寫明誰優先，現在寫明了。若你要的是連這種小測試都不准，就要同時改「釘住文字的測試」那條規則。
- **既有的「規劃時的遺漏要怎麼判」那一段留在審查文件** — 那段是有登記的自動檢查位置，搬走會讓檢查找不到它，所以沒動。
