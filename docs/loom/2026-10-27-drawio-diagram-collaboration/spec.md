# 與 agent 協作編輯 draw.io 圖表以溝通規格與介面設計 — spec
intent: 2026-10-27-drawio-diagram-collaboration@c7eefed91792fc863b7751a83e2cb6d655404571
pre-build-review: required — this change adds a diagram collaboration channel to the loom contract package consumed by three plugins; it modifies write-spec SKILL.md, adds a reference file, a check script, and a diagram convention used in repository documents

## Requirements
REQ-1 — Agent writes diagram, VS Code shows it instantly
  WHEN the agent writes or updates a .drawio file in the change's diagrams/ folder while the user has the same file open in VS Code's Draw.io Integration editor, the diagram shall reflect the new content without the user reopening the file, provided the VS Code text buffer is clean (saved or autosave enabled) → Acceptance #1

REQ-2 — User hand-edits diagram, agent reads it back
  WHEN the user makes a manual edit to the open diagram in VS Code's Draw.io Integration editor or the draw.io desktop app and saves the file, the agent reading the same .drawio file shall restate the change correctly → Acceptance #2

REQ-3 — Diagram carries a text projection and the check enforces consistency
  The specification shall reference each diagram with a text projection (node and edge list) committed alongside the .drawio file; the mechanical check script shall fail when the projection disagrees with the diagram, naming the difference → Acceptance #3

REQ-4 — Malformed or non-conforming diagrams are rejected
  IF a .drawio file is malformed (cannot be parsed as valid mxfile XML) or does not follow the uncompressed format convention, THEN the mechanical check script shall fail and name the offending file → Acceptance #4

REQ-5 — Clean-environment reproducibility
  Following the repository documentation, a clean environment with prerequisites installed shall reproduce the collaboration loop of Acceptance #1 and #2 → Acceptance #5

REQ-6 — Desktop app sync behaviour documented and working
  WHEN the same .drawio file is open in the draw.io desktop app and autosave is enabled, the diagram shall synchronize without a click; when autosave is disabled, the app shall show the "file modified" prompt whose click displays the new content → Acceptance #6

## Design decision
- Extend loom-design:write-spec with a "Diagram collaboration" capability (reference file `references/diagram-collaboration.md`, check script `scripts/check_diagram.py`, and a short SKILL.md section) rather than a new skill — avoids increasing the skill count (already at the 23/23 budget) and a `budget-exception` CHANGELOG line; the capability is invoked only inside the flow, so it is not "standalone" per manifest — agent-decided
- Diagram files live at `docs/loom/<change-id>/diagrams/<slug>.drawio` with an accompanying text projection at `diagrams/<slug>.projection.md` — a simple convention, not a new artifact_type glob (artifact_types is reserved and not yet consumed by the checker; declaring one would add a mechanism and need an eval) — agent-decided
- Diagram format: uncompressed pretty-printed XML (mxfile or bare mxGraphModel) as per draw.io AI generation rules (never compressed, cells 0 and 1 mandatory, unique IDs, no XML comments); the projection is regenerated by `check_diagram.py` from the XML and compared byte-for-byte to the committed `.projection.md` — agent-decided
- `check_diagram.py` lives in the skill's `scripts/` folder; it validates against the official `mxfile.xsd`, regenerates the projection, and diffs it; it also exports to PNG via the draw.io CLI (if available) for CI headless verification — agent-decided
- write-spec SKILL.md gains a "Diagram collaboration" section: when a spec references a diagram, the UI flows section shall include the diagram path and the projection table; the `check_diagram.py` run is added to the station hand-off checklist — agent-decided
- No browser/embed view, no WebSocket bridge, no MCP server integration this change — deferred per intent Out of scope — agent-decided

## Alternatives considered
- Extend loom-visualization instead: rejected — its boundary is chat output (tables, ASCII, Mermaid in chat); the repo explicitly defers repository-document diagrams to the artifact-owning skill (loom-design:write-spec) per its SKILL.md boundary
- New counted skill: rejected — would either require a `budget-exception` CHANGELOG line (net mechanism count increase) or misdeclare as `standalone: true` to dodge the budget, which is dishonest for a flow-internal capability
- MCP server integration (lgazo/drawio-mcp-server / abossard/drawio-mcp): deferred — external daemon braids concerns, requires a running service, and the file-on-disk loop is sufficient for the stated acceptance; re-trigger: when the loop proves valuable and agent-in-diagram annotation is demanded
- Mermaid-only with no file: rejected — the intent's core is a hand-editable file both parties can open; Mermaid in chat renders as raw code in terminals

## UI flows
### Surface: diagram file in VS Code Draw.io Integration editor
- Empty → no diagram in `diagrams/` yet; user opens a non-existent path → VS Code shows empty editor; way out: agent runs the diagram generation task
- In progress → agent writes .drawio; the file on disk updates; the open webview merges the new XML and renders instantly; way out: wait for merge complete
- Error → malformed XML or non-conforming format; `check_diagram.py` fails with file path and message; way out: user or agent fixes the file and re-runs the check
- Success → diagram displays the intended flow; text projection matches; user can hand-edit

### Surface: diagram file in draw.io desktop app
- Empty → no diagram in `diagrams/` yet; user opens a non-existent path → app shows blank canvas; way out: agent runs the diagram generation task
- In progress → agent writes .drawio; within ~5 s the app detects the change; if autosave is enabled the diagram auto-merges silently; if disabled the status bar shows "The file has been modified. Click here to synchronize."; way out: user clicks status bar
- Error → stale file written (older copy of itself); modal "The file has been modified. Overwrite or Synchronize?"; Synchronize adopts the disk version; way out: user chooses Synchronize (or avoids stale writes by not editing the same file simultaneously in two editors)
- Success → diagram displays the intended flow; text projection matches; user can hand-edit

### Path walk (single graph)
spec (write-spec) produces diagram file → user opens in editor → edits → saves → agent reads → next spec/planning step. One forward edge (spec → diagram), one back edge (user edit → agent reads). No orphan surface, no dead end.
