## 我代你決定的事項

- **先改善兩個長任務** — 先處理發佈與最終驗證，保留原有結果輸出及結束代碼，讓既有呼叫方式繼續可用；擴大到其他命令時仍須逐一驗證相容性。
- **進度與結果分開** — 進度寫入獨立訊息輸出（stderr）；發佈等待每滿 60 秒後，在下一次查詢時提醒，最終驗證則在每個階段開始及結束時回報。單一子程序執行中沒有定時提醒；若要補上，需要額外設計與驗證。
- **只省掉確定不需要的收錄檢查** — 先排除不符合資格的檔案，保留所有既有判定規則；沒有加入快取或放寬驗證，之後若要再加速仍需另行量測。
- **不加入正式轉換工具** — 候選方法雖能提早發現部分錯誤，仍未證明減少操作，也增加維護負擔，因此保留現行方式；重新考慮時需補上真實使用成本的量測。
- **其餘介面改善留待後續** — 更完整的說明、可區分原因的錯誤分類，以及更多機器可讀輸出，本次都未擴充；後續需要各自設計並確認不影響既有使用方式。
- **驗收環境** — 使用乾淨來源副本及既有鎖定依賴快取，避免改動已安裝環境；這驗證來源工具可載入，沒有驗證各宿主的安裝更新。
