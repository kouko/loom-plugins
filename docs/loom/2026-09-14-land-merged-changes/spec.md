# Land a reviewed Loom change: wait for CI, merge, sync, and clean up — spec
intent: 2026-09-14-land-merged-changes@3869e1a8
pre-build-review: required — the change deletes branches and worktrees (irreversible on local state) and changes the publication hook's merge contract

## Requirements
REQ-1 — Merge without a typed command
  WHEN the agent runs `loom_checker.py land --accepted-by <name>` from a change worktree whose attestation validates and whose open PR head equals HEAD, the checker shall squash-merge that PR itself, so the maintainer types no git or GitHub command → Acceptance #1
REQ-2 — Refuse on failing checks or unmergeable PR
  IF any check of the PR fails, is cancelled, or requires action, or GitHub reports the PR as conflicting, blocked, behind, unstable, or draft THEN `land` shall not merge, shall exit 1, and shall name each failing check or the reported merge state → Acceptance #2
REQ-3 — Acceptance is the authorization
  IF `land` is run without `--accepted-by <name>`, or with a name that is neither the intent's `originator` nor the name in its `publication:` line, THEN it shall merge nothing, exit 1, and report that blind-run acceptance is not recorded; WHEN it merges, the squash commit body shall carry the line `Accepted-by: <name> <YYYY-MM-DD>` → Acceptance #3
REQ-4 — PR title and body preserved
  WHEN `land` merges, the squash commit on the trunk shall carry the PR title as its subject and the PR body text in its message, and `land` shall read the merged commit back and report `BLOCK land.verify` if either is missing → Acceptance #4
REQ-5 — Trunk fast-forward only
  WHEN a merge is verified, `land` shall fast-forward the local trunk to `origin/<trunk>`, which contains the merge commit, or report `trunk not updated: <reason>` without force-updating, rebasing, or merging into the trunk → Acceptance #5
REQ-6 — Change branch and worktree removed
  WHEN a merge is verified and every cleanup precondition holds, `land` shall remove the change's worktree, local branch, and remote branch, and report each removal → Acceptance #6
REQ-7 — Cleanup refusals
  IF the PR is not merged on GitHub, the worktree has modified or untracked files, the worktree holds ignored files outside the regenerable set, or the local or remote branch tip differs from the merged PR's head commit THEN cleanup shall remove nothing for that change and report `BLOCK land.cleanup: <reason>` → Acceptance #7
REQ-8 — No collateral removal
  The `land` command shall select worktrees and branches only by exact equality with the change's branch name and PR head commit, so that other worktrees and branches, including dirty ones with similar names, are unchanged → Acceptance #8
REQ-9 — Named cleanup alone
  WHEN the agent runs `land --cleanup <branch>` for a branch whose PR is merged, the checker shall perform the REQ-6 removals under the REQ-7 and REQ-8 refusals without merging anything → Acceptance #9
REQ-10 — Sweep lists, then removes on confirmation
  WHEN the agent runs `land --sweep`, the checker shall list each merged change it would remove and each it skips with a reason, remove nothing, and print a confirmation token; WHEN run with `--sweep --confirm <token>` and the recomputed list yields the same token, it shall clean up each listed change under the REQ-7 and REQ-8 refusals, continuing past a refused change; IF the token differs THEN it shall remove nothing and report that the list changed → Acceptance #10
REQ-11 — Hand-typed merge refused
  WHEN the text of a Bash tool command contains the words `gh` (or a path ending in `/gh`), `pr`, and `merge` in that order, after joining backslash-newlines and splitting on quoting and shell punctuation, the installed publication hook shall block it with `BLOCK push.merge` naming `loom_checker.py land` as the merge path, including commands that only mention those words → Acceptance #11

## Design decision
- **Entry point** — `loom-code/scripts/loom_checker/command_handlers/land.py` exporting `cmd_land`, registered in `COMMANDS` and the module docstring of `loom_checker.py` beside `publish`. Three forms: `land --accepted-by <name>`, `land --cleanup <branch>`, `land --sweep [--confirm <token>]`. `user-decided` (intent Constraints, 2026-09-14) for the placement; `agent-decided` for the flag shape — it mirrors `publish --confirm-authorized`.
- **Rule ids** — four new ids, kept few to limit the mechanism population: `land.merge` (every refusal before a merge: acceptance, attestation, PR identity, checks, merge state, merge not performed), `land.verify` (merged commit lacks title or body), `land.cleanup` (every cleanup refusal, including a changed sweep list), and `push.merge` (hook refusal). Each is registered with its description in `loom_checker/rules.py` `RULES`, added to `EXPECTED_RULE_IDS` in `test_loom_checker_cli.py`, the `land` area added to that file's area allow-list, and each registered in `docs/loom/evidence/mechanisms.yaml` with a regression eval. `agent-decided` — the refusal reason text carries the distinction a separate id would; four ids instead of nine keeps the budget small.
- **Execution safety reused from publish** — every git and gh call uses `publish.py`'s trusted-executable resolution, pinned `PATH`, sanitized environment, and repository identity from `github_repo_from_origin`. Calls go through a land-owned seam `run_land_external(argv, timeout)` built on the same `subprocess.run` shape as `run_publish_external`: 30 seconds for reads, 300 seconds for `gh pr merge`, `git fetch`, `git push`, and `git worktree remove`. `agent-decided` — the existing 30-second cap can kill a merge or a large worktree deletion midway; tests fake the new seam exactly as `ExternalCalls` fakes publish's.
- **Acceptance record** — `--accepted-by <name>` is the acknowledgement that the maintainer accepted the result at decision point ③; Ship passes it only after that explicit answer. `land` recomputes what it can: the name must equal the intent's `originator` or the name in its `publication: automatic — authorized <date> by <name>` line. When `docs/loom/<change-id>/blind-run-report.md` is committed at HEAD, the record also cites it: `Accepted-by: <name> <date> (blind-run-report <blob sha7>)`. The record is written into the squash commit body, not into a committed branch file. `user-decided` (acceptance authorizes merge, 2026-09-14). `agent-decided` for the carrier — any committed-file change invalidates the attestation digest. Remaining trust, disclosed at decision point ③: `land` cannot observe the conversation, so it relies on the agent relaying the maintainer's yes, the same trust `publish --confirm-authorized` already carries.
- **Merge preconditions, in order** — (1) acceptance as above; (2) attestation validates at live HEAD via the existing `_cmd_push --head HEAD --require-live-head` path; (3) exactly one open PR for the current branch against the default base, found with publish's `gh api …/pulls?state=open&head=<owner>:<branch>` query, whose `head.sha` equals HEAD; (4) all checks of the PR observed with `gh pr checks <n> --json name,state,bucket` (not only required ones), polling every 10 seconds while any is pending, with publish's registration wait and 60-minute pending limit; any `fail` or `cancel` bucket, or a state requiring action, refuses; (5) `gh pr view <n> --json mergeable,mergeStateStatus` is `MERGEABLE` with a state other than `BLOCKED`, `DIRTY`, `BEHIND`, `UNSTABLE`, or `DRAFT`, re-reading while `UNKNOWN` for up to 60 seconds. Every refusal is `BLOCK land.merge: <reason>`. `agent-decided` — this repository requires only one of its four checks, so observing required checks alone would merge a PR whose other checks fail, which intent Acceptance #2 forbids.
- **Merge command** — title and body come from `gh pr view <n> --json title,body`; the body plus a blank line and the Accepted-by line is written to a mode-0600 file inside a `tempfile.TemporaryDirectory`, as `cmd_publish` does. The command is `gh pr merge <n> --squash --match-head-commit <HEAD> --subject "<title> (#<n>)" --body-file <file>`; never `--admin`, `--auto`, or `--delete-branch`. When the command exits non-zero or times out, `land` reads `gh pr view <n> --json state,mergeCommit`: `MERGED` continues to verification with `Merged PR #<n>`; anything else reports `BLOCK land.merge: merge not performed: <gh stderr>`. `agent-decided` — `--match-head-commit` makes GitHub refuse if anyone pushed after the check; `--body-file` removes the editable dialog that dropped PR bodies (docs/loom/memory/squash-dialog-can-drop-entire-pr-body.md), and this repository's squash default is commit messages, not the PR body.
- **Verification** — `gh pr view <n> --json state,mergeCommit` must report `MERGED`; `git fetch origin <trunk>` then `git cat-file commit <mergeCommit>` must have a first message line that starts with the PR title and must contain the PR body, both with whitespace runs normalized. A verification failure stops before trunk sync and cleanup, exits 1, and states that the PR is merged. `agent-decided` — the merge cannot be undone by refusing, so the report must not claim nothing happened.
- **Anchor directories** — the *main worktree* is the parent of `git rev-parse --git-common-dir`, equal to the first `worktree` entry of `git worktree list --porcelain`. The *trunk checkout* is the worktree whose porcelain `branch` field equals `refs/heads/<trunk>`, when one exists. All `git -C` calls that must outlive the removed worktree, and the process's own change of directory, use the trunk checkout when it exists and the main worktree otherwise. `agent-decided` — a named directory always exists, so no step depends on the worktree being deleted.
- **Trunk sync** — if the trunk checkout exists and `git status --porcelain` is empty, run `git -C <it> merge --ff-only origin/<trunk>`; if it is dirty, skip with `trunk not updated: <path> has local changes`; if no worktree has the trunk checked out, run `git fetch origin <trunk>:<trunk>`, which git refuses when not a fast-forward. A skipped sync does not stop cleanup. `agent-decided` — the trunk is shared by other work; only a fast-forward is safe without asking.
- **Cleanup preconditions, per change** — PR state `MERGED`; local branch tip, when the branch exists, equals the PR `headRefOid`; remote branch tip, when it exists after `git fetch --prune origin`, equals `headRefOid`; the worktree, when one exists, has no modified or untracked entry and every ignored file in `git status --porcelain --ignored=traditional --untracked-files=all` is either named `.DS_Store`, ends in `.pyc` (including inside `__pycache__`), or lies inside a `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.venv`, or `node_modules` directory; `git ls-files -v` shows no skip-worktree or assume-unchanged entry (a hidden edit that `git worktree remove` would delete); when the branch is checked out in the main worktree rather than a linked worktree, that checkout must be clean and no other worktree may have the trunk checked out. Every refusal is `BLOCK land.cleanup: <reason>`. `agent-decided` — a scratch probe on 2026-09-14 showed `git worktree remove` without `--force` silently deletes a worktree containing an ignored `.env` while refusing untracked files, so ignored files need their own guard; the listed names are regenerable caches, and the reviewer observed only such names in this repository's worktrees.
- **Which worktree path** — `land --accepted-by` removes the invoking worktree's own `git rev-parse --show-toplevel` path, and uses the porcelain listing only to confirm that path's `branch` field is `refs/heads/<branch>`. `--cleanup` and `--sweep` have no invoking path, so they look the path up by exact equality of the porcelain `branch` field with `refs/heads/<branch>`, print the absolute path before removing, and remove it with no `--force` and no suppressed stderr. `agent-decided` — this reconciles the intent Constraint ("by exact known path, never selected by filtering a listing") with the user-decided sweep, which cannot exist without enumerating: the recorded incident failed through four mistakes — substring matching over whole listing lines that include branch names, `--force`, suppressed stderr, and a filter where names were known — and exact field equality, a printed path, a kept git refusal, and visible errors remove each of them.
- **Cleanup actions, in order** — (1) if the process's working directory is inside the worktree, change to the anchor directory; remove with `git -C <anchor> worktree remove <path>`; when the branch is in the main worktree instead, `git -C <main worktree> switch <trunk>`; (2) delete the local branch with `git update-ref -d refs/heads/<branch> <headRefOid>`, which git refuses if the tip moved, then `git config --remove-section branch.<branch>`, ignoring an absent section; (3) delete the remote branch with `git push --force-with-lease=refs/heads/<branch>:<headRefOid> origin :refs/heads/<branch>`, which the server refuses if the tip moved; an already absent remote branch reports `remote branch already deleted`. A removal that times out or fails midway stops that change and reports `BLOCK land.cleanup: worktree removal interrupted at <path>; run git worktree prune after checking the directory`. Output ends with `next: cd '<anchor absolute path>'` whenever a worktree was removed. `agent-decided` — compare-and-delete on both refs closes the race between check and removal; the worktree goes first so the branch is no longer checked out when its ref is deleted (docs/loom/memory/a-worktree-cleanup-by-pattern-match-destroys-other-peoples-work.md).
- **Named cleanup** — `--cleanup <branch>` resolves the PR with `gh pr list --state merged --head <branch> --json number,headRefOid,mergedAt`; zero results refuse with `BLOCK land.cleanup: no merged PR for <branch>`; several results choose the one whose `headRefOid` equals an existing local or remote tip, and refuse otherwise. `agent-decided` — a reused branch name must never inherit an older PR's merged state.
- **Sweep** — after `git fetch --prune origin`, candidates are local branches and `origin/*` remote branches other than the trunk; one `gh pr list --state merged --json number,headRefName,headRefOid --limit 1000` call supplies merged PRs; a branch is listed only when a PR's `headRefName` equals it and `headRefOid` equals its local or remote tip. The branch of the invoking worktree is skipped with `skip <branch> — current working directory`. Each candidate runs the cleanup preconditions read-only and prints `remove <branch> <sha7> — <worktree <path> | main worktree <path> switches to <trunk> | no worktree>, <local | no local>, <remote | no remote>` or `skip <branch> — <reason>`. The token is the first 12 hex digits of SHA-256 over the sorted `remove` lines. With `--confirm`, the list is recomputed; a different token removes nothing and reports `BLOCK land.cleanup: the sweep list differs from the one confirmed; run land --sweep again`. If the PR list returns 1000 entries, the output states that older merged PRs were not examined. `user-decided` (list first, remove after confirmation, 2026-09-14); `agent-decided` for the token — it proves the removal set is the one shown. The agent passes `--confirm` only after the maintainer answers yes to the printed list; like acceptance, that relay is agent-attested.
- **Hook** — `command_handlers/push.py` hook mode blocks, before any repository-selection logic, every command whose text — after joining backslash-newlines — contains the words `gh` (or a path ending in `/gh`), `pr`, `merge` in that order, including the absolute-`cd` form allowed today, nested shell forms, prefix words with options, and shell grammar such as `( … )`, with `BLOCK push.merge: merge through loom_checker.py land --accepted-by <name>`. It fails closed: a command that only mentions those words, such as an `echo`, is refused too. `agent-decided` — the closing-review adversary found structured parsing let `(…)`, `bash -lc`, and optioned prefixes through; a textual rule has no such gaps, and its false positives cost a reworded command, not a bypass. The Codex and Antigravity hooks call the same `push --hook`, so they inherit the block. `agent-decided` — `land`'s own subprocess calls are not Bash tool calls and are never seen by the hook, so one merge path remains.
- **Ship station text** — `loom-code/skills/ship/SKILL.md` replaces the direct-merge section with: after all checks pass, present the result and blind-run report when one exists (decision point ③); on explicit acceptance run `cd '<absolute worktree root>' && python3 <loom-code>/scripts/loom_checker.py land --accepted-by <name>`; the agent's next Bash command starts with the `cd` printed on land's `next:` line; the Handoff no longer keeps the worktree and reports land's output. A short paragraph names `land --cleanup` and `land --sweep`, and says the sweep token is passed only after the maintainer answers yes to the printed list. Tests pinning the old merge text and behaviour (`test_ship_worktree_merge.py`, the merge cases in `test_loom_publish.py`, `test_publish_command_detection.py`, `test_codex_stale_hook.py`, `test_hooks_json.py`, `test_ship_station_text.py`) are updated to the new contract. `agent-decided`.
- **Release** — minor version bump in `loom-code/plugin.json`, `loom-code/.claude-plugin/plugin.json`, and `loom-code/.codex-plugin/plugin.json`, and one `loom-code/CHANGELOG.md` entry noting that direct `gh pr merge` is now refused, with one `budget-exception: <rule id> — <reason>` line per new rule id, each naming its eval. `agent-decided` — repository convention and the mechanism budget check.

## Alternatives considered
- `gh pr merge --delete-branch` — rejected: deletes branches with no tip comparison, cannot delete a branch checked out in a worktree, and does not remove the worktree.
- GitHub auto-merge (`--auto`) — rejected: merge happens after the session ends, so verification, trunk sync and cleanup have no process to run in, and it depends on a repository setting.
- Gating on required checks only — rejected: in this repository three of four checks are not required.
- A new station or a separate skill — rejected by the maintainer in favour of a checker sub-command (intent Constraints).
- Recording acceptance in the intent or blind-run report file — rejected: any committed-file change invalidates the attestation and returns the change to Review.
- Requiring a committed blind-run report before merge — rejected: Review writes one only when an Acceptance line cannot be settled mechanically, so many reviewed changes have none.
- One rule id per refusal (nine ids) — rejected: each id is a counted mechanism needing its own budget exception, while the reason text already distinguishes refusals.
- `git branch -D` and `git push origin --delete` — rejected: neither compares the tip, so a push after the check could be deleted.
- `herdr worktree remove` — rejected: host-specific; Loom runs in repositories without herdr. herdr's own workspace metadata may keep a stale entry, which is disclosed, not handled.
- Removing worktrees with `--force` to get past ignored files — rejected: that is the failure recorded in the worktree-cleanup memory.
- Blocking the `gh api …/pulls/<n>/merge` REST form in the hook — not taken in this change: the intent names `gh pr merge`; the REST form is listed as a known limit in the PR.

## UI flows
Surface: the `land` checker command (read by the agent and quoted in the maintainer's report).

Land after acceptance:
- `land` without `--accepted-by`, or with a name that is not the intent's originator or publication authorizer → `BLOCK land.merge: blind-run acceptance not recorded; pass --accepted-by <name> after the maintainer accepts` on stderr, exit 1, nothing merged.
- checks still pending → prints `Waiting for checks on PR #<n>` once, then nothing until a terminal state (in progress).
- a check fails, is cancelled, or requires action → `BLOCK land.merge: check <name>: <state>` per such check, exit 1, nothing merged; the way out is to fix the change and publish again.
- PR conflicting, blocked, behind, unstable, or draft → `BLOCK land.merge: PR #<n> is <mergeStateStatus>`, exit 1, nothing merged; the way out is to update the branch and return to Review.
- PR head differs from HEAD, no open PR, or attestation invalid → `BLOCK land.merge: <reason>`, exit 1; the way out is to publish again or return to Review.
- merge command fails and GitHub shows the PR still open → `BLOCK land.merge: merge not performed: <gh message>`, exit 1; the way out is to rerun `land` after resolving the named cause.
- success → `Merged PR #<n> as <sha7>`, `Trunk <trunk> fast-forwarded to <sha7>` or `trunk not updated: <reason>`, `Removed worktree <path>`, `Deleted local branch <branch>`, `Deleted remote branch <branch>` (or `remote branch already deleted`), `next: cd '<anchor path>'`, exit 0. Removal of the worktree is irreversible: ignored cache directories inside it are deleted with it; any other ignored, modified, or untracked file makes cleanup refuse instead.
- merged but body missing → `Merged PR #<n> as <sha7>` then `BLOCK land.verify: squash commit lacks the PR body`, exit 1, no sync or cleanup; the PR stays merged.
- merged but a cleanup precondition fails → `Merged PR #<n> as <sha7>`, trunk line, then `BLOCK land.cleanup: <reason>`, exit 1, nothing removed; the way out is to resolve the named state and run `land --cleanup <branch>`.
- worktree removal interrupted → `BLOCK land.cleanup: worktree removal interrupted at <path>; run git worktree prune after checking the directory`, exit 1, branches kept.
- git refuses the removal and the directory is intact (for example a locked worktree) → `BLOCK land.cleanup: git refused to remove worktree <path>: <git's error line>`, exit 1, branches kept; git's own override or force hints are not repeated.

Named cleanup:
- `land --cleanup <branch>` with no merged PR → `BLOCK land.cleanup: no merged PR for <branch>`, exit 1.
- precondition fails → `BLOCK land.cleanup: <reason>` (for example `worktree <path> has untracked files`, `local branch tip <sha7> is not PR head <sha7>`, `trunk is checked out in <path>`), exit 1, nothing removed.
- success → `Worktree for <branch>: <path>`, then the removal lines and `next:` line above, exit 0; nothing is merged.

Sweep:
- `land --sweep` with nothing to clean → `No merged changes to clean up`, exit 0.
- `land --sweep` with candidates → one `remove …` or `skip …` line per branch, then `confirm with: land --sweep --confirm <token>`, exit 0, nothing removed.
- `land --sweep --confirm <token>`, list unchanged → per change the removal lines or `BLOCK land.cleanup: <branch>: <reason>`, then `next:` when any worktree was removed; exit 0 when all removed, 1 when any refused.
- `land --sweep --confirm <token>`, list changed → `BLOCK land.cleanup: the sweep list differs from the one confirmed; run land --sweep again`, exit 1, nothing removed.

Hand-typed merge:
- a Bash tool command containing `gh pr merge` → `BLOCK push.merge: merge through loom_checker.py land --accepted-by <name>`, the command does not run.

Paths: every refusal leaves state as it was, except the documented `Merged PR` lines and an interrupted worktree removal; rerunning `land --accepted-by` after a fix restarts from the preconditions; `land --cleanup <branch>` resumes a merged change whose cleanup refused.
