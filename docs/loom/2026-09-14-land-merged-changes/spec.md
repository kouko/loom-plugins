# Land a reviewed Loom change: wait for CI, merge, sync, and clean up — spec
intent: 2026-09-14-land-merged-changes@3869e1a8
pre-build-review: required — the change deletes branches and worktrees (irreversible on local state) and changes the publication hook's merge contract

## Requirements
REQ-1 — Merge without a typed command
  WHEN the agent runs `loom_checker.py land --accepted-by <name>` from a change worktree whose attestation validates and whose open PR head equals HEAD, the checker shall squash-merge that PR itself, so the maintainer types no git or GitHub command → Acceptance #1
REQ-2 — Refuse on failing checks or unmergeable PR
  IF a required check of the PR fails or is cancelled, or GitHub reports the PR as conflicting, blocked, or behind a required state THEN `land` shall not merge, shall exit 1, and shall name each failing check or the reported merge state → Acceptance #2
REQ-3 — Acceptance is the authorization
  IF `land` is run without `--accepted-by <name>` THEN it shall merge nothing, exit 1, and report `BLOCK land.acceptance`; WHEN it merges, the squash commit body shall carry the line `Accepted-by: <name> <YYYY-MM-DD>` → Acceptance #3
REQ-4 — PR title and body preserved
  WHEN `land` merges, the squash commit on the trunk shall carry the PR title as its subject and the PR body text in its message, and `land` shall read the merged commit back and report `BLOCK land.verify` if either is missing → Acceptance #4
REQ-5 — Trunk fast-forward only
  WHEN a merge is verified, `land` shall fast-forward the local trunk to the merge commit, or report `trunk not updated: <reason>` without force-updating, rebasing, or merging into the trunk → Acceptance #5
REQ-6 — Change branch and worktree removed
  WHEN a merge is verified and every cleanup precondition holds, `land` shall remove the change's worktree, local branch, and remote branch, and report each removal → Acceptance #6
REQ-7 — Cleanup refusals
  IF the PR is not merged on GitHub, the worktree has modified or untracked files, the worktree holds ignored files outside the regenerable set, or the local or remote branch tip differs from the merged PR's head commit THEN cleanup shall remove nothing for that change and report `BLOCK land.cleanup: <reason>` → Acceptance #7
REQ-8 — No collateral removal
  The `land` command shall select worktrees and branches only by exact equality with the change's branch name and PR head commit, so that other worktrees and branches, including dirty ones with similar names, are unchanged → Acceptance #8
REQ-9 — Named cleanup alone
  WHEN the agent runs `land --cleanup <branch>` for a branch whose PR is merged, the checker shall perform the REQ-6 removals under the REQ-7 and REQ-8 refusals without merging anything → Acceptance #9
REQ-10 — Sweep lists, then removes on confirmation
  WHEN the agent runs `land --sweep`, the checker shall list each merged change it would remove and each it skips with a reason, remove nothing, and print a confirmation token; WHEN run with `--sweep --confirm <token>` and the recomputed list yields the same token, it shall clean up each listed change under the REQ-7 and REQ-8 refusals, continuing past a refused change; IF the token differs THEN it shall remove nothing and report `BLOCK land.sweep-changed` → Acceptance #10
REQ-11 — Hand-typed merge refused
  WHEN a Bash tool command contains `gh pr merge` in any form, the installed publication hook shall block it and name `loom_checker.py land` as the merge path → Acceptance #11

## Design decision
- **Entry point** — `loom-code/scripts/loom_checker/command_handlers/land.py` exporting `cmd_land`, registered in `COMMANDS` and the module docstring of `loom_checker.py` beside `publish`. Three forms: `land --accepted-by <name> [--ci-timeout-minutes <n>]`, `land --cleanup <branch>`, `land --sweep [--confirm <token>]`. A new rule area `land` (`land.acceptance`, `land.attestation`, `land.pr`, `land.checks`, `land.mergeable`, `land.verify`, `land.cleanup`, `land.sweep-changed`) is added to the area allow-list in `test_loom_checker_cli.py`. `user-decided` (intent Constraints, 2026-09-14) for the placement; `agent-decided` for the flag shape — it mirrors `publish --confirm-authorized`.
- **Execution safety reused from publish** — every git and gh call goes through `publish.py`'s trusted-executable resolution, pinned `PATH`, sanitized environment, and `run_publish_external` seam; the repository identity comes from `github_repo_from_origin`. `agent-decided` — one hardened execution path, and the existing test seam (`ExternalCalls` fakes) applies unchanged.
- **Acceptance record** — `--accepted-by <name>` is the machine-checkable acknowledgement that the maintainer accepted the blind-run report at decision point ③; Ship passes it only after that explicit acceptance. The record is written into the squash commit body as `Accepted-by: <name> <date>`, not into a committed file on the branch. `user-decided` (acceptance authorizes merge, 2026-09-14); `agent-decided` for the carrier — any committed-file change invalidates the attestation digest, while the squash body is on the trunk permanently.
- **Merge preconditions, in order** — (1) `--accepted-by` present; (2) attestation validates at live HEAD via the existing `_cmd_push --head HEAD --require-live-head` path; (3) exactly one open PR for the current branch against the default base, found with the same `gh api …/pulls?state=open&head=<owner>:<branch>` query publish uses, whose `head.sha` equals HEAD; (4) required CI observed with publish's `_observe_required_ci` (terminal pass, or no required checks registered), default timeout 60 minutes; (5) `gh pr view --json mergeable,mergeStateStatus` is `MERGEABLE` and not `BLOCKED`/`DIRTY`/`BEHIND`, re-reading while `UNKNOWN` for up to 60 seconds. `agent-decided` — each step is a refusal the maintainer can read; checks are re-observed because a publication-only fix may have restarted CI.
- **Merge command** — `gh pr merge <n> --squash --match-head-commit <HEAD> --subject "<PR title> (#<n>)" --body-file <temp file: PR body, blank line, Accepted-by line>`. Never `--admin`, `--auto`, or `--delete-branch`. `agent-decided` — `--match-head-commit` makes GitHub refuse if anyone pushed after the check; `--body-file` removes the editable dialog that dropped PR bodies before (docs/loom/memory/squash-dialog-can-drop-entire-pr-body.md); branch deletion stays under land's own checks.
- **Verification** — `gh pr view <n> --json state,mergeCommit` must report `MERGED`; `git fetch origin <trunk>` then `git cat-file commit <mergeCommit>` must contain the PR title and the PR body with whitespace runs normalized. A verification failure stops before trunk sync and cleanup, exits 1, and states that the PR is merged. `agent-decided` — the merge cannot be undone by refusing, so the report must not claim nothing happened.
- **Trunk sync** — the trunk checkout is the worktree whose porcelain `branch` field equals `refs/heads/<trunk>`. If it exists and `git status --porcelain` is empty, run `git -C <it> merge --ff-only origin/<trunk>`; if it is dirty, skip with `trunk not updated: <path> has local changes`; if no worktree has the trunk checked out, run `git fetch origin <trunk>:<trunk>`, which git refuses when not a fast-forward. A skipped sync does not stop cleanup. `agent-decided` — the trunk is shared by other work; only a fast-forward is safe without asking.
- **Cleanup preconditions, per change** — PR state `MERGED`; local branch tip, when the branch exists, equals the PR `headRefOid`; remote branch tip, when it exists after `git fetch --prune origin`, equals `headRefOid`; the worktree, when one exists, has empty `git status --porcelain` and `git status --porcelain --ignored` lists only paths whose final component is one of `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.venv`, `node_modules`, `.DS_Store`, or ends in `.pyc`. `agent-decided` — a scratch probe on 2026-09-14 showed `git worktree remove` without `--force` deletes a worktree containing an ignored `.env` silently while refusing untracked files, so ignored files need their own guard; the listed names are regenerable caches.
- **Cleanup actions, in order** — (1) the worktree path is taken from `git worktree list --porcelain` by exact equality of its `branch` field with `refs/heads/<branch>` — never by substring, pattern, or path guess — and removed with `git -C <trunk checkout> worktree remove <path>` without `--force`; if the process's working directory is inside it, the process first changes to the trunk checkout and prints `working directory is now <path>`; if the branch is checked out in the main checkout instead of a linked worktree, that checkout is switched to the trunk when clean, otherwise cleanup refuses; (2) the local branch is deleted with `git update-ref -d refs/heads/<branch> <headRefOid>`, which git refuses if the tip moved; (3) the remote branch is deleted with `git push --force-with-lease=refs/heads/<branch>:<headRefOid> origin :refs/heads/<branch>`, which the server refuses if the tip moved; a remote branch already absent reports `remote branch already deleted`. `agent-decided` — compare-and-delete on both refs closes the race between check and removal; worktree first so the branch is no longer checked out when its ref is deleted (docs/loom/memory/a-worktree-cleanup-by-pattern-match-destroys-other-peoples-work.md).
- **Named cleanup** — `--cleanup <branch>` resolves the PR with `gh pr list --state merged --head <branch> --json number,headRefOid,mergedAt`; zero results refuse with `BLOCK land.cleanup: no merged PR for <branch>`; several results choose the one whose `headRefOid` equals an existing local or remote tip, and refuse otherwise. `agent-decided` — a reused branch name must never inherit an older PR's merged state.
- **Sweep** — after `git fetch --prune origin`, candidates are local branches and `origin/*` remote branches other than the trunk; one `gh pr list --state merged --json number,headRefName,headRefOid --limit 1000` call supplies merged PRs; a branch is listed only when a PR's `headRefName` equals it and `headRefOid` equals its local or remote tip. The branch of the invoking worktree is skipped with `skip: current working directory`. Each candidate runs the cleanup preconditions read-only and prints `remove <branch> — <worktree path | no worktree>, <local | no local>, <remote | no remote>` or `skip <branch> — <reason>`. The token is the first 12 hex digits of SHA-256 over the sorted `remove` lines including each head commit. With `--confirm`, the list is recomputed; a different token removes nothing. If the PR list returns 1000 entries, the output states that older merged PRs were not examined. `user-decided` (list first, remove after confirmation, 2026-09-14); `agent-decided` for the token — it proves the removal set is the one the maintainer saw.
- **Hook** — `command_handlers/push.py` hook mode blocks every command where `is_pr_merge_command` is true, including the absolute-`cd` form allowed today, with `BLOCK push.merge: merge through loom_checker.py land --accepted-by <name>`. The Codex and Antigravity hooks call the same `push --hook`, so they inherit the block. `agent-decided` — land's own subprocess calls are not Bash tool calls and are never seen by the hook, so one merge path remains.
- **Ship station text** — `loom-code/skills/ship/SKILL.md` replaces the direct-merge section with: after required CI passes, present the blind-run report (decision point ③); on explicit acceptance run `cd '<absolute worktree root>' && python3 <loom-code>/scripts/loom_checker.py land --accepted-by <name>`; the Handoff no longer keeps the worktree and reports land's output. A short paragraph names `land --cleanup` and `land --sweep` for merged changes left from earlier work. Tests pinning the old merge text (`test_ship_worktree_merge.py`, the merge cases in `test_loom_publish.py`, `test_ship_station_text.py`) are updated to the new contract. `agent-decided`.
- **Release** — `loom-code` minor version bump in both plugin manifests and one CHANGELOG entry noting that direct `gh pr merge` is now refused. `agent-decided` — repo convention.

## Alternatives considered
- `gh pr merge --delete-branch` — rejected: deletes branches with no tip comparison, cannot delete a branch checked out in a worktree, and does not remove the worktree.
- GitHub auto-merge (`--auto`) — rejected: merge happens after the session ends, so verification, trunk sync and cleanup have no process to run in, and it depends on a repository setting.
- A new station or a separate skill — rejected by the maintainer in favour of a checker sub-command (intent Constraints).
- Recording acceptance in the intent or blind-run report file — rejected: any committed-file change invalidates the attestation and returns the change to Review.
- `git branch -D` and `git push origin --delete` — rejected: neither compares the tip, so a push after the check could be deleted.
- `herdr worktree remove` — rejected: host-specific; Loom runs in repositories without herdr. herdr's own workspace metadata may keep a stale entry, which is disclosed, not handled.
- Removing worktrees with `--force` to get past ignored files — rejected: that is the failure recorded in the worktree-cleanup memory.
- Blocking the `gh api …/pulls/<n>/merge` REST form in the hook — not taken in this change: the intent names `gh pr merge`; the REST form is listed as a known limit in the PR.

## Current state evidence
- Forward: `loom-code/skills/ship/SKILL.md:157-175` — after publication the agent asks for separate merge authorization, issues `cd '<root>' && gh pr merge <number> --squash`, and keeps the worktree; `command_handlers/publish.py:236-320` (`_observe_required_ci`) already observes required CI after publication.
- Reverse: `loom-code/hooks/hooks.json:15-24` runs `loom_checker.py push --hook` on every Bash tool call; `rule_checks/push.py:183-195` (`is_pr_merge_command`) and `rule_checks/push.py:404-405` allow a merge only after an absolute `cd`; `command_handlers/push.py:108-122` then re-validates the attestation.
- Error: a bare `gh pr merge` fails with `BLOCK push.attestation: ambiguous repository selection` (`test_loom_publish.py:67-83`); the maintainer's global guard outside the repo denies `^gh pr merge` and `git branch -D`, which is why merges and cleanups were typed by hand (session history 2026-07-25 to 2026-09-14: 57 manual merges, 30 denied `git branch -D`).
- Data: `docs/loom/<change-id>/attestation.json` binds `content_digest` to the pre-merge HEAD (`loom_checker/attestation.py:25-95`); the change-id is derived from the attestation path, not the branch name (`publish.py:149-172`); no machine-readable record of blind-run acceptance exists today.
- Boundary: the change stops at `loom-code` (checker, hook, Ship text, tests, version); the maintainer's `~/dotfiles` guard and settings, worktree creation, stash handling, and PR comments are untouched.

## UI flows
Surface: the `land` checker command (read by the agent and quoted in the maintainer's report).

Land after acceptance:
- `land` without `--accepted-by` → `BLOCK land.acceptance: blind-run report acceptance not recorded; pass --accepted-by <name> after the maintainer accepts` on stderr, exit 1, nothing merged.
- `land --accepted-by kouko`, checks still pending → prints `Waiting for required CI on PR #<n>` once, then nothing until a terminal state (in progress).
- a required check fails → `BLOCK land.checks: <check name>: <state>` per failing check, exit 1, nothing merged; the way out is to fix the change and publish again.
- PR conflicts or is blocked → `BLOCK land.mergeable: PR #<n> is <mergeStateStatus>`, exit 1, nothing merged; the way out is to update the branch and return to Review.
- PR head differs from HEAD, or no open PR → `BLOCK land.pr: <reason>`, exit 1; the way out is to publish again.
- success → `Merged PR #<n> as <sha7>`, `Trunk <trunk> fast-forwarded to <sha7>` or `trunk not updated: <reason>`, `Removed worktree <path>`, `Deleted local branch <branch>`, `Deleted remote branch <branch>` (or `remote branch already deleted`), optionally `working directory is now <path>`, exit 0. Removal of the worktree is irreversible: ignored cache directories inside it are deleted with it; any other ignored, modified, or untracked file makes cleanup refuse instead.
- merged but body missing → `Merged PR #<n> as <sha7>` then `BLOCK land.verify: squash commit lacks the PR body`, exit 1, no sync or cleanup; the PR stays merged.
- merged but a cleanup precondition fails → `Merged PR #<n> as <sha7>`, trunk line, then `BLOCK land.cleanup: <reason>`, exit 1, nothing removed; the way out is to resolve the named state and run `land --cleanup <branch>`.

Named cleanup:
- `land --cleanup <branch>` with no merged PR → `BLOCK land.cleanup: no merged PR for <branch>`, exit 1.
- precondition fails → `BLOCK land.cleanup: <reason>` (for example `worktree <path> has untracked files`, `local branch tip <sha7> is not PR head <sha7>`), exit 1, nothing removed.
- success → the removal lines above, exit 0; nothing is merged.

Sweep:
- `land --sweep` with nothing to clean → `No merged changes to clean up`, exit 0.
- `land --sweep` with candidates → one `remove …` or `skip …` line per branch, then `confirm with: land --sweep --confirm <token>`, exit 0, nothing removed.
- `land --sweep --confirm <token>`, list unchanged → per change the removal lines or `BLOCK land.cleanup: <branch>: <reason>`; exit 0 when all removed, 1 when any refused.
- `land --sweep --confirm <token>`, list changed → `BLOCK land.sweep-changed: the list differs from the one confirmed; run land --sweep again`, exit 1, nothing removed.

Hand-typed merge:
- a Bash tool command containing `gh pr merge` → `BLOCK push.merge: merge through loom_checker.py land --accepted-by <name>`, the command does not run.

Paths: every refusal leaves state as it was except the documented `merged` lines; rerunning `land --accepted-by` after a fix restarts from the preconditions; `land --cleanup <branch>` resumes a merged change whose cleanup refused.
