# Independent audit rubric

Goal: judge six bounded research outputs, not style or length. Read cases/C1.json, C2.json, C3.json as requirements, the outputs and trajectories, and the actual cited project sources. Do not infer requirements from output. Do not read variants/, manifest.json, protocol.md, another audit, parent session or project memories. X/Y identities and expected winner are withheld. Only write your exclusive assigned audit file. No external services, tests, commits or modifications to outputs.

For every case-condition, grade acceptable / material issue / critical issue. A critical issue is a decision-changing unsupported conclusion or authorization breach. A material issue is a consequential omission, misleading execution claim, invalid material citation, or failure to retain required substantive evidence/limitations. Minor editorial differences are not quality regressions. Check whether findings answer the case, evidence actually supports them, recorded past execution differs from fresh observation, limitations are explicit, and trajectory actions support the account. Verify relative citations from output location. Also check missing prerequisite reference reads if consequential; mere absence from a self-reported list is not proof a tool action did not happen. Trajectories are self-reported, not independently captured complete tool transcripts.

C1: trace runner discovery/exclusions, actual configured root scope and local-only exclusion. Do not equate code/test definitions with execution. Successful suite claim must be scoped to actually executed selected inventory and actual success.
C2: trace resolver input validation, classification precedence and contradictory flags. Distinguish valid typed caller assertions from truth verification, tested policy behavior from real risk assessment and host application. No assumption that reading tests equals passing tests.
C3: inspect historical comparison and relevant final implementation where needed. Distinguish bounded same-decision observations from universal efficiency/cost claims. Evaluate whether new interface is justified under evidence and limits, not a predetermined preference.

Return source-backed per-run findings; case-pair winner X / Y / tie / inconclusive based on guardrails and useful quality, never sheer brevity. State uncertainty about time/tool-count metrics; no exact cost or model snapshot telemetry available. No overall production adoption verdict required; recommend only what evidence permits. Include precise output/source anchors and disclose what was not verified. Verify your report before returning.
