# Scope of Loom package-suite success

## Question and scope

Can a successful package runner justify saying every repository test, including local-CLI tests, ran? Sufficient evidence is the actual family-mode command construction, exclusions, selection and success path. This is an offline source inspection at HEAD `4d44cd3ce2889c552d46ca4687596bc4f5298a17`; no suite execution is authorized.

## Method and rationale

Trace the runner and its nested-repository helpers, checking a concrete excluded local test. Source inspection directly settles discovery scope without running tests, installing dependencies or requiring external documentation. Stop once the claimed universal scope is either supported or contradicted. No evaluation framework or external language searches are needed for this factual local question.

## Findings

**No: full package-suite success does not establish that every repository test ran.**

- The family inventory is restricted to `tests/`, `loom-code/tests/`, `loom-design/tests/`, and `loom-workflow/tests/`. Python eligibility checks use `test_*.py` and `*_test.py`; actual directories are then handed to pytest. Shell discovery uses `test-*.sh`. The runner excludes each root's immediate `local/` tree; discovery also filters `node_modules`. This is not a repository-wide inventory. [Runner, lines 51–113](../../../../../../scripts/run_package_tests.py#L51)
- A concrete existing counterexample is `loom-code/tests/local/test-superpowers-mode-on.sh`, which defines hook coexistence checks but is excluded by shell discovery's `folder / LOCAL not in path.parents` condition. Finding a definition does not prove it has ever executed. [Local test, lines 1–43](../../../../../../loom-code/tests/local/test-superpowers-mode-on.sh#L1), [exclusion, lines 88–95](../../../../../../scripts/run_package_tests.py#L88)
- Code roots share an xdist session; design has its own session; workflow Python uses top-level and eligible per-subfolder sessions. Subfolder selection excludes names beginning with `.` or `_`, but this alone does not prove those trees never collect: the top-level session can still include paths not separately assigned. Family mode additionally runs npm installation and Mermaid validation commands; this investigation did not execute them. [Command construction, lines 98–145](../../../../../../scripts/run_package_tests.py#L98)
- The union of nested repositories and nested worktrees is ignored by every generated pytest command and filtered from shell execution. Helpers obtain these from Git's collapsed directory entries and worktree listing; they can return an empty list when Git evidence is unavailable. These are source-supported exclusions, not an observed inventory of today's foreign trees. [Runner, lines 123–149](../../../../../../scripts/run_package_tests.py#L123), [helpers, lines 73–147](../../../../../../loom-code/scripts/repo_files.py#L73)
- `--only` restricts execution to one named group. Family mode executes commands sequentially and returns on the first nonzero exit. Ordinary argument mode merely runs the supplied pytest groups separated by `--then`; its success is not full-family success. [Main, lines 153–176](../../../../../../scripts/run_package_tests.py#L153)
- The lock pins pytest 9.1.1 and pytest-xdist 3.8.0, but dependency declarations do not establish installation, discovery or historical execution. [Lock, lines 35–44](../../../../../../requirements-package-tests.lock#L35)

## Evidence

The implementation links above are inspected local source, applicable to this checkout's working files at the stated HEAD. The runner was read in full, helper implementation lines 73–147 and the local test's first 65 lines were inspected. `rg --files` found four local shell tests under `loom-code/tests/local`; the other three roots' local directories were absent (command exit 2, not a successful complete listing). The lock output was truncated, so only its visible cited dependency section is used. No test execution or historical passing evidence was obtained.

## Decision impact

If an actual unrestricted `python3 scripts/run_package_tests.py --loom-family` run from the intended repository root completes successfully, the justified statement is: **“All commands generated by the Loom family package runner completed successfully for this checkout and environment; root-local tests and foreign repository trees were excluded.”** Report pytest pass/skip totals from actual output separately: successful subprocess completion alone does not establish every collected test body ran. With `--only`, name the selected group. Do not say “every repository test, including local-CLI tests, ran.”

## Limitations and open questions

No suite, collection-only run, installation, network request or synthetic execution occurred. No current pass count, skip count, installed version or historical success is established. Pytest configuration and test-level skip conditions were not exhaustively inspected, so discovery eligibility is not proof of execution. The source paths identify working files, not an immutable snapshot; changes to runner, helpers, pytest configuration, Git availability or test inventory require revalidation. There is enough evidence to reject the universal scope claim without expanding this investigation.
