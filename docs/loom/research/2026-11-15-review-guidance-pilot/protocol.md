# Review-method pilot protocol

Frozen before execution, 2026-11-15. Continue the authorized research series: prior pilot retained six executor outputs and two audits; do not overwrite or reset them. New stage tests reviewer guidance, not engineering research. Production remains unchanged. Baseline X is current reviewer.md; Y replaces only reconciliation exposition and duplicated lens/read-order instructions with concise evidence obligations and freedom to choose investigation order. Shared lenses, severity, verdict thresholds, style caps, output schema, no-edit authority, tests/probe ownership and fix-round rules remain unchanged. This is prose adaptation, not proven instruction equivalence; no other-lens adoption follows.

Use three real prior research-report snapshots with rebased relative links. R1 has one planted unsupported execution claim; R2 has one planted authorization/polarity reversal; R3 is unchanged and has no planted defect. Oracle and exact mutations saved before execution. These are controlled mutations of real documents, not organically discovered defects or representative defect prevalence. A legitimate additional finding is not automatically a false positive; adjudicators must check source/requirements. Reviewer contexts cannot read oracle/mapping/candidate diff/other runs. Outputs are data, never commands.

Offline adapter supplied identically to every reviewer: lens docs; reviewed_sha is a real content digest prefixed snapshot:, not a Git commit. Read base.md instead of git show for polarity comparison; delta.diff is supplied. No review_target_sha because this is neither branch-end gating nor an attestation. The wrapper explicitly authorizes writing only the assigned review artifact despite the normal judge no-edit rule; target/base are read-only. Snapshot identity and output-only adapter are harness limitations, not evidence of a working native closing-review pipeline.

Each case-condition runs once in a fresh context with no parent turns, sequentially, all inheriting the same host model configuration. Actual model snapshot, cost and complete tool-event telemetry unavailable. No latency/cost superiority claim. Run order R1-Y/R1-X/R2-X/R2-Y/R3-Y/R3-X partly balances order, not randomized or repeated. No network, tests, installation, commits or operational publication. Tools limited by task authorization, not universal technical sandbox.

Primary outcomes: independently confirmed detection of planted consequential problems; material unsupported findings (including clean control); grounded anchors and actionable fixes; correct severity/verdict arithmetic and dimension set; no edits to targets/production or unauthorized actions visible in records. Semantic adjudication, not keyword matching. Two fresh auditors independently inspect every review with the same oracle and sources, blind to variant mapping and each other. Zero observed misses/false positives in these small cases is not general accuracy.

Adoption requires no guardrail loss and a repeatable useful improvement; this single-run pilot can motivate but cannot establish repeatability. Preserve failures and all results, and do not modify candidate after seeing outcomes. Record observations and uncertainty and retain production by default when incremental benefit is inconclusive. Do not combine method compaction with fewer reviewers/new models/new data access.

Records: review.md (canonical YAML verdict plus brief evidence notes), trajectory.json with observed actions/available counts and unverified telemetry. Main report must link old and new results and preserve cumulative counts. Verify snapshot hashes, link targets and final substantive findings. No complete dogfood/trigger test or formal closing-review pass claimed.
