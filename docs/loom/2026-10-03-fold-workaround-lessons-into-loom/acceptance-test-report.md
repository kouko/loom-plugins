## 我替你決定的

- **第 1 條在檢查工具本身驗，而不是跑一整輪 closing review** — 我直接呼叫 closing review 和審查證據檢查兩處共用的那個判斷，用 19 種指令逐一比對新舊版。理由是這樣才能同時看到「該接受的接受了」和「該拒絕的仍拒絕」；完整跑一輪要另開一個變更。若你要求端到端，代價是再多跑一輪 closing review。
- **第 2 條的範圍比你寫的寬** — 指引是對「所有什麼都沒打破的攻擊」都要求指名既有測試，不只限於需要實際執行程式的變更。我判為 works，因為它涵蓋了你要的情況；若你只想在需要時才這樣做，要再改一次指引文字。
- **Plugin 沒有實際裝進 Claude Code 試** — 我用 repo 自己規定的驗證方式（完整 suite 加 manifest 檢查）確認變更能在乾淨副本載入；指引文字類的條目是讀 agent 實際會讀到的原文。
