## 我替你決定的事

本輪沒有新的代理自行決定 — 這是合併後的重新驗收，修正（探測程式的路徑白名單、
四條規則的登記、版號同步）都已在修正 commit 裡，我逐條重測。上一輪的決定仍然有效：

- **v1 憑證向下相容、v2 憑證缺欄位即失敗** — 舊版憑證沒有新欄位時跳過檢查；新版憑證
  缺少被測或被審查 commit 任一就失敗。若放寬，破口會回到原狀。
- **判定欄的字彙由檢查器固定** — 報告每一列的判定必須是模板固定的四個詞；寫別的東西
  會被擋下並點名條號。這是機制能讀懂報告的最低代價。
- **只排除必要的證據檔案** — 功能內容比較排除驗收憑證、驗收報告與證據資料夾的檔案；
  探測程式放在證據資料夾的 probes 子目錄、算功能內容，其他檔案（包括 intent）的變動
  也算功能內容，會被當成漂移擋下。
- **intent 確認記錄排除狀態行** — 計算確認版本時拿掉狀態行與記錄行本身，避免記錄變成
  對自己的雜湊；沒有確認記錄或 intent 尚未確認時就不比對，所以本變更這種確認於機制
  存在之前的 intent 不會被誤擋。

## 我不確定你要不要的事

- **邊界測試任務只認標頭後面的字** — 風險條目指名 `W1-01`、而任務標題寫
  「Boundary test for the risky path」時，檢查仍會說任務不存在；只有在任務標頭後面
  （`after: none` 之後）再寫一次「boundary test」才會通過。plan 模板把這個寫法寫成
  約定，照模板寫不會踩到，但照標題寫會誤擋。要不要放寬由你決定。
- **變更目錄裡還留著一份暫時的審查輸入** — 文件現在說審查輸入是暫時的、放在 repo
  之外，但這個變更自己的目錄裡（從更早的輪次）還有一份，裡面的判定和憑證重複。
  發布前檢查不讀它，所以不會漂移，但它和文件的說法不一致；要不要清掉由你決定。
