## 我代你決定的事

- **沿用現有記錄格式** — 讓既有的「沿用設定」與「主機預設但未驗證」狀態直接回報結果，沒有另造通用格式；日後若換格式，需一併修改產生與讀取記錄的各端，處理相容性。
- **分開檢查指定設定與實際觀測** — 明確指定的模型與推理強度必須完整且合法，工具看不到的實際值仍可留未知；外部審查仍須保留明確設定與執行證據。若改成容許不完整指定，需重新設計防止非法設定混入的檢查。
- **分開保留過去事實與下次保證** — 每次完成都回報原執行狀態；重試則重新檢查當下主機是否保證沿用設定，不宣稱未知後端必然相同。若日後要求證明實際模型一致，需主機提供額外可觀測證據。
- **保留停止界線** — 未知基準不推測升級，也不擴大重試次數；審查成功發現缺陷與審查本身失敗分開計數。若放寬，需重新確認成本與停止條件並補驗證。
- **分開確認內容與判斷需求變更** — 既有內容檢查只證明確認過的文字相符；是否能開始新審查階段，仍須說明實質義務差異，沿用現有文件記錄，不新增集中計數帳本。若日後要自動判斷或集中管理，需另設機制與驗證，不能靠重新確認就清零。
- **只交付來源版本更新** — 兩個受影響外掛各升一次次版號並同步發版資料，這次沒有更新已安裝副本；日後若更改交付範圍，需重做相應版本與安裝驗證。
- **實測形式** — 使用隔離專案、事先標示的錯誤注入與模擬需求對話；這能檢查流程決策，不代表已觀測實際後端設定或驗證其他主機。改成其他主機實測需要另做驗證。
