## 對你既有的資料做了什麼

這次變更改寫了既有的 Loom 外掛指示、執行程式、測試與說明檔；舊版本仍可從 Git 歷史讀取，沒有另存備份。驗收只在乾淨副本測試，沒有將你的專案內容送到外部廠商。

## 我替你決定的事

- **共用入口與原有標準** — 我選擇讓程式碼、計畫與決策審查共用外部執行入口，但各自沿用原本的評判標準；日後改變入口須同步檢查三類審查。
- **保留原審查者** — 我選擇在正式審查至少保留一位原審查者，外部審查另占一席；選用外部審查時可能增加一次執行與費用。
- **外部選擇的紀錄** — 我選擇在有計畫時寫入計畫，略過計畫時寫入意圖，讓審查人數與結果檢查仍能核對；日後若改記錄位置，這些檢查也須同步修改。
- **授權來源分開保存** — 我選擇將原請求與審查目標留在執行紀錄中，不把選擇紀錄當成逐字授權；日後若要合併兩者，須重新檢查授權判定。
- **模型選擇** — 我選擇在執行當下取得候選模型，並依選定模型的廠商判斷是否獨立；Antigravity 可列出多家模型。日後若改用固定名單，須負責維護其時效與可用性。
- **失敗處理** — 我選擇讓短程驗證及正式審查使用同一組指定模型與 effort；失敗便停止而不自動換用預設模型。日後若要改成自動替換，須重新界定使用者授權的範圍。
- **額外技能額度** — 我選擇為共用外部入口記錄一項技能數量例外，讓既有檢查仍能核對；若日後刪除這個入口，還須一併移除例外。
- **實機驗證範圍** — 我只執行不傳送資料的本機測試；計畫雖已記錄選用 Claude，這輪仍未測到真實帳號與模型的行為。
