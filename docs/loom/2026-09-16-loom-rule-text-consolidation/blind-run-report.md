## What you asked for, one line at a time

### 1. Every contradiction and stale reference the audit lists (its items C1–C19) is gone: re-checking each listed item against the new text finds it removed or consistent with what the scripts and stations actually do.
- **How I tried it**: 在舊版與新版兩份副本裡，逐條用審計指出的原句去搜尋，19 條全做。會影響流程的 7 條（流程說明文件的步驟順序、找不到的攻擊清單、規格審查交錯站、沒人讀的問題欄位、發布站合併小問題、實作者「一律派出」少了例外、「讀不到另一個外掛」的前提），我把新舊兩邊的前後文都讀了。
- **What happened**:
  - 流程說明文件：舊版把「對抗者」排在審查站派出、還有「完整車道／小車道」和已不存在的審查紀錄檔。新版的步驟表改成「所有任務完成後由建置站派對抗者 → 交給審查 → 盲跑 → 兩位讀者 → 發布」，舊的車道說法和壞連結都沒了。
  - 攻擊清單：舊版有兩處叫對抗者去讀一份不存在的清單；新版任何規則檔都搜不到這份清單。
  - 規格審查：舊版叫寫規格的人把規格交給「收尾審查站」做規格審查，但那個站只在建置完成後才能跑。新版兩處都改成寫規格的人自己派一位獨立審查者，並寫明審查基準是規格那次提交的前一版。收尾審查站的說明仍是「建置完成後才用」，兩邊不再衝突。
  - 實作者：新版寫成「除非跳過清單列了實作者，否則每個實作任務一律派出」，和建置站實際行為一致。
  - 發布站合併小問題：審查者說明裡這句已刪，剩下的寫法與評審標準的「發布站可以批次修字」一致。
  - 其餘：沒人讀的問題欄位只剩在更新紀錄裡；指向設計紀錄的章節引用、過期的審查紀錄說法、已退役的任務標記、「套件測試探針」、「六種鏡頭」（改為七種）、「只剩這些停點」（改為列出其他停點）、「讀不到另一個外掛」、待辦清單說法、已退役的技能名稱，新版都搜不到了；建置站現在直接連到對抗程序說明。
- **Evidence**: 兩份副本逐條搜尋的輸出（本次操作時抓取）；新版寫規格站「提交、視需要審查、交接」一節原文；新版 write-plan 規格審查段原文。
- **Verdict**: PASS — 19 條都已消失或與行為一致。其中 7 條我讀了前後文，其餘 12 條只做了原句搜尋與局部閱讀。

### 2. Each block duplicated within one plugin that the audit lists (D1 for the two loom-design tools, D2, D3, D4, D5, D9) exists in one file of that plugin, and every former copy is replaced by a pointer to it.
- **How I tried it**: 新舊兩邊搜尋每段重複內容的特徵句，數它出現在幾個檔案，再看原本的位置是否改成指向單一來源。
- **What happened**:

  - 「先找到 loom-code、再檢查合約版本」：四個技能都改成指向同一份新說明。但每個技能仍保留一行檢查指令和「失敗就停」一句，只有找路徑的長段落集中了。
  - 「進站先看跳過清單、最多建議一次」：這句長說明現在只在專家模式裡。四個站各剩一句進站指令，外加指向專家模式的連結。
  - 派工設定的呼叫方式：呼叫指令只剩在共用的派工設定說明裡，建置站和收尾審查站改成連結過去。
  - 對抗程序（含禁用丟棄指令的清單）：只在對抗程序說明裡，對抗者本人的說明改成「先讀那份」。
  - 嚴重度判定規則（「有 fatal 就退回」等）：只在評審標準裡，審查者說明已不重述。

### 3. The loom-code and loom-design rule files, counted the same way as the audit baseline of 37,665 words, total at least 2,000 fewer words, and loom-code's write-plan SKILL.md is under 3,750 words.
- **How I tried it**: 我自己寫了一支小程式，用和原本證據相同的算法（同樣的四個資料夾、排除說明檔與更新紀錄、以空白切字），直接在兩份副本的檔案上計算，沒有沿用原本的數字。
- **What happened**: 舊版 31 個檔案共 37,665 字，新版 33 個檔案共 35,486 字，少了 2,179 字，比門檻 35,665 多省 179 字。write-plan 主文（去掉開頭設定區）從 4,176 字降到 3,352 字。
- **Evidence**: 我的計算輸出 `base (37665, 31, 4176)`、`wt (35486, 33, 3352)`，與原本的字數證據一致。
- **Verdict**: PASS。注意兩點：餘裕只有 179 字；write-plan 有 862 字搬到一份「只有意圖尚未確認時才讀」的新說明，這 862 字仍算在總數裡。所以意圖已確認時，agent 實際要讀的字比總數顯示的更少。另外，意圖文件寫 write-plan 原本 4,182 字，我算出 4,176 字，差別來自開頭設定區的切法，不影響結論。

### 5. Fresh-context agents given the same real task for each changed station on main and on the branch take the same steps, ask the user the same decision-point questions, and produce artifacts that pass the same checker commands.
- **How I tried it**: 我另外挑了兩個站，用和原本證據不同的情境，各派兩位全新的閱讀 agent，一位只讀舊版、一位只讀新版，提示只有路徑不同。它們只能讀檔，不能跑指令，最後回報會走的步驟、會問你的問題、會跑的檢查指令、會產出的檔案、會派出的 agent。
  - 建置站：三個任務、使用者已選擇跳過實作者。
  - 規劃站（沒裝 loom-design）：使用者要「匯出指令遇到已存在的檔案時拒絕覆寫，除非加 --force」，而且還沒有意圖文件。
- **What happened**:
  - 建置站：兩邊步驟和順序相同：主 agent 自己做三個任務、同步主幹、派一位全新對抗者、跑整套測試與對抗程式、交給收尾審查一次。檢查指令、產出檔案、派出的 agent 也都相同。新版的閱讀者提到「任務標記」，但新版文字已沒有這個詞，屬於閱讀者自己的用詞。
  - 規劃站（第一輪各一位）：檢查指令、產出（意圖、簡易規格、計畫、分支）兩邊相同。有兩處不同：新版閱讀者沒把「進站先看跳過清單」列成一步；新版閱讀者多問了一題「加 --force 仍會直接覆寫、沒有備份，可以嗎」。這一段在新版被縮成一句加連結，所以可能是「變得不顯眼」，不能只憑一次就說是閱讀者差異。
  - 規劃站重跑：同一情境、同一提示，每邊再加兩位全新閱讀者，合計每邊 3 位，結果如下。

    | 看什麼 | 舊版 | 新版 |
    |---|---|---|
    | 有沒有跑「進站先看跳過清單」 | 3/3 | 2/3（沒跑的是第一輪那位；重跑兩位都有，其中一位排在合約檢查之後、訪談之前） |
    | 有沒有多問一題不可逆決定 | 0/3 | 1/3（只有第一輪那位；重跑兩位都判定不需要問） |
    | 規格判定「需要事前審查」並派一位規格審查者 | 0/3 | 2/3（重跑兩位） |
    | 檢查指令 | 相同的一組（有人多列「查欄位上限」或 git 指令） | 相同的一組 |

  - 判定規則是「新版 3 位中有 2 位以上漏掉進站檢查、而舊版沒有漏，才算退步」。新版只漏 1/3，所以**算閱讀者差異，不是退步**。多問的不可逆問題也只出現 1/3 次。
  - 重跑多看到一個差異：新版 3 位中有 2 位判定規格需要事前審查，舊版 0 位。決定「要不要審查」的那句規則，新舊兩邊一字不差（「安全／隱私、不可逆資料、公開合約、跨系統、需求模糊時要審查」），所以不是這次改動造成的。兩位閱讀者都說「這個改動是在防止資料被覆寫，算不算不可逆資料」這句話說不清楚。這是規則本來就有的模糊，不是本次的退步；如果判定為需要審查，新版的做法是直接派審查者，這正是本次刻意做的修正。
- **Evidence**: 八位閱讀者的回報（建置站 2 位、規劃站 6 位，本次操作時保留）；決定點①新舊文字的比對輸出；「需要事前審查」判定句的新舊比對（相同）。原本的平行閱讀證據（7 個情境、42 列）結論是「沒有無法解釋的差異，唯一的行為差異是規格審查改由寫規格的人直接派」，我的抽查與這個結論一致。
- **Verdict**: 部分通過 — 建置站完全一致。規劃站重跑後，進站檢查漏掉 1/3、多問的問題 1/3，都在差異範圍內，不算退步。證據仍偏弱：每邊只有 3 位閱讀者、只看兩個站、只是「描述會怎麼做」而沒真的執行，也沒有真的用產出去跑檢查指令。它能說明文字把人導向同一方向，不能保證每次執行都一樣。

## 沒通過或偏弱的地方

- **第 5 條證據偏弱**：見上，只是閱讀者的描述。規劃站重跑後，進站檢查漏掉的比例是新版 1/3、舊版 0/3，判定為差異而非退步。另外，規則裡「防止覆寫算不算不可逆資料」這句有模糊（新舊兩邊相同），新版有 2/3 位閱讀者因此多派了規格審查者。
- **舊的凍結攻擊測試有 7 個變紅**：上一個改動（對抗者自己維護探針）留下的 22 個攻擊案例中，7 個失敗、15 個通過。失敗原因是它們找的原句已從對抗者說明搬到對抗程序說明，例如找不到「When Build re-dispatches」。規則本身沒消失，但這批舊證據已無法重跑為綠。計畫事先就預告了這個風險，並決定只記錄、不修改；已經收進套件的正式測試不受影響（全綠）。
- 第 1 條有 12 條只做了原句搜尋，沒逐條讀前後文。

## I decided for you

- **規格事前審查改由寫規格的人直接派一位獨立審查者**，不再交給收尾審查站。原因是收尾審查站只能在建置完成後運作，舊寫法根本跑不起來。以後若想讓收尾審查站也支援規格審查，要替它加一種新模式。
- **被刪除的攻擊清單不復原**：對抗者改依對抗程序說明裡已寫好的攻擊類別工作。如果以後覺得清單有價值，要重新寫一份並接回兩處說明。
- **write-plan 的「沒裝 loom-design 時確認意圖」一段搬到另一份按需讀取的說明**，意圖已確認時不會載入。內容與原本相同（我比對過），但如果 agent 漏讀那份說明，會漏掉確認步驟。
- **跨外掛的重複段落暫時保留**（站點總表的其餘副本、第二供應商說明、不可逆決定分類等），留到下一次改動。這是你選範圍 A 的結果。
- **「找 loom-code」集中成一份說明，但各技能仍各留一行檢查指令與停止規則**，沒有全部搬走。
- **對抗程序說明留在原位置、由建置站直接連過去**，不搬家，以免 71 處測試引用的路徑一起改動。
- **loom-memory 的心得分流句一併改成「未完成事項開新意圖」**：這段有內容雜湊保護，所以改之前先做了新舊閱讀比較。據交接說明，那次比較的證據偏弱；我沒有重做。
- **上一個改動留下的凍結攻擊測試有 7 個案例因原句搬家而變紅**，決定只記錄、不修改那份舊證據。

## Things I am not sure you want

- 第 5 條只有閱讀者層級的證據，你是否接受這個強度，還是要真的拿一個小改動在新版跑一輪？
- 「這個改動是在防止資料被覆寫，算不算需要事前審查的不可逆資料」這句規則說不清楚，新舊版本都一樣。要不要另開一個改動把它寫清楚？
- 7 個變紅的舊攻擊案例要留著當歷史紀錄，還是希望另開一個改動把它們的原句更新？
- 總字數只比門檻多省 179 字。若之後的修正加回字數，這條就可能不過；是否需要留更多餘裕？
