## 我替你決定的

- **106 個短字眼刻意留下**（主流程的決定）— 新腳本在現在的版本仍列出 106 個散文候選，都被判定保留並寫了理由：標題、欄位名、表格欄位值、專有名詞、「不可出現」的檢查，或第三批留下的關卡檢查。我抽讀了一部分，理由和程式對得上。代價是：之後潤稿時，改到這些字眼（例如某些概念詞、欄位名）測試仍會變紅。
- **六成的被刪比對改由人工審查接手** — 72 列裡 43 列沒有自動檢查，只靠審查時讀出來。
- **四個 skill 的「證明它有效」測試變薄了**（主流程的決定）— handoff、recap-state、git-memory、independent-advisor 的登記測試檔還在，但現在只檢查欄位名、指標和字數上限，不再檢查規則的措辭；independent-advisor 那個檔從 8 支測試剩 3 支。登記檔指向的檔案都還在，所以普查仍通過。
- **有些寫法腳本仍看不到** — 經過兩層小工具傳遞的字串、用索引取出的字串、非字面的正規表示式，以及幾種 repo 裡沒人用的寫法，報告的「已知限制」都寫了。另外我發現：一個同時會執行程式的測試檔，就算新加了沒寫理由的散文比對，普查仍會通過、「句子比對」總數也不會動，只會在逐檔清單上標出來。
- **loom-design 沒有 skill 內容變更也一起升版號**（主流程的決定）— 三個 plugin 一起升，讓更新時整組一起拿到。
