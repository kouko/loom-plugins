## 我替你決定的

- **第 1 條判「成立」，但「零」只代表腳本看得到的那幾種寫法** — 兩個字的短語、藏在檢查小工具裡的句子、用位置查找或正規表示式比對的句子，腳本仍看不到；這些是作者逐檔讀出來清掉的，報告的「已知限制」寫明了。代價是：之後潤稿時，仍有可能碰到腳本沒抓到的短語讓測試變紅。
- **刻意留下 3 個「規則方向」檢查**（主流程的決定）— 視覺化那支 skill 有 3 句關卡規則，測試仍會讀它們，但只檢查句子有沒有被改成相反意思。代價是：改寫這 3 句關卡規則時，測試仍會變紅。
- **一支給 Codex 顯示用的預設提示字串照舊比對**（主流程的決定）— 那是 Codex 介面欄位的文字，不是 skill 說明，所以不算這次要清的範圍。
- **四分之三的被刪比對改由人工審查接手** — 第一輪審查發現有 11 列把「其實守不住」的測試寫成替代，這輪全部改標為人工審查，另有 6 列改寫成「測試只守一半、另一半靠審查」。結果是 68 列裡 50 列沒有自動檢查。上一輪我抽查時跑過的幾支替代測試（例如派工設定的解析器、外掛安裝路徑的模擬），也在這 11 列裡：它們存在也會過，但守的不是那列寫的缺陷。
- **測試改名，讓名字只說它實際還在檢查的事**（主流程的決定）— 17 支被刪減過的測試改了名字和說明，舊名字記在刪除清單裡。
- **loom-design 沒有內容變更也一起升版號**（主流程的決定）— 三個 plugin 一起升，讓更新時整組一起拿到。代價只是 loom-design 多一個「只同步測試與版號」的版本。
