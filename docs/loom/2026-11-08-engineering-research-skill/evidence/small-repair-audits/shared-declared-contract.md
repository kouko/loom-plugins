# Shared declared-contract bar (frozen before audits)

Source: only the current seven runtime Markdown files of loom-code/skills/engineering-research, whose hashes are frozen alongside this bar. This is a neutral extraction of declared requirements, not author intent, rationale, prior findings, or an inference from executor artifacts. Apply together with rubric.md and cases.json; explicit user boundaries override generic requirements.

- Verify actual relevant source branches and conditions. Recheck applicability after changed assumptions. Source/test definitions are not observed test execution; local main merge is not release, install, or host validation. Attribute source observations, runtime observations, inference and unknowns separately.
- Choose the smallest fitting method or adequate evidence reuse; record method and rationale plus bounded scope. Read methods/source policy before new substantive evidence or experiments. Evaluation reference is conditional on an assessment; framework labels, matrices, diagrams, and experiments are optional, not a quota.
- Each independently answerable question gets a retained Markdown record (except explicit no-write/unavailable-write: provide unsaved draft and name missing saved artifact). Continue the same question under same conditions in its original file, preserving created and original evidence/revision; changed conditions require separately scoped revalidation and retained prior decision basis. Real active change uses docs/loom/<change-id>/research/<sequence>-<topic>.md after inspecting allocation; standalone uses docs/loom/research/<date>-<topic>.md.
- New/updated records require flat title, type: loom-research, status (in-progress/concluded/superseded), created, updated (YYYY-MM-DD), tags list containing loom/research; add change only for actual active change. Status is work state, not user acceptance or evidence quality. Body retains question/conditions, method/rationale, findings, concrete evidence, decision impact, limitations/open questions. No rigid heading/template duplication is needed if substance is clear. Optional irrelevant template sections may be omitted.
- Decision-critical evidence includes source kind, actual applicable revision/commit and conditions, source path/anchor or URL, and measured command/result only where observed. Do not fabricate missing historical output, file existence, successful readback, CI, or host validation. Relative Markdown evidence links must resolve from saved record. Saved record completion requires actual content readback, not exit/existence alone.
- Keep original task/authorization. No invented new goal, tool install, publication, test execution, contacting others, or human acceptance advancement.
- Preservation is optional and instance-specific. Relevant prior merged work or finishing after merge+successful cleanup can trigger guidance; verify exact merge/stable revision and actual cleanup. If merge/cleanup unverified or failed, defer proposal and state missing evidence. CLI absence alone is no failure: user-supplied destination or unsaved candidate is permitted, authorized compatible write mechanism is allowed without install.
- Preservation candidates select enduring supported findings, include actual reviewable content/scope/provenance and destination, adapt links to destination. Interest is not consent. Before writing recheck exact instance/source/destination/scope and note collision; never overwrite without separate authorization. Preserve original source; write only authorized copy, read it back and verify actual destination/provenance. Distinguish copy success, research correctness, merge, release, install, loader/host behavior. Do not claim untested renderer/import validation.
- If diagrams appear, relationships/evidence status must be explicit and prose independently readable; actual parser/render validation or its absence must be reported. Diagram existence is not itself required or proof.
