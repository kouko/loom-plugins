# Publication floor moves to GitHub — spec
intent: 2026-09-22-publication-floor-moves-to-github@71377548
pre-build-review: required — the change removes the only local publication gate, adds a public contract (a CI template other repositories copy) and spans two systems (the local checker and GitHub branch rules)

## Requirements
REQ-1 — PR body floor on GitHub
  WHEN a pull request targeting the protected trunk has a body with any of Ship's nine contextual headings missing, duplicated, out of order or empty, the loom PR-floor CI check shall fail and name the first offending heading, so GitHub refuses the merge → Acceptance #1
REQ-2 — Trunk accepts pull requests only
  WHERE the trunk carries the rule set that `loom_checker.py github-rules` prints, the trunk shall accept changes only through a pull request, for administrators too, so a direct push to the trunk is refused by GitHub → Acceptance #2
REQ-3 — Recomputed verification disclosure
  WHEN the loom PR-floor CI check runs, it shall recompute the branch's verification status from committed content as `valid`, `valid (skipped: <steps>)`, `absent` or `stale (<reason>)`, publish it in the check's own title and summary, pass on every status, and never read a status from the PR body; an attestation that records skipped steps is never reported as plain `valid`, and more than one attestation or an unreadable one is `stale` → Acceptance #3
REQ-4 — Hooks never refuse publication
  WHEN an agent runs any Bash command that pushes or opens a pull request, the publication hook on every host (Claude Code, Codex, Antigravity) shall allow it, including when the checker is missing or crashes; WHERE the command's first simple command is literally `git push` or `gh pr create`, it shall also emit one reminder line naming the branch's verification status → Acceptance #4
REQ-5 — Ship refuses a malformed body before the PR exists
  WHEN the Ship station's publish command receives a body with a heading missing, duplicated, out of order or empty, it shall refuse before pushing or creating the pull request and name that heading → Acceptance #5
REQ-6 — Land checks the body and discloses verification
  WHEN `loom_checker.py land --accepted-by <name>` is run, it shall identify the change without needing an attestation, read the pull request's live body and refuse when a heading is missing, duplicated, out of order or empty, naming it; IF the body passes, the name is accepted and the status is `absent` or `stale` THEN it shall merge and print one reminder line naming that status → Acceptance #6
REQ-7 — Ship reports missing GitHub rules
  WHEN the Ship station runs in a repository whose trunk lacks the pull-request requirement (with administrators included) or the loom PR-floor required check, it shall print which is missing and the one `loom_checker.py github-rules --print-setup` command output that would add it, and shall not change any GitHub setting itself → Acceptance #7
REQ-8 — Ship tolerates unreadable rules
  IF the trunk's rules cannot be read or cannot be decided (no permission for classic protection with no ruleset visible, no GitHub remote, or the API fails) THEN the Ship station shall print that the rules could not be confirmed and continue publishing → Acceptance #8
REQ-9 — Copyable CI template
  The loom-code plugin shall ship one CI template file that, copied unchanged into a GitHub repository's workflow directory, runs the same PR-floor check as REQ-1 and REQ-3 on every pull request, and whose required check a pull request cannot satisfy by editing workflow files in its own head → Acceptance #9
REQ-10 — Skipping needs words, not a code, and is reminded
  WHEN the user tells the agent in plain words to skip a step, the stations shall continue without asking for a generated code and the agent shall tell the user which step it skipped; WHEN such a branch is pushed, has its PR opened or is merged, the reminder line shall list which verification records are absent → Acceptance #10
REQ-11 — Principle 2 amended
  The repository's PRINCIPLES.md non-negotiable 2 shall state that a step the user skips by plain instruction must be disclosed on the pull request, shall no longer require a typed confirmation, and the ratified-by line shall record the user's amendment → Acceptance #11
REQ-12 — Mentioning a merge is silent
  WHEN a command only mentions the merge words (a search, printed text, a commit message), the publication hook shall allow it and emit nothing → Acceptance #12
REQ-13 — Suite green
  The complete package suite shall pass → Acceptance #13

## Design decision
- **The floor is GitHub, loom stops guessing** — the trunk is guarded by a GitHub rule set (pull request required, zero approvals, `bypass_actors: []`, the loom PR-floor check required) instead of the PreToolUse shell-text parser. user-decided (① answer: move the floor to GitHub; keep nine sections).
- **Where loom still refuses** — only inside its own commands: `publish` (Ship's single push+PR command, body validated at `publish.py:365`) and `land` (new body check against `gh pr view --json body`). The selection-store guard keeps refusing file-tool writes. Carried detail: 「loom 自己的合併指令（`land`）合併前讀 PR 內文再檢查一次」; 「跳站紀錄目錄的防護（`selection.guard`）維持阻擋」. user-decided.
- **The body validator names the heading** — `validate_contextual_pr_body` (`rule_checks/publish.py:45-49`) today returns one generic sentence; it is changed to report the first missing, duplicated, out-of-order or empty heading by name, with the acceptance condition unchanged (intent Constraint: no loosening). The same function serves `publish`, `land` and CI. agent-decided.
- **Identifying the change without an attestation** — `land` (`_accepted_names`, `land.py:873-894`, via `_publication_change_id`), `publish` and the hook reminder today learn the change id from the attestation and fail when it is absent. They instead take the change id from the branch name `<type>/<change-id>` when `docs/loom/intent/<change-id>.md` exists at HEAD, else from the single intent file in the branch delta; the attestation, when present, must agree. Neither found → `land` refuses naming the fix (rename the branch or commit the intent); `publish` refuses likewise; the hook reminder says the change is unidentified. Acceptor names still come from the committed intent's `originator` and `publication:` lines. agent-decided.
- **Hook becomes allow-only with shallow recognition** — the hook recognises a push, PR create or PR merge only when it is the first simple command after `VAR=` assignments; every other shape is silent. It never refuses a publication command. Carried detail: 「PreToolUse hook 只提醒，只辨認最常見的寫法；漏看只是少一行提醒」. user-decided. Every reminder — push, PR create, merge outside `land` — carries the same `(missing: …)` clause.
- **Host fallbacks allow too** — `hooks/hooks-codex.json:13-28`'s inline fallback (checker file absent) and `hooks/agy_adapter.py:138-168` (checker absent, crash, or an exit code other than 0/2) today deny; they change to allow every command except the selection-guard refusal, which still exits 2 through the checker when it runs. A checker crash therefore allows and prints `loom: publication hook failed (<error>); allowing`. agent-decided — REQ-4 requires allow on every host.
- **Verification status — local depth** — `publish`, `land` and the hook run the full `validate_attestation` including the local selection-record comparison (`attestation.py:104-111`); it yields `valid`, `valid (skipped: <steps>)`, `absent` or `stale (<first failing check>)`, and never refuses.
- **Verification status — CI depth** — selection records live under the git common dir (`selection.py:87-91`) and are absent in a fresh checkout, so CI cannot confirm a recorded skip. CI runs the content-level checks only (`attestation.py:92-102,113-167`) and treats the attestation's own `selection` field as a claim: any non-null skip set is reported as `valid (skipped: <steps>)`, never plain `valid`; zero attestations `absent`; more than one, unparseable JSON, or any content-level failure `stale (<reason>)`. agent-decided — keeps NN3 (a claimed skip is shown as a skip, not as verification).
- **Status is published by the check, not read from the body** — the CI check writes the status into its check title and job summary and never parses a status from the PR body (REQ-3). agent-decided.
- **Body disclosure lines** — Ship writes, under `## Verification`, the line `Verification status: <status>` computed locally, and for a plain-words skip the line `Skipped by instruction: <steps>`. `validate_selection_disclosure` (`rule_checks/publish.py:81-116`) keeps enforcing its `Skipped steps:` line only when the attestation carries a bound selection; the two new prefixes are always accepted and are not validated against anything (the check's own title is the recomputed source). agent-decided.
- **Mechanism ids and NN4 budget** — retired: `push.merge`, `push.attestation` (`rules.py:108,124`; `mechanisms.yaml:161,167`). Added: `publish.verification-status` (the disclosure computation shared by publish/land/hook) and `ci.pr-floor` (the CI check). `push.contextual-body` and `land.merge` keep their ids. The `github-rules` probe is advisory output with no rule id. Net checker-rule count: 0. Build confirms with `check_mechanisms.py --baseline origin/main`; any rise needs a declared `budget-exception:` line. agent-decided.
- **CI template shape** — caller workflow `loom-code/templates/loom-pr-floor.yml`, job id `loom-pr-floor`, triggered by `pull_request_target` (`opened, edited, synchronize, reopened`) so the workflow definition always comes from the base branch and a PR cannot rewrite its own required check; it calls the reusable workflow `.github/workflows/loom-pr-floor.yml` in this repository (`on: workflow_call`, job `PR floor`, input `loom-ref`). The required check context is the constant `loom-pr-floor / PR floor`, used by the template, the reusable workflow, the `github-rules` probe and its printed setup JSON. The reusable job checks out this repository's `loom-code/scripts` at `inputs.loom-ref` and the PR head at `github.event.pull_request.head.sha` with `fetch-depth: 0`, reads only files and the event's body, and executes no code from the PR. It runs a new read-only subcommand `loom_checker.py pr-floor --body-file <f> --base <sha> --head <sha>`. The template references `@main` and passes `loom-ref: main`, with a comment showing how to pin both to one commit SHA. agent-decided — `pull_request_target` over path restrictions/CODEOWNERS because it needs no second rule; `@main` because the repository publishes no release tags. The context string is unverified against a live reusable-workflow run; build must confirm it on GitHub before the probe constant is trusted.
- **`github-rules` probe** — new subcommand `loom_checker.py github-rules [--print-setup]`, called by Ship. Reads `gh api repos/{o}/{r}/rules/branches/{trunk}` (rulesets, read access) and, when readable, `branches/{trunk}/protection` (classic, admin only). PR requirement counts when a ruleset `pull_request` rule applies with no bypass actors, or classic `required_pull_request_reviews` is set **and** `enforce_admins.enabled` is true. The check requirement counts when a `required_status_checks` rule or classic required contexts contain `loom-pr-floor / PR floor`. Rulesets empty and classic unreadable → "could not confirm" (REQ-8), never "missing". `--print-setup` prints one `gh api -X POST repos/{o}/{r}/rulesets --input -` command with the JSON (`bypass_actors: []`). Ship never runs it; the agent runs it only after the user explicitly agrees in conversation (intent Constraint). Carried detail: 「ship 站用 `gh api` 讀 main 的保護規則；沒設時提示缺什麼，並附一個可以直接設定的指令，由你確認後才執行」. user-decided.
- **Skipping** — zero or stale attestation no longer refuses in `publish` (`publish.py:438`) or `land` (`land.py:954`); `publication_advice` (`command_handlers/push.py:143`) stops offering the typed-code route. Station prose (ship, closing-review, build, using-loom-code) tells the agent: skip only on the user's instruction, and say in one line which step was skipped before continuing. Carried detail: 「agent 可以在跳過的時候給使用者提醒（但是不擋流程繼續執行）」. user-decided (① answer A). The expert-mode skill and its selection store are left as they are: an optional route that still records skips. agent-decided — removing them serves no Acceptance line.
- **Reminder content** — the `(missing: …)` clause lists absent records among: confirmed intent, plan, attestation; a stale attestation names its failing check. Blind-run, spec review and TDD order are not listed: no committed record lets them be recomputed. agent-decided.
- **PRINCIPLES.md amendment** — non-negotiable 2's last sentence becomes: "A step the user skips by plain instruction falls outside this guarantee; every such skip must be disclosed on the pull request, and the attestation-level verification status there is recomputed rather than claimed." Append `; non-negotiable 2 plain-words-skip amendment by kouko 2026-09-22` to the existing `ratified-by:` line (an amendment log). user-decided (① answer A).
- **Parser shrink** — `rule_checks/push.py` keeps only what non-hook callers import (`_shell_segments`, `_strip_prefix`, `_tokenise` for `selection_guard.py:12-14`; `github_repo_from_origin`, `CANONICAL_PUSH_FLAGS` for `publish.py:18-19` and `land.py:27`) plus the shallow recogniser; everything reachable only from the hook's refusal path is deleted with its tests. agent-decided.
- **This repository adopts its own floor** — the caller workflow is added under `.github/workflows/` here. Applying the rule set to kouko/loom-plugins (which today has classic protection with `enforce_admins` on and a required CI context, but no PR requirement) is an outward action proposed to the user, not performed. agent-decided — no authorisation, conservative option.
- **Not doing** — no pre-push git hook, no `gh api …/merge` recognition, no change to `~/dotfiles`, no deletion of branch `loom-gate-warn` (intent Out of scope).

## Alternatives considered
- Fix branch `loom-gate-warn` and keep the shell parser as the gate — rejected: it cannot see web or user-terminal merges, and each hardening round reopened a bypass (3 confirmed, 23 failing tests).
- Keep a typed confirmation without a generated code (option B) — rejected by the user at ①.
- CI parses a status sentence from the PR body and fails on mismatch — rejected: it reintroduces a hard stop and still trusts text.
- Inline a copy of the nine-heading validator in the CI template — rejected: two copies drift.
- `pull_request` trigger plus a CODEOWNERS or file-path rule on `.github/workflows/**` — rejected: a second rule to set up and verify; `pull_request_target` closes the same hole alone because the job runs no PR code.
- Pin the template to release tags — rejected for now: no release tags exist; the SHA-pin comment covers adopters who need immutability.
- Rely on the classic protection endpoint alone — rejected: it is admin-only; rulesets are the primary source and classic is read only when readable.
- git pre-push hook for trunk pushes — rejected (intent Out of scope; GitHub rules already refuse them).

## UI flows

| case | what the user/agent does | what they see |
|---|---|---|
| push, no record | agent runs `git push …` on a branch with no attestation | command runs; `loom: verification absent (missing: attestation); publishing anyway.`; exit 0 |
| push, stale | same, attestation no longer matches | command runs; `loom: verification stale (<check>); publishing anyway.`; exit 0 |
| push, unidentified change | branch name and delta name no intent | command runs; `loom: change not identified (no intent for this branch); publishing anyway.` |
| wrapped push | `true; git push …`, `bash -c '…'`, heredoc | command runs; no line |
| hook failure | checker missing or crashes, any host | command runs; `loom: publication hook failed (<error>); allowing.` |
| merge outside land | agent runs `gh pr merge …` | command runs; `loom: this merges outside loom_checker.py land (missing: …); merging anyway.`; exit 0 |
| merge words only | `grep "gh pr merge" …`, `echo`, commit message | command runs; no line |
| Ship publish, bad body | Ship publishes with a missing, duplicated, out-of-order or empty heading | refused before any push: `BLOCK push.contextual-body: heading "<heading>" is missing` (or `duplicated`, `out of order`, `empty`); agent fixes the body and reruns |
| Ship publish, good body | Ship publishes | branch pushed, PR opened; body carries `Verification status: <status>` (and `Skipped by instruction: …` when the user skipped); terminal reminder when status is not `valid` |
| Ship publish, unidentified | branch name and delta name no intent | refused: `BLOCK publish: cannot identify the change — name the branch <type>/<change-id> or commit its intent` |
| Ship, rules missing | trunk lacks the PR requirement and/or the check | `loom: <trunk> does not require a pull request (administrators included)` and/or `does not require the check "loom-pr-floor / PR floor"`, then the setup command; publishing continues; nothing on GitHub changes |
| Ship, rules unreadable | no permission / no GitHub remote / API error | `loom: could not confirm GitHub rules for <trunk> (<reason>)`; publishing continues |
| user agrees to setup | user says yes to the printed command | agent runs it once; the next Ship run reports no missing rule |
| land, bad body | `land --accepted-by <name>` on a PR whose live body fails | `BLOCK land.merge: PR body heading "<heading>" is missing` (or other fault); nothing merged; edit the PR body and rerun |
| land, no record | same, body fine, name accepted, no attestation | merged; `loom: verification absent (missing: attestation); merged anyway.` |
| land, unidentified | branch and delta name no intent | `BLOCK land.merge: cannot identify the change — …`; nothing merged |
| CI, bad body | PR opened or body edited with a failing heading | check `loom-pr-floor / PR floor` fails naming the heading; merge stays blocked until the body is edited (the `edited` event re-runs it) |
| CI, good body | PR opened/edited/synced | check passes; title `verification: valid`, `valid (skipped: …)`, `absent` or `stale (…)` |
| CI, workflow edited in PR | PR changes the caller workflow to always pass | the base branch's workflow still runs; the edit has no effect on the check |
| skip by words | user: "skip review, open the PR" | agent: "Skipping closing review as you asked; the PR will show verification absent." and continues |

In progress: every check above is one command run; no waiting surface beyond the command itself. Empty: a repository with no trunk rules and no template behaves as the "rules missing" row.
