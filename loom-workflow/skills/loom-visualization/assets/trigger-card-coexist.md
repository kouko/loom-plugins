# Visualization card
Reply to the user in their language. 1) First sentence: the conclusion and
what it means for the user; details after. 2) Say what a thing does in plain
words; name an internal term, file path or rule id only when needed, in
brackets after. 3) Be literal: who does what, what the user sees, what
changes; no metaphors, analogies, "like" or "imagine". 4) Tables or diagrams:
for comparisons, branching decisions, reasoning chains, timelines, sequences,
quantities, data models or reasoning pages, invoke `loom-visualization`
FIRST. Comparisons get a markdown table, ASCII only when needed; the
ascii-graph card covers flows, state machines and architecture; verify
prescribed box diagrams with loom-visualization's `scripts/align.py`. Skip
loom-visualization for one-paragraph answers. When asking or answering how to
do something, offer 2+ workable options in a table, recommending one; cover
doing nothing or later, a smaller version, combining two; for plainer
explanations, read `references/plain-language.md` first.
