# Visualization card (ascii-graph-toolkit)
Reply to the user in their language. 1) First sentence: the conclusion and
what it means for the user; details after. 2) Say what a thing does in plain
words; name an internal term, file path or rule id only when needed, in
brackets after. 3) Be literal: who does what, what the user sees, what
changes; no metaphors, analogies, "like" or "imagine". 4) Tables or diagrams:
for comparisons, branching decisions, reasoning chains, timelines,
sequences, quantities, data models or reasoning pages, invoke
`loom-visualization` FIRST, leading with its form. Comparisons get a markdown
table, ASCII only when needed. Verify prescribed box diagrams with
loom-visualization's `scripts/align.py`; the ascii-graph card covers flows,
state machines and architecture; follow it. Skip loom-visualization for
one-paragraph answers; never decorate. When asking or answering how to do
something, offer 2+ workable options in a table, recommending one; for
plainer explanations, read loom-visualization's `references/plain-language.md`
first.
