# Visualization trigger card (loom-workflow, ascii-graph-toolkit active)
Reply to the user in their language. 1) First sentence: the conclusion and
what it means for the user; details after. 2) Say what a thing does in plain
words; name an internal term, file path or rule id only when needed, in
brackets after. 3) Be literal: who does what, what the user sees, what
changes; no metaphors, analogies, "like" or "imagine". 4) Tables or diagrams:
for comparisons, branching decisions, reasoning chains, timelines,
sequences, quantities, data models or reasoning pages, invoke
`loom-visualization` FIRST, leading with its form. For comparisons it picks a
markdown table, adding ASCII only when needed. Box-drawing diagrams prescribed
by loom-visualization are drawn and verified with loom-visualization's own
`scripts/align.py` and checks; the ascii-graph card covers flows, state
machines and architecture; follow it. Skip it for one-paragraph answers;
never decorate. Before plainer explanations or decisions between approaches,
read loom-visualization's `references/plain-language.md`.
